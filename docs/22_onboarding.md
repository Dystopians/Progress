## 0. 本文件的地位与边界

### 0.1 本文件规定什么

1. **引导的非强制契约**：引导能做什么、绝不能做什么，以及每一条如何被静态或运行时检验（§1）。
2. **前四季逐季规格**：学习目标、锚点、导语、玩家错误路径、界面如何提示而不代替判断、达成判据（§2）。
3. **判据的机器求值**：事件集合、谓词定义、求值时机、`n/a` 规则（§3）。
4. **决策密度而非强制行动点**：四类真实限制的可观测形态、禁止行动点、最小必要交互预算、默认常设指令集与披露卡（§4）。
5. **引导的实现**：目录、类、资源 schema、状态机、存档字段（§5）。
6. **试玩脚本**：主持人逐步指引、台词卡、卡住协议、解释题评分标准（§6）。
7. **记录表格式**：五张 CSV 的列定义、本地日志契约、隐私边界（§7）。
8. **门槛判定与报告口径**：§17 那一行怎么算通过、样本声明、重测规则（§8）。
9. **验收条目** `AC-OB-01..AC-OB-14`（§9）。

### 0.2 本文件不规定什么

- 不重复定义界面结构、三类信息编码、原因对象、五主页面与覆盖层——那是 `docs/20_ui_spec.md` 的职责。
  本文件只引用它已定义的节点别名与验收编号，**不修改它**。
- 不定义变量字典、数据协议、结算合同、待决问题登记、参数登记（`docs/10`—`docs/14`）。
  本文件对它们的需要集中写在 §10，**以「界面/引导需要什么」的形式声明，不预设其命名**。
- 不定义任何模拟规则与参数值。文中出现的数字（120 秒、3 次连击、5 条常设指令等）
  分两类：**试玩协议参数**（§7.4 登记，可由主持经验调整）与**界面常量**（§10 要求进参数登记）。
  **没有一个数字是模拟参数提案。**

### 0.3 与 `docs/20_ui_spec.md` §11.2 的关系

`docs/20` §11.2 已给出四步引导的骨架（锚点节点、文案要点、完成判据、AC-36 / AC-37）。
**本文件是它的实现级展开，不是替代**。对应关系：

| `docs/20` §11.2 的一格 | 本文件展开为 |

与 `docs/10`—`docs/14` 冲突时，以那几份为准。

### 0.4 一句话立场

> **引导教玩家怎么读这个界面，不教玩家该做什么决定。**
> 一条引导步骤如果在「玩家做了 X」和「玩家做了非 X」两种情况下给出不同的评价，它就越界了；
> 它只允许在「玩家看没看到那块证据」上有区别。

## 1. 引导的非强制契约

### 1.1 问题：§15 的门槛与 §05 的禁令同时成立

- §15 G4 门槛：**陌生玩家无需口头教学可完成前 4 季**。这要求界面自己会说话。
- §05：**剧本不是预设胜利路线**——「没有『必须先修电网』的隐藏答案」。这禁止引导替玩家排序。

这两条不矛盾，但**只在一种引导形态下**同时成立：

> 引导是**指路牌**，不是**轨道**。
> 它把玩家送到能回答问题的那块界面前，然后闭嘴。至于玩家读完之后修电网、先培训还是暂缓扩张，
> 引导既不建议，也不在事后评价。

### 1.2 引导只做三件事

| # | 允许的动作 | 形态 | 硬约束 |
|---|---|---|---|
| G-1 | **指路**：把一个**已经存在**的区块指出来 | 非模态锚定提示条 `JwAnchorTip`，贴附锚点节点，≤1 行正文 | 不遮挡锚点；不捕获输入；不改变任何控件属性 |
| G-2 | **命名**：术语首见时给一句定义 | 复用 `docs/20` §10.4 的术语首见机制与 `glossary.json` | 引导不另建术语表 |
| G-3 | **复盘**：本季推进后，静默记录该季达成判据 | 写 `ui_events.jsonl` 与 `<save>/onboarding.json` | 不弹窗、不评分、不排名、不在界面上显示「你做对了」 |

**引导不做**：不推荐政策、不预填参数、不排序目录、不禁用控件、不阻止推进、不倒计时、不打分、不在第 5 季回溯评价前四季。

### 1.3 十二条非强制硬规则（`OB-F*`）

每条都必须可被一条测试检验。违反任一条即为缺陷。

| # | 规则 | 检验方式 | 通过标准 |
|---|---|---|---|
| `OB-F1` | **引导不产生任何 `Command`** | 静态扫描 `res://ui/onboarding/`：不得出现 `Command` 类名、命令提交接口名、`commands.jsonl` 字面量；引用图不得指向 `res://sim/`（`docs/20` B-01 延伸） | 0 命中 |
| `OB-F2` | **引导不改变任何控件的 `disabled` / `visible` / `focus_mode`** | 同一存档、同一季、同一断点，分别在引导开与关两种条件下遍历全部 `Control`，逐节点比较这三项属性（引导自身的 `JwAnchorTip` 子树除外） | 0 处不等 |
| `OB-F3` | **引导不改变政策目录的顺序、分组与筛选默认值** | 两次遍历 `%PolicyCatalog` 的可见项序列与筛选控件取值，逐项比较 | 序列与取值逐项相等 |
| `OB-F4` | **引导不预填草案** | 引导开启下新开局，断言草案篮条数 == 0 且全部政策参数 == 剧本默认值 | 0 违规 |
| `OB-F5` | **判据是析取式**：每季 ≥3 条互不包含的满足路径，其中 **≥1 条不涉及提交任何政策命令** | 静态读 `onboarding_steps.tres`：`step.predicates.size() >= 3`；`step.has_no_command_path == true` 且该路径的谓词表达式中不出现 `CMD(...)` | 4/4 步通过 |
| `OB-F6` | **引导不影响 `content_hash`** | 引导开启下执行 ≥200 步非 `advance_quarter` 的 UI 操作（含全部引导交互），断言 `state.content_hash` 不变（`docs/20` AC-28 延伸） | 哈希恒定 |
| `OB-F7` | **随时可跳过，跳过不删除记录** | 任一季点「不再显示」后：断言后续季不再出现 `JwAnchorTip`；断言 `ui_events.jsonl` 中判据事件仍在产生 | 两条同时成立 |
| `OB-F8` | **引导不评价路线** | 对四步导语与全部引导文案资源跑 §1.4 禁用词 lint | 0 命中 |
| `OB-F9` | **锚点必须是已存在的区块** | 断言四个 `anchor_path` 均可在关闭引导的构建中解析到同一节点；断言 `res://ui/onboarding/` 下不存在任何 `JwPage` 子类与任何新增业务区块场景 | 0 违规 |
| `OB-F10` | **引导关闭时信息仍可达** | 关闭引导，对四个锚点断言：或在该页 `required_above_fold`（三档任一），或从该页默认视图 ≤2 次点击可达（复用 `docs/20` AC-08 的 `evidence_path` 机制） | 4/4 可达 |
| `OB-F11` | **课程无对象时标 `n/a`，不标「未达成」** | 构造「第 1 季未提交任何项目」夹具走到第 2 季，断言 `step.onb.q2.na == true` 且不出现任何提示性或催促性文案 | 0 违规 |
| `OB-F12` | **判定只写引导自己的存档块** | 断言 `onboarding.json` 不参与 `manifest.command_log_hash` 与 `state.content_hash` 的计算；断言删除该文件后重放结果逐位相同 | 哈希不变，重放一致 |

### 1.4 引导文案禁用词表（正则 lint，命中即失败）

扫描域：`content/ui/onboarding_steps.tres` 的全部文本字段 + `JwAnchorTip` 的全部文案资源。

| 类 | 禁用 | 理由 |
|---|---|---|
| 祈使与评价 | `应该`、`建议你`、`最好`、`正确的`、`错误的`、`最优`、`推荐`、`别忘了`、`记得先` | 引导不得替玩家排序（§05） |
| 指向具体政策 | 正则 `P(0[1-9]\|1[0-2])`、`电网升级`、`培训扩容`、`公共住房` 等政策显示名全集 | 一旦出现政策名，「没有隐藏答案」当场作废 |
| 顺序暗示 | `先…再…`、`第一步`、`下一步`、`接下来你要` | 同上 |
| 伪进度 | `完成度`、`教程`、`关卡`、`解锁`、`奖励`、`得分` | §04「不设置凭空出现的限制」；§18「玩家只看一条综合分数」风险 |
| 空洞 | `不可用`、`无效`、`未知原因` | 沿用 `docs/20` §9.4 禁用词表 |

**允许并鼓励的措辞**：`这里能看到…`、`这块的数字来自…`、`两种都算`、`也可以什么都不做`、`规则在 ▸规则手册`。

**导语长度**：每季导语 ≤24 汉字，且必须是**陈述句**（结尾不得为 `。你可以…吗？` 式反问）。
超长在资源层改写，不在运行时截断（沿用 `docs/20` RC-14）。

### 1.5 引导与自由度如何共存：三条结构性保证

1. **判据检测的是证据接触面，不是决定内容。**
   每季的达成判据求值的是「玩家是否到过能回答本季问题的那块界面」，而不是「玩家是否提交了某条政策」。
   因此 §2 的每一季都存在一条 `*.C`（或更靠后的）谓词：**看懂了但这一季决定不动，同样算达成。**
2. **主锚点缺对象时有同构替代锚点。**
   第 2 季的课是「支出先于收益」。若玩家第 1 季没立项目，就没有在建项目行可指。
   此时锚点改到**已签承诺**（承诺摘要第 2 行 / B 表），课程形态同构；若连承诺也没有，标 `n/a`（`OB-F11`）。
3. **引导关掉之后界面不变差。**
   `OB-F2` / `OB-F10` 合起来保证：引导是一层可摘除的贴纸。
   摘掉之后，四个锚点仍在首屏或两次点击内，控件状态逐位相同。
   这也是 §15 G4 门槛「**无需口头教学**」的真正落点——门槛考的是界面，不是引导。

## 2. 前四季逐季规格

> **季号口径**：本节全部使用**显示季号**（第 1—4 季）。内部 `q` 从 0 起，显示季号 = `q + 1`
> （`docs/20` §19）。谓词表达式中出现的 `CMD(0)` / `EV(0)` 指内部 `q == 0`，即显示第 1 季。

四步的共同规格：

| 项 | 规格 |
|---|---|
| 形态 | `JwAnchorTip`：非模态，贴附锚点节点，宽 ≤360 lu，高 ≤72 lu，含导语 1 行 + `[知道了]` + `[不再显示]` |
| 出现时机 | 进入该季且锚点节点**首次满足 `visible == true` 且 `global_rect` 落在 `%Body` 内**时立即出现，无延迟、无动画诱导 |
| 同屏上限 | 任一时刻 ≤1 条 `JwAnchorTip` |
| 输入 | `mouse_filter = IGNORE`（除两个按钮）；`Esc` 关闭当前条；不进入 `Tab` 焦点陷阱，但两个按钮必须可 `Tab` 到达（`docs/20` AC-40） |
| 消失 | 点 `[知道了]`、点 `[不再显示]`、按 `Esc`、该季推进、或锚点离开视口 |
| 判定时机 | 该季 `advance_quarter` 被接受后立即求值一次，结果写入 `<save>/onboarding.json`（§5.4） |
| 生命周期 | 第 5 季起自动关闭；设置中可重开（`docs/20` §11.2） |

### 2.1 第 1 季 · 跟随简报找到供电瓶颈，提交一项可融资的项目

#### 2.1.1 学习目标（§04 原文）

> 跟随简报找到供电瓶颈，提交一项可融资的项目。

拆成两个可检验的子目标：

| 子目标 | 含义 | 落点 |
|---|---|---|
| L1-a | 知道**症状→证据→机制→干预**这条动线存在，并至少走完一次 | 总览诊断卡四段（`docs/20` §7.1.3） |
| L1-b | 知道提交一项政策**必须同时指派资金来源**，否则不是一个完整的提案 | `reason.blk.source_unassigned` / `E_NO_FUNDING` 原因卡 |

**L1-b 是这一季真正的新概念**，不是「修电网」。「可融资」三个字承载的是财政纪律，不是路线。

#### 2.1.2 锚点与导语

| 项 | 值 |
|---|---|
| 主锚点 | `%DiagnosticStack/Card0/MechanismSection`（`docs/20` §11.2） |
| 同构替代锚点 | 若第 1 张诊断卡的机制段因任何原因不可见：改锚 `%RegionMap` 的 `layer.constraint` 图例（`docs/20` §11.1 保证 Q01 默认图层产生 ≥2 种着色，AC-20b） |
| `n/a` 条件 | 无（第 1 季必有诊断卡：Q01 冷启动态取剧本提供的初始约束诊断，`docs/20` §11.1） |
| 导语（逐字，20 汉字） | `这张卡从症状走到机制。干预段是可提交的命令。` |

导语逐字复核：不含政策名、不含祈使、不含顺序词、≤24 汉字。✔

#### 2.1.3 玩家可能的错误路径

| # | 错误路径 | 界面必须发生什么 | 为什么不拦 |
|---|---|---|---|
| `EP-1.1` | 只看三支柱的红数字，不进诊断卡，直接在政策目录里挨个点（菜单试错） | 政策目录**折叠态**即带一句原因（`docs/20` §7.3.2），试错本身就在读原因；目录不排序、不高亮「正确项」 | 试错是合法的学习方式；界面负责让试错产生信息，而不是消耗次数 |
| `EP-1.2` | 提交项目但未指派资金来源 | `reason.blk.source_unassigned`：「本季应付 {need}，已指派 {avail}，未指派 {gap}」+ ≥1 条出口（发债 / 调度税收 / 减小规模） | 这是本季核心新概念的教学时刻，必须让它发生 |
| `EP-1.3` | 选中的地区建设队列已满 | `reason.blk.queue` / `E_NO_SLOT`：「需要 {n} 位，余位 {m}，最早入队第 {N} 季（{占用者}）」 | 队列是 §04「真正的限制」之一，必须以原因对象而非灰按钮呈现 |
| `EP-1.4` | 以为提交即完工，本季就期待供电改善 | 影响预览左栏 `算 确定性后果` 明写逐季现金占用与**最早反馈季**；确认框「本季将发生的全部不可逆动作」只列支出，不列能力 | 这是第 2 季的课；第 1 季只埋证据，不提前讲解 |
| `EP-1.5` | 把引导读成「必须先修电网」 | 诊断卡干预段**必须给 2–3 个可比选项**，且其中 ≥1 个是非建设选项（如「暂缓扩产」）（`docs/20` §7.1.3）；导语不含任何政策名 | §05 明令；若实测中 5 人里 ≥3 人第一局都选同一条，记为**设计缺陷线索**（§8.4），不是好结果 |
| `EP-1.6` | 什么都不提交就推进 | 空草案可直接推进（`docs/20` §8.2 / §6.2 `IDLE`）；确认框仍渲染四季现金预测与承诺（显示义务与草案无关） | §05「暂缓扩张」必须是有讨论条件的选项，不能靠禁止推进来否定它 |

#### 2.1.4 界面如何提示而不代替判断

| 做 | 不做 |
|---|---|
| 诊断卡把症状（`实`）、证据（台账入口）、机制（`算` + 规则号）、干预（2–3 个**可比**选项 + 各自代价短语）四段摆齐 | 不给「推荐」「最优」标记；不把某一条干预排在显眼位置或加色 |
| 每条被拒命令给出 `need / avail / gap` 三个数字 + ≥1 条**可执行**出口 + `residual_gap` | 不写「请考虑削减支出」这类纯文字建议（`docs/20` RC-08） |
| 干预段 2–3 项的代价短语同格式、同字号、同颜色 | 不用字号、粗细、颜色制造推荐梯度 |
| 引导导语只描述这张卡的**读法** | 不描述这张卡的**结论** |

#### 2.1.5 达成判据（机器可求值）

```
MET(Q1) := P1.A ∨ P1.B ∨ P1.C

P1.A  # 提交成功且资金来源完整
  := ∃ c ∈ CMD(0):
        c.kind ∈ {project_launch, policy_enact}
        ∧ c.accepted == 1
        ∧ c.args.funding_source ≠ null

P1.B  # 被拒 → 读了原因 → 换一条重新提交（试错但读懂了）
  := (∃ r ∈ CMD(0): r.accepted == 0 ∧ r.kind ∈ {project_launch, policy_enact})
     ∧ (∃ e ∈ EV(0): e.name == "ev.reason_exit_opened"
                     ∧ e.args.code ∈ reject_codes_of(CMD(0)))
     ∧ (∃ c ∈ CMD(0): c.accepted == 1
                     ∧ c.kind ∈ {policy_enact, policy_set_params, project_launch,
                                 budget_reallocate, issue_bond})

P1.C  # 无命令路径（OB-F5 要求的那一条）：读懂了，这一季决定不动
  := (∃ e ∈ EV(0): e.name == "ev.section_expanded"
                   ∧ e.args.node matches "%DiagnosticStack/Card*/MechanismSection")
     ∧ (∃ e ∈ EV(0): e.name ∈ {"ev.page_shown", "ev.section_expanded"}
                   ∧ e.args.target ∈ {"page.region", "%ConstraintLadder"})
     ∧ (∃ e ∈ EV(0): e.name == "ev.ledger_opened"
                   ∧ e.args.ledger ∈ {constraint, project, cash, debt})
```

三条路径互不包含：`P1.A` 无需读任何原因卡；`P1.B` 必须被拒过；`P1.C` 不含任何命令。
`P1.C` 满足 `OB-F5` 的「无命令路径」要求。

#### 2.1.6 完成判据 vs 达成判据

**这两个必须分开，否则引导就变成了轨道。**

| 判据 | 定义 | 用途 |
|---|---|---|
| **完成**`DONE(Qn)` | `∃ c ∈ CMD(n-1): c.kind == advance_quarter ∧ c.accepted == 1`，且该季未触发 §6.5 卡住协议第 ③ 级 | §15 G4 门槛与 §17 门槛的前半句「可完成前 4 季」 |
| **达成**`MET(Qn)` | §2 各季的析取谓词 | 引导自身的有效性（`AC-OB-02`）与试玩观测；**不进入 §17 门槛** |

一个玩家可以 `DONE` 而不 `MET`（推了季但没读懂），也可以 `MET` 而不 `DONE`（读懂了但时间耗尽）。
§17 门槛只看 `DONE(Q1..Q4)` 全成立 + 解释题合格（§8.1）。

### 2.3 第 3 季 · 面对住房或培训需求，学会查看分配后果

#### 2.3.1 学习目标（§04 原文）

> 面对住房或培训需求，学会查看分配后果。

### 2.4 第 4 季 · 完成首次年度审查，辨认收入改善和公共服务负担并存

#### 2.4.1 学习目标（§04 原文）

> 完成首次年度审查，辨认收入改善和公共服务负担并存的情况。

| 子目标 | 含义 |
|---|---|
| L4-a | 认出这是**两件同时成立的事**，不是一个净额 |
| L4-b | 认出公共服务运行费是**每季重复发生**的（`U每季`），而收入改善是**本年一次性对比** |
| L4-c | 认出债务/GDP 比率**不替代偿付能力分析** |

#### 2.4.2 锚点与导语

| 项 | 值 |
|---|---|
| 主锚点 | `%AnnualReview` 的**两块交界处**（`docs/20` §10.1：左块本年收入 / 右块本年公共服务负担，禁止折叠、禁止合成单值） |
| 触发 | 年度审查覆盖层出现在**显示第 4 / 8 / … 季**（内部 `q ≡ 3 (mod 4)`，`docs/20` §19）——这是制度规则，不是引导安排 |
| 同构替代锚点 | 无（覆盖层必现） |
| `n/a` 条件 | 第 4 季前执政已提前结束（财政重组失败路径）→ `step.na = true`，并记 `early_end` |
| 导语（逐字，22 汉字） | `左边是本年收入，右边是每季运行费，两件事同时成立。` |

#### 2.4.3 玩家可能的错误路径

| # | 错误路径 | 界面必须发生什么 | 备注 |
|---|---|---|---|
| `EP-4.1` | 看到收入上升就认为财政改善，不读右块 | 两块**并列、禁止折叠**，右块含「已投运资产的每季运行费明细」与「`算` 下一年运行费（含在建项目投运后的增量）」 | 这是本季课程的全部内容 |
| `EP-4.2` | 把「净覆盖缺口 Z」当成本季现金缺口 | 结论行三槽位模板写死单位：`本年收入改善 {X} U，同期新增公共服务运行费承诺 {Y} U每季，净覆盖缺口 {Z} U。`；`U` 与 `U每季` 的量纲差异由 `JwUnitTag` 承载 | 量纲混淆是这一课最典型的失败模式 |
| `EP-4.3` | 把债务/GDP 比率当偿付能力结论 | 比率带角标 `比 · 四季滚动 · 分母=名义GDP`，紧跟固定句 `该比率不替代偿付能力分析，见四季现金预测与到期表。`（`docs/20` §10.1） | §07 明文 |

| `EP-4.6` | 想在第 4 季一次性把前三季的问题都改完 | 不阻止；但确认框逐条列出新增长期承诺与不可逆动作，`GAP` 必须绑定出口（`docs/20` §8.5 GR-1） | 没有行动点上限，只有承诺与队列 |

#### 2.4.4 界面如何提示而不代替判断

| 做 | 不做 |
|---|---|
| 左右两块并列、不可折叠、各 ≥4 行分解 | 不合成为单一「财政健康」数值 |

#### 2.4.5 达成判据


## 3. 判据的机器求值

### 3.1 两个数据源

| 源 | 文件 | 谁写 | 是否进哈希 |
|---|---|---|---|
| 命令流 | `<save>/commands.jsonl`（`docs/11` §6.1） | Application 层，玩家提交时 | **是**：进 `manifest.command_log_hash` |
| UI 事件 | `<save>/ui_events.jsonl` | Presentation 层的事件总线 | **否**：不进 `command_log_hash`，不进 `state.content_hash`（`OB-F12`） |

**硬规则 `EV-0`**：UI 事件**不是命令**。它们不进入命令流、不参与重放、删除后重放结果必须逐位相同。
这一条必须由 `AC-OB-05` 断言，否则一次界面改版就会让历史存档的重放分歧。

### 3.2 事件集合（15 个，封闭集）

新增事件必须同步登记：名称 / 触发控件 / args schema / 被哪条谓词使用。**未被任何谓词或观测项使用的事件不得新增**（§03 范围闸门）。

| 事件名 | 触发 | args |
|---|---|---|
| `ev.page_shown` | 主页面成为当前页 | `{page_id}` |
| `ev.overlay_opened` | 覆盖层打开 | `{overlay_id, left_block_visible, right_block_visible}`（后两项仅年度审查） |
| `ev.section_expanded` | L2 区块展开按钮被触发（鼠标或 `Alt+Space`） | `{node, target}` |
| `ev.ledger_opened` | `JwLedgerDrawer` 打开或定位 | `{ledger, row_id, focus_row}` |
| `ev.rule_card_opened` | `JwRuleCard` 打开（`Alt+R` 或规则角标） | `{rule_id, from_node}` |
| `ev.reason_shown` | 一条 `JwReasonItem` 完成渲染并可见 | `{code, severity, q}` |
| `ev.reason_expanded` | 原因卡展开 | `{code}` |
| `ev.reason_exit_opened` | 原因卡的某条出口被点开 | `{code, exit_index}` |
| `ev.gap_bound` | 缺口绑定了一条处理路径 | `{code, path}` |
| `ev.cost_card_rendered` | 暂停 / 改期 / 撤回触发的成本卡渲染完成 | `{project_id, action}` |
| `ev.impact_source_changed` | 受益受损清单触发源切换 | `{source}` |
| `ev.matrix_field_changed` | 36 格矩阵着色字段切换 | `{field}` |
| `ev.group_focused` | 36 格矩阵中某一格被选中 | `{group_id}` |
| `ev.confirm_opened` / `ev.advance_confirmed` | 推进确认框打开 / 确认 | `{q}` |
| `ev.repeat_click` | 同一控件连续 ≥3 次点击且控件状态与 `content_hash` 均未变 | `{node, n}` |
| `ev.onb_step` | 引导步骤状态变化 | `{step_id, state ∈ {shown, dismissed, skipped, met, na}}` |

每条记录的公共字段：`{t_ms, q, name, args}`。`t_ms` 为**自本局开局起**的单调毫秒数，不是墙钟时间（避免写入可识别的时间戳，§7.5）。

### 3.3 求值时机与幂等

```
on advance_quarter accepted (q):
    step := steps[q]                       # q ∈ [0,3] 才有步骤
    if step == null: return
    if not step.precondition(state, CMD, EV):
        step.na = true ; emit ev.onb_step{step_id, "na"} ; return
    step.met    = any(pred(CMD(q), EV(q)) for pred in step.predicates)
    step.met_by = first satisfied predicate id (或 null)
    emit ev.onb_step{step_id, "met" if step.met else "not_met"}
    write <save>/onboarding.json
```

| # | 规则 |
|---|---|
| `EVAL-1` | 求值**只在该季推进被接受后发生一次**，不在季中实时求值（否则会诱导玩家「刷判据」） |
| `EVAL-2` | 求值结果**不在界面上显示**。玩家看不到「本季学习目标已达成」之类的提示（`OB-F8`：引导不评价） |
| `EVAL-3` | 求值是**纯函数**：同一 `(CMD, EV, state)` 两次求值结果逐位相同（`AC-OB-04`） |
| `EVAL-4` | 求值只读 `CMD(q)` 与 `EV(q)`（本季），不跨季累积。跨季行为的观测归 §7 试玩记录，不归判据 |
| `EVAL-5` | 跳过引导后求值**继续进行**（`OB-F7`），只是不再渲染 `JwAnchorTip` |

### 3.4 `n/a` 的处理

`step.na == true` 的步骤：

- **不计入** `AC-OB-02` 的达成率分母；
- 不产生任何界面提示（不写「本季无内容」，那会变成催促）；
- 在试玩记录表中单列一列 `na_steps`，作为**设计观测项**：若 5 人中 ≥3 人的第 2 季都是 `n/a`，
  说明第 1 季的动线没把任何人送到一个项目或一笔承诺上——这是**设计缺陷线索**，不是玩家问题（§8.4）。

## 4. 决策密度，而不是强制行动点

> §04 原文：**每季推荐处理 2—3 件重要事项，但不设置凭空出现的「每季只能点三次」限制。
> 真正的限制来自财政承诺、立法窗口、采购进度与部门执行队列。低风险维护可以预先设定，减少重复操作。**

### 4.1 禁止：任何形式的行动点

| # | 禁止 | 检查 |
|---|---|---|
| `DD-1` | 不得存在任何「每季操作次数 / 行动点 / AP / 精力 / 政治资本点数」字段 | 全仓库字段名与类名静态扫描：`(?i)(action_point\|\bap_\|_ap\b\|moves_left\|energy_points\|political_capital_points\|每季次数\|行动点)` == 0 命中 |
| `DD-2` | 草案篮不得设条数上限 | 构造 30 条草案的夹具，断言全部进入草案篮且确认框全部渲染（`docs/20` §7.3.5） |
| `DD-3` | 推进按钮不得因「本季已提交 N 条」而变状态 | `JwDockState` 九态的转移条件中不得出现草案条数（`docs/20` §6.2 已定，本条为交叉断言） |
| `DD-4` | 不得用弹窗、确认次数或动画时长制造隐形节流 | 断言从 `IDLE` 到结算完成的必要点击数恒为 2（§4.3） |

### 4.2 允许：四类真实限制的可观测形态

每一类限制**必须以原因对象出现**，带 `need / avail / gap`、发生季与 ≥1 条出口——不得表现为灰按钮。

| 限制类 | 状态来源（`docs/12`） | 原因码（`docs/20` §9.6） | 界面落点 | 玩家的出口 |
|---|---|---|---|---|
| **财政承诺** | `state.gov.committed_memo` / `reserved_memo`；`state.bond.*` | `gap.cash_now`、`gap.cash_path`、`gap.commit_overlap`、`gap.opex_unfunded`、`blk.source_unassigned` | 底部固定区承诺摘要三行；预算审查 A1/A2/B 表 | 发债 / 延期 / 削减 / 重组（`docs/20` §8.5） |
| **立法窗口** | `state.politics.next_budget_review_q`（`q ≡ 3 mod 4` → 显示第 4/8/…/40 季） | `blk.window`、`blk.authority` | 政策目录折叠态的原因行，含「下一窗口：第 {N} 季（还有 {N−q} 季）」 | 等待（**等待也是出口，必须写到第几季**，RC-06）/ 改用不需该窗口的工具 |
| **采购进度** | `state.project.delivery_progress_ppm`；`state.world.credit_limit_uu` / 交付能力上限 | `gap.fx_credit`、`note.supply_no_demand` | 季度报告时滞块的「交付进度 %」列；外部账户台账 | 改用国产方案 / 减小规模 / 延期 |
| **部门执行队列** | `region.construction_slots_total` vs `derived.region.construction_slots_used`；`E_NO_SLOT` | `blk.queue` | 底部固定区队列占用行 `建设 3/4 · 采购 2/4 · 培训 1/4 · 立法 0/4` | 换地区 / 等待到第 N 季 / 取消占位项目（带取消代价） |

**这四类共同构成「决策密度」**：玩家每季能做的事不受次数限制，但受**同时可承担的承诺量**限制。
第 1—4 季的实测密度（每季实际提交的被接受命令数）作为观测项登记（§7.2 `drafts_submitted`），**首版不设门槛**。

### 4.3 最小必要交互（MNI）：证明没有强制行动点

**定义**：`MNI(q)` = 在无 `BLOCK`、无 `GAP` 的状态下，从该季界面可交互 到 该季结算完成，玩家必须执行的最少交互次数。

| 季 | `MNI` | 序列 |
|---|---|---|
| 任意季（无草案） | **2** | ① 点「推进季度 ▸」→ 打开确认框；② 点确认 |
| 任意季（有 `WARN`） | **3** | ①；② 勾选「我已阅读全部 N 项提示」；③ 确认 |
| 任意季（有 `GAP`） | **2 + 每条 `GAP` 绑定 1 次** | `GR-1` 要求每条 `GAP` 绑定一条路径 |

| # | 断言 | 通过标准 |
|---|---|---|
| `MNI-1` | 脚本化以最小序列连续推进 40 季（空草案），断言零次被阻止、零次强制弹窗、零次必须打开预算审查 | 40/40 季通过 |
| `MNI-2` | 引导**开启**下重跑 `MNI-1`，断言 `MNI` 逐季不变 | 逐季相等 |
| `MNI-3` | 断言 `MNI` 不随草案条数、季号、常设指令条数变化 | 三组对照均为 2 |

`MNI-2` 是 `OB-F2` 在交互层的直接后果：引导不增加任何一次必要点击。

### 4.4 低风险维护如何预设：默认常设指令集

> §04：**低风险维护可以预先设定，减少重复操作。**
> 命令载体：`docs/11` §6.1 `kind == set_standing_rule`（code 11）。界面载体：`docs/20` §8.6 `JwStandingOrders`。

**新开局必须预设的 5 条常设指令**（`content/scenarios/*.json` 提供，不是代码硬编码）：

| 别名 | 作用对象 | 每季金额上限 | 自动终止条件 | 撤销代价 | 它替掉的重复操作 |
|---|---|---|---|---|---|
| `so.opex_autopay` | 已投运资产与公共服务设施的运行费 | 按规则计算的当季应付额 × 1.00 | 无（永续） | 无直接违约金；停拨降低服务可用率，不删除资产（§07） | 每季逐项手动拨付运行费 |
| `so.debt_service` | 到期本金与票息 | 当季到期额全额 | 无（永续） | 撤销后需每季手动排序支付优先级 | 每季手动安排偿付 |
| `so.unemployment_renew` | 失业保障给付（P03 生效期间） | 按资格人数与替代比例规则计算额 | P03 被撤销时自动终止 | 无；但停付触发支付优先级挤出提示 | 每季按合格人数重录给付 |

| `so.maintenance` | 已投运资产的计划维护 | 计划维护额 | 无（永续） | 维护欠账累积（`maintenance_backlog_ppm`） | 每季逐资产下维护单 |

#### 4.4.1 硬规则

| # | 规则 | 检验 |
|---|---|---|
| `SO-1` | 默认常设指令必须在**第 1 季冷启动时以一张披露卡显式列出**，不得静默生效（§04 信息设计底线：「可以隐藏未来冲击，不隐藏当前规则」） | 断言新开局第 1 季存在 `%StandingOrdersDisclosure`，含 5 行，每行四要素齐全 |
| `SO-2` | 披露卡是**非模态、可关闭、不阻塞**的，**不占用四步引导中的任何一步** | 断言披露卡不是 `JwAnchorTip`，关闭它不影响 `MNI == 2`；断言 `onboarding_steps.tres` 仍恰有 4 步 |
| `SO-3` | 每条常设指令必须有**撤销入口**与**撤销代价**，撤销代价复用 `docs/20` §7.5.3 成本卡渲染函数 | 5/5 条有撤销入口；撤销前必渲染成本卡 |
| `SO-4` | 常设指令**不跳过预算审查**，只跳过重复录入：每季自动进入草案，在 A1 表与确认框中以独立「常设」段显示并带 `常设` 徽章（`docs/20` §8.6） | 断言 A1 表存在「常设」段且段内条目带徽章 |
| `SO-5` | 常设指令产生的支出若造成 `GAP`，**仍必须绑定出口**，不因「是常设的」而豁免 | 构造常设支出致缺口夹具，断言 `JwDockState == GAP_UNBOUND` |
| `SO-6` | 常设指令的上限被触及时，超出部分**不自动拨付**，转为原因卡（`docs/20` §8.6） | 构造超限夹具，断言出现原因卡且含 `need/avail/gap` |
| `SO-7` | 披露卡文案跑 §1.4 与 `docs/20` §9.4 两张禁用词表 | 0 命中 |
| `SO-8` | 默认集合可在剧本层调整；**界面不得硬编码这 5 条** | 修改剧本的常设指令数组后重跑，断言披露卡行数随之改变，UI 代码零改动 |

#### 4.4.2 前四季的重复操作预算

预设这 5 条之后，前四季**不需要**任何一次「纯维护性」重复录入。可测形式：

> 脚本化以最小序列推进前四季，断言 `commands.jsonl` 中 `kind ∈ {budget_reallocate, set_payment_priority}`
> 且 `args` 与上一季逐字相同的命令条数 == 0。

若实测中试玩者仍出现同一控件的 `ev.repeat_click`，按 §8.4 归入**信息层级缺陷（P2）**，不归玩家。

## 5. 引导的实现

### 5.1 目录与文件

```
res://ui/onboarding/
    onboarding_director.gd      # JwOnboardingDirector：订阅只读快照与 UI 事件总线
    anchor_tip.gd / .tscn       # JwAnchorTip：非模态锚定提示条
    predicates.gd               # JwOnbPredicates：纯函数谓词库（无状态、无副作用）

    onboarding_steps.tres       # 4 步定义（数据，不是代码）
```

**层归属**：`JwOnboardingDirector` 属 Presentation 层，只消费 Application 层的只读快照与事件总线。
禁止引用 `res://sim/`（`docs/20` B-01 / AC-27），禁止构造 `Command`（`OB-F1`）。

### 5.2 `onboarding_steps.tres` schema

```gdscript
class_name JwOnbStep extends Resource

@export var step_id: StringName            # onb.q1 .. onb.q4
@export var quarter_internal: int          # 0..3
@export var anchor_path: NodePath          # 主锚点，必须可在关闭引导的构建中解析（OB-F9）
@export var anchor_fallback_path: NodePath # 同构替代锚点；可为空
@export var lead_text_key: StringName      # 导语的本地化 key，≤24 汉字（§1.4）
@export var lead_text_fallback_key: StringName
@export var precondition_id: StringName    # PRE2 / PRE4 / null
@export var predicate_ids: Array[StringName]    # ≥3 条（OB-F5）
@export var no_command_predicate_id: StringName # 必填且 ∈ predicate_ids（OB-F5）
@export var glossary_anchors: Array[StringName] # 术语首见锚点（复用 docs/20 §10.4）
@export var rule_anchors: Array[StringName]     # 规则手册锚点
```

| # | 资源层约束 | 检验 |
|---|---|---|
| `RES-1` | `predicate_ids.size() >= 3`；`no_command_predicate_id` 非空且在 `predicate_ids` 中 | 载入期断言 |
| `RES-2` | 导语字段只存 key，不存自由文本；文案表条目跑 §1.4 lint | 载入期 + lint |
| `RES-3` | `anchor_path` 与 `anchor_fallback_path` 必须能在四配置 C1–C4 下解析到位于 `%Body` 内的节点 | `AC-OB-01` |
| `RES-4` | 恰好 4 条 `JwOnbStep`，`quarter_internal` 为 `{0,1,2,3}` 的排列 | 载入期断言 |
| `RES-5` | 谓词实现必须是 `JwOnbPredicates` 的静态纯函数，签名 `(cmds: Array, evs: Array, snap: Dictionary) -> bool`，且不得写任何状态 | 静态扫描：函数体内无 `=` 赋值到成员、无信号发射 |

### 5.3 `JwAnchorTip` 实现约束

## 6. 试玩脚本（§17 可理解性门槛的执行协议）

> §17 原文：**5 名首次体验者中至少 4 名可完成前 4 季，并解释一项政策未按预期生效的原因。**
> §17 记录项：**第一次有效决策耗时、无法理解的指标、被忽视的警告、重复点击、失败原因以及第二局的策略变化。**
> §17 边界：**5 名测试者只是方向性检查，不能被解释成具有统计代表性的市场结论。**

### 6.0 样本声明（必须逐字出现在任何试玩报告的抬头）

```
本次试玩样本为 5 人，属方向性检查（directional check），不具统计代表性。
它能发现「多数人都撞上的同一堵墙」，不能估计任何比例、偏好分布或市场接受度。
任何形如「x% 的玩家……」的表述都不得由本记录推出。
```

`AC-OB-14` 断言：报告模板 `tools/playtest_report_template.md` 首段包含上述文本，逐字一致。

### 6.1 参与者：什么叫「首次体验者」

### 6.5 卡住协议（三级，必须严格执行）

「无需口头教学」是 §15 的**门槛条件**，任何口头提示都会污染该场数据。因此卡住必须按固定协议处理：

| 级 | 触发 | 主持人动作 | 数据后果 |
|---|---|---|---|
| ① | 参与者停止有效操作 **120 秒**（无点击、无页面切换，或反复点同一控件） | **静默**。继续计时与记录 | 无 |
| ② | 再过 **120 秒**仍无进展 | 念台词 `F-03`（`界面上有没有哪里能回答这个问题？`）。**只能念这一句，全场最多 3 次** | 记 `hint_level_2 += 1`；该季仍可计为完成 |
| ③ | 再过 **120 秒**仍无进展 | 给出**最小引导**（指出一个页面名，不解释内容），以便后续季能继续 | **该季记为未完成**（`completed_qn = 0`），并记 `blocker` 分类。后续季数据仍收集，但该场不再计入门槛的「全四季完成」 |

| # | 规则 |
|---|---|
| `ST-1` | 三级计时阈值（120 s）是**试玩协议参数**，登记在 §7.4，可由前两场经验调整，但**同一批 5 场必须使用同一值** |
| `ST-2` | 主持人在任何级别都不得指向具体政策、具体按钮或具体数字 |
| `ST-3` | 参与者主动提问一律回 `F-03`；提问本身记入 `playtest_events.csv`（`source = obs`） |
| `ST-4` | 到达第 ③ 级的季必须在报告中逐条列出：季号、卡住时长、最后一次有效操作、当时屏幕上可见的 `BLOCK`/`GAP` 条数 |

### 6.6 解释题：评分标准

**题目（逐字）**：`请挑一条你提交过、但结果和你预期不一样的政策，说说你认为是哪里没对上。`

**评分由 2 名评审独立判定；分歧时由第 3 人仲裁。评审不得是本场主持人。**

| 判定 | 标准 | 计入门槛 |
|---|---|---|
| **合格 `pass`** | 同时满足两条：<br>(a) 指出 ≥1 个**机制层环节**（见下方封闭清单）；<br>(b) 能指出在界面**何处**看到该证据（页面名或台账名，允许描述性表述如「那个左下角的项目表」，不要求准确 ID） | **是** |
| **半合格 `half`** | 满足 (a) 不满足 (b)：机制说对了，但记不起在哪看到 | 否。记入观测：信息可达性不足 |
| **不合格 `fail`** | 只说「钱不够」「运气不好」「游戏有 bug」「没反应」「太复杂」，或无法指出任何机制环节 | 否 |
| **无候选 `none`** | 追问一次后仍称一切都如预期 | 否。记入观测：可能反馈链太弱、时滞未被感知，或前四季确实未产生偏差 |

**机制层环节封闭清单**（命中任一即满足 (a)）：

```
资金来源未指派 / 现金不足 / 融资额度不足 / 融资价格 /
建设队列无空位 / 采购交付未到 / 施工进度未满 / 完工后下一季才供能 /
教师或医护或税务或施工人员不足 / 技能错配 / 目标组为空 /
新增供给无对应需求 / 审查或立法窗口未开 / 法定权限不足 /
支付优先级挤出 / 配给按优先级或比例 / 运行费无经常性来源 /
互斥政策 / 冷却期 / 参数越界
```

| # | 规则 |
|---|---|
| `EX-1` | 参与者**不需要使用上述术语**。用自己的话描述同一环节即算命中（例：「钱付了但没人去盖」= 施工进度未满；「没老师所以没人毕业」= 人员不足） |
| `EX-2` | 参与者指出的政策**不必真的**「未按预期生效」。判定只看解释的机制内容与证据位置，不核对模拟结果 |
| `EX-3` | 评审必须记录**逐字引述**（`playtest_session.csv` 的 `explain_verbatim` 列），否则该判定无效 |
| `EX-4` | 若 5 人中 ≥3 人命中**同一个**机制环节，报告必须单列该环节——它可能是唯一一条被界面讲清楚的链路，其余链路可能都没被看见 |

## 8. 门槛判定与报告口径

### 8.1 §17 那一行怎么算通过

> 原文：**5 名首次体验者中至少 4 名可完成前 4 季，并解释一项政策未按预期生效的原因。**

本文件采**严口径**：两件事必须落在**同一个人**身上。

```
pass_i  := completed_q1_i ∧ completed_q2_i ∧ completed_q3_i ∧ completed_q4_i
           ∧ (explain_verdict_i == "pass")

GATE    := (Σ_{i=1..5} pass_i) ≥ 4
```

**宽口径（未采用，但记录在案以便裁决）**：`(Σ completed_all4 ≥ 4) ∧ (Σ explain_pass ≥ 4)`，允许不是同一批人。
采严口径的理由：原文用「并」连接两个谓词，且 §02 北极星要求的是**同一个玩家**既能走完又能解释。
若首版实测在严口径下卡住而宽口径通过，**不得悄悄改口径**——必须作为一条明示裁决进入 §11 待决登记。

| # | 规则 |
|---|---|
| `GT-1` | 门槛计算的分母恒为 **5**。因 `deleted_by_request` 或环境登记不全而作废的场次**必须补测**，不得缩小分母 |
| `GT-2` | 到达卡住协议第 ③ 级的季 `completed = 0`，不因「后来自己走出来了」而回改 |
| `GT-3` | `explain_verdict == half` **不计入** `pass`。半合格是「机制懂了但界面没让他找到」，这恰恰是界面缺陷 |
| `GT-4` | 门槛不通过时按 §17 缺陷修复顺序处理：P0（错账、坏档、崩溃、无法继续）→ P1（机制错误、不可解释结果、操作阻断）→ P2（信息层级、重复操作、视觉细节）。**任何 P0 未清零不得重测** |

### 8.2 达成率（引导自身的有效性，不是门槛）

```
MET_RATE := (Σ_{i,n} [met(i,n) ∧ ¬na(i,n)]) / (Σ_{i,n} [¬na(i,n)])
```

**首版不设 `MET_RATE` 门槛。** 它是诊断量：

| 观察 | 读法 |
|---|---|
| `DONE` 高而 `MET` 低 | 玩家在推季但没读懂。界面「能操作」但不「能解释」——直指 §02 北极星未成立 |
| `MET` 高而 `explain_verdict` 差 | 玩家看过那块界面但没形成因果理解。多半是措辞问题，不是布局问题 |
| 某一季 `na` 比例高 | 前一季的动线没把人送到该季课程的对象上（§3.4） |

### 8.3 重测规则

| # | 规则 |
|---|---|
| `RT-1` | **重测必须换 5 名新的首次体验者**。已测过的人不再是首次体验者，其数据只能作为「第二次接触」的补充观测，不进门槛 |
| `RT-2` | 重测前必须列出本轮修复了哪些 P0/P1 条目，并指明每条对应哪一次观测记录（可追溯到 `session_id` + `q`） |
| `RT-3` | 重测使用**同一 `root_seed` 与同一剧本**，除非修复涉及剧本初值；涉及时必须在报告中标注并说明不可比性 |
| `RT-4` | 连续两轮不通过时，按 §18 风险处理原则**先修耦合、先砍内容**，不得靠增加引导步骤来过门槛——第 5 步引导即视为承认界面没说清楚（§11 `OQ-OB-7`） |

### 8.4 从试玩到缺陷：归因规则

试玩记录不是「玩家评分」，是**界面的缺陷证据**。归因必须按下表，不得归因为「玩家不够仔细」：

| 观测 | 归因 | 缺陷级 |
|---|---|---|
| ≥3 人在同一控件上 `repeat_click` | 该控件的状态变化不可见，或反馈不明确 | P2 |
| ≥3 人 `ignored_warnings` 含同一原因码 | 该原因卡的视觉权重或位置不足 | P1 |
| ≥3 人第一局都选同一条干预 | 诊断卡干预段的呈现有隐性推荐梯度，违反 §05 | **P1**（这是本规格最重视的一条） |
| ≥3 人 `explain_verdict` 为 `half` | 证据可达性不足（`docs/20` AC-08 的 3 次点击在实际中太深） | P1 |
| ≥3 人某指标 `unclear` 且 `severity == 阻断` | 该指标的五元组口径标注失效 | P1 |
| ≥3 人第二局 `strategy_delta_flags` 全为 0 | **可重玩性未成立**（§02 四个必须同时成立的体验之一）。不是界面问题，是机制或剧本问题，回流 §09/§05 | P1 |
| 任一人遇到崩溃、坏档、错账 | — | **P0**，立即停测 |

## 附录 C · 指标指认题的 8 个指标（`PT-10`）

每个指标截取**该数字及其口径角标**的局部截图（不含上下文区块），逐个问「这个数字是什么？」
记录三态：`能说出` / `说不出` / `说错`，并记逐字引述。

| # | 指标 | 页面 | 考什么 |
|---|---|---|---|
| 1 | 实际产出指数（`指·本季·基期=第1季·基年价`） | 总览支柱 A | 指数基期是否被读懂 |
| 2 | 失业率（`比·本季·分母=劳动力`） | 总览支柱 B | 分母是否被读懂（§05 明文：分母是劳动力，不是总人口） |
| 3 | 国库现金（`存·季末·名义`） | 总览支柱 C | 存量 vs 流量 |
| 4 | 四季最窄余量（**不含**本季草案） | 总览支柱 C 副行 | 与底部固定区同名数字的口径差（`docs/20` AC-23） |
| 5 | 四季最窄余量（**含**本季草案，区间形态） | 底部固定区承诺摘要 | 同上 + `预` 类的区间语义 |
| 6 | 本季新增能力 `0` | 季度报告时滞块 | 第 2 季课程是否落地 |
| 7 | 新增公共服务运行费（`U每季`） | 年度审查右块 | 第 4 季的量纲课 |
| 8 | 债务 / GDP 比率（`比 · 四季滚动 · 分母=名义GDP`） | 年度审查下方 | 是否被误读为偿付能力结论 |

**读法**：指标 4 与 5 是一对。若多数参与者说不出二者差别，说明 `docs/20` AC-23 的「两处措辞不相等」
在视觉上不足以传达口径差——那是 P1 缺陷，不是参与者不仔细。
