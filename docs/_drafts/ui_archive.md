> 提案编号 **UI-A**｜署名倾向 **国家档案派**｜版本 0.1 草案｜2026-09-12
> 需求依据：`docs/ref/plan_v1.0.txt` §03 §04 §07 §08 §11 §12 §13 §17 §18
> 本文是三份互不通气的独立提案之一，不是已选定方案。

## 0. 这份提案的立场

界面不是仪表盘，是**一份正在变化的国家档案**。

玩家不是在读一块屏幕，是在翻一份卷宗：封面（总览）— 分册（地区 / 社会）— 办件（政策工作台）—
季度纪要（季度报告），每一页都能向下追到**台账**，每一个数字都带**引用码**，
每一句结论都能被问"依据是哪一行"。

由此推出三条贯穿全文的组织规则：

| 规则 | 内容 | 为什么 |
|---|---|---|
| **R-A 引用强制** | 屏幕上任何一个数字，都必须能通过一次点击到达产生它的台账行；做不到的数字不允许出现在界面上 | 落实 §13"每条变化附带实体 ID、来源操作、金额／数量、时间和约束" |
| **R-B 分类强制** | 任何一个数字必须属于"已经发生 / 规则推断 / 情景预测"三类之一，并带可见分类标记；无法分类的数字视为缺陷 | 落实 §04 信息设计底线 |
| **R-C 口径随行** | 数字与其单位、期间、价格基期、分母**同屏**呈现，不允许只靠悬停 | 落实 §11 可读性规格、§14"先保证定义正确" |

克制使用图形：优先表格与排版，图形只在**分布**与**时间序列**两种信息形态上使用
（这两种用文字无法在同等面积内表达）。禁止装饰性图形、禁止进度环、禁止仪表盘指针、禁止雷达图。

```
+----------------------------------------------------------------+---------------------------+

+----------------------------------------------------------------+                           |
|                                                                |  当前选中项的：             |
|                        主 区                                    |   · 定义与口径             |
|                                                                |   · 输入台账行（可点）      |

```

- **顶部条**：国名 + 季度定位 + 国库现金。国库现金常驻是 §07"财政页面必须展示当前现金"的最低保证。
- **档案路径（Breadcrumb）**：每一级可点回退。这是"可追溯"的骨架，也是玩家不迷路的保证。
  规格：最多显示 5 级，超出时折叠中段为 `…`，鼠标悬停展开全路径；路径必须可复制为文本引用串。
- **证据栏**：不是提示气泡。它是常驻的第三栏，显示"主区当前选中对象"的全部出处。
  在窄档（见 §8.4）降级为覆盖式抽屉，用 `E` 键或点击引用码唤出。

### 1.2 台账登记表（界面侧的接口要求）

台账是本提案的信息底座。界面不定义它们的字段（那是数据协议文档的职责），
只声明**界面需要能打开哪些台账、每张台账必须提供哪些列**。

| 台账 ID | 名称 | 界面要求其提供的列（最低） |
|---|---|---|
| `L-CASH` | 国库现金流水 | 季度、方向、对手方 ID、金额、科目、来源命令 ID |
| `L-DEBT` | 债务与到期 | 批次 ID、债权人、本金、票息率、付息季、到期季、剩余本金 |
| `L-COMMIT` | 合同承诺 | 合同 ID、对手方、总额、已付、剩余付款曲线、取消违约条款 |
| `L-OPEX` | 服务运行费 | 资产/服务 ID、每季运行费、已拨付、拨付缺口、可用率影响 |
| `L-PROJ` | 项目进度 | 项目 ID、地区、交付进度、施工进度、队列位次、预计完工季 |
| `L-VA` | 增加值与中间投入 | 部门、地区、总产出、中间投入、增加值、价格基期 |
| `L-CONSTR` | 约束诊断 | 部门、地区、Q_plan/Q_capacity/Q_labor/Q_energy/Q_materials、生效约束项 |
| `L-INV` | 库存对账 | 物品、期初、生产、购入、售出、耗用、损耗、期末 |
| `L-LABOR` | 就业与劳动力 | 地区、群组、劳动力、就业、失业、分母定义 |
| `L-POP` | 人口流水 | 群组、出生、死亡、成年、退休、技能转变、迁入、迁出 |
| `L-HH` | 群组收入与负担 | 群组 ID、可支配收入、住房支出占比、服务可及性 |
| `L-SVC` | 公共服务可及性 | 服务、地区、容量、需求、排队、可用率 |
| `L-TAX` | 税收与征收能力 | 税种、法定税基、实际征得、征收覆盖率 |
| `L-EXT` | 外部账户 | 进口支出、出口收入、外债、利息、还款、额度余量 |
| `L-POL` | 政治支持与组织反应 | 群组/集团、当期生活、未来预期、程序信任、席位映射输入 |
| `L-EVT` | 事件与冲击日志 | 季度、模板 ID、抽样结果、随机流 ID、强度、剩余持续期 |
| `L-CMD` | 命令与重放 | 季度、命令 ID、参数、校验结果、拒绝原因 |

**引用码格式**：`台账ID#季度.行号`，例如 `L-CASH#Q07.014`。
界面上的每个引用码是一个 `CitationChip` 组件，点击后打开该台账并**滚动定位并高亮该行**（不是只打开表）。

## 2. 三类信息的视觉编码（§04 信息设计底线）

这是本提案最不可让步的部分。

### 2.1 编码表

| | **已经发生** | **规则推断** | **情景预测** |
|---|---|---|---|
| 分类字 | **实** | **算** | **预** |
| 图标 | ■ 实心方（4lu 实心正方） | ◇ 空心菱（4lu 菱形，1lu 描边） | ◌ 点圆（4lu 圆，1lu 点线描边） |
| 左标尺 | 3lu **实线**，`teal.fill` | 3lu **双线**（1lu 线 / 1lu 空 / 1lu 线），`teal.ink` | 3lu **点线**（2lu 实 / 3lu 空），`ink.tertiary` |
| 底色 | `paper.base` 平涂，无底纹 | `paper.sunk` 平涂 | `paper.base` + 45° 斜线底纹（线宽 1lu，间距 8lu，色 `paper.rule.hair`） |
| 数字排版 | 裸数字，等宽表格数字，**不加括号、不带区间** | 裸数字 + 紧跟上标规则号 `^R·07`，**不加括号、不带区间** | **必须**置于 `〔 〕` 内，**必须**为区间 `〔0.31 – 0.58〕`，禁止单点数 |
| 措辞前缀 | 「本季实际……」「已记录……」 | 「按模型规则……」「模型中的限制因素是……」 | 「若……则可能……」「在<情景名>下……」 |
| 强制附带 | 台账引用码（必有） | 规则 ID + 输入台账引用码（必有） | 情景 ID + 假设清单链接（必有） |
| 时态词禁用 | 禁用"将""可能""预计" | 禁用"实际""已经""将" | 禁用"实际""已经""确定" |

### 2.3 为什么不会互相混淆

三类之间存在 **5 条彼此独立的编码通道**，且其中 3 条在完全去色的情况下仍然有效：

| 通道 | 去色后是否有效 | 三类取值互斥 |
|---|---|---|
| 分类字（实 / 算 / 预） | 有效 | 是 |
| 图标形状（实心方 / 空心菱 / 点圆） | 有效 | 是 |
| 左标尺线型（实线 / 双线 / 点线） | 有效 | 是 |
| 底纹（无 / 平涂 / 斜线） | 有效 | 是 |
| 色相（青绿 / 青绿深 / 暖灰） | 无效 | 否（实与算同色相，靠线型区分） |

在此之上再加 **3 条结构性硬规则**，任何一条被违反都是缺陷，而不是风格问题：

1. `〔 〕` 与区间**只**出现在情景预测。看到方括号就一定是预测。
2. 台账引用码 `L-xxx#Qnn.row` **只**出现在已经发生。看到引用码就一定是既成事实。
3. 上标规则号 `^R·xx` **只**出现在规则推断。看到上标规则号就一定是模型推断。

**验收**：`test_ui_class_encoding.gd`
对 5 个主页面 + 预算审查 + 季度报告的全部数字节点做遍历，断言：
(a) 每个数字节点的 `info_class ∈ {actual, derived, projected}`，无 `null`；
(b) `info_class == projected` 的节点，其文本匹配 `^〔.+–.+〕$`，否则失败；
(c) `info_class == actual` 的节点，`citation` 非空且能在对应台账中解析到行；
(d) `info_class == derived` 的节点，`rule_id` 非空；
(e) 措辞前缀不含该类禁用时态词（正则表）。

### 2.4 分类归属的判定规则（逐单元格，不逐表）

一张表里可以同时出现三类。**分类按单元格判定，不按表判定**。判定优先级：

1. 该数值已由某个已结算季度的台账行记录 → **实**。
2. 否则，该数值由合同、票息、到期本金、已核定运行费等**契约性确定项**按固定规则算出，
   且不依赖任何未来经济结果 → **算**。
3. 否则（依赖未来税基、出口收入、价格、就业等经济结果） → **预**，必须给区间。

这条规则的直接后果：**四季现金预测表是混类表**——到期本金与已签合同付款是 `算`，
税收与出口收入是 `预`。这正是我们要让玩家看见的区别。

## 3. 五个主页面

通用规格（下文各页不再重复）：

- **口径标注要求**：每个数字旁必须同屏可见 `单位`；此外按类型必须给出
  - 存量/流量标记（存量写"期末"或"期初"，流量写"本季"或"全年"）
  - 价格基期（名义 / 基年价，实际量一律标"基年价"，§06 精度边界）
  - 分母（一切比率必须把分母写在可见位置，例：失业率 8.0%（分母＝劳动力 1,180 万，非总人口））
  - 分类徽章（§2）与引用码（R-A）
- **首屏**定义：在 1366×768 @100% 与 1920×1080 @150% 下**不滚动**即可见的区域。
  各页"首屏必须有"的区块在这两种配置下都必须完整可见，这是可测的（§9 验收 6）。
- **第二层**：在同页内展开 / 右证据栏 / 台账全屏三种，逐页指明。

**排序规则（风险卡最多 3 项）**：候选池 = {约束诊断中生效约束项} ∪ {四季现金低于下限的季度} ∪
{承诺占用率越阈值项} ∪ {服务可用率下降项} ∪ {群组负担越阈值项}。
排序键依次为：(1) 类别权重（阻断 > 缺口 > 警示），(2) 影响量的**归一化**幅度降序，
(3) 首次出现季度升序。**不足 3 项时显示实际条数，禁止用次要项凑满**——
这是为了让"没有优先风险"成为一个可被读出的信号。

**数据来源**：区块二严格按 §13 的 8 步顺序取结算日志，**步序不可重排**——

**第 40 季结算**：同页模板，标题改为"发展档案（第 01–40 季）"，

### 5.3 原因文案的生成规则

原因由**预算引擎 dry-run** 产生，界面只负责渲染，不允许自行估算（§11 禁止事项）。

**模板**

```
行1  〔类别徽章〕〔编号〕 〔类别名〕
行2  {主语实体}{判定动词}{量化缺口}{单位}{季度定位}。判定依据 {规则ID}。
行3  可做： [动作1] [动作2] [动作3]
行4  出处： {台账引用码 1} ｜ {台账引用码 2} ｜ …
```

**生成规则（逐条可测）**

| 编号 | 规则 |
|---|---|
| G-01 | 每条原因**必须**至少含一个数字、一个单位、一个季度标识。三者缺一即为缺陷，lint 拒绝。 |
| G-02 | 金额显示为 U，保留 2 位小数（内部 μU 整数，显示层四舍五入）；悬停必须显示完整 μU 整数，禁止只显示舍入值。 |
| G-03 | 量化缺口的算法必须写明是"点值"还是"按预测区间中值"；若基于区间，文案必须出现"（按下限中值计）"。 |
| G-04 | `判定依据` 必须是一个可打开的规则 ID，指向规则说明卡（含判据表达式与阈值参数 ID）。 |
| G-05 | `可做` 为 1–3 个动作，**每个动作必须是一条可执行的 UI 命令**（改额度／改季度／改来源／删除条目／打开台账）；禁止纯文字建议如"请考虑削减支出"。 |
| G-06 | `出处` 至少 1 个台账引用码，点击定位到行。 |
| G-07 | 禁用词表：`不可用`、`无效`、`错误`、`失败`、`不满足条件`（单独出现时）。lint 以正则匹配文案全文，命中即失败。禁用词只有在其后紧跟"：{原因}"时才允许。 |
| G-08 | 同一草案条目产生多条原因时合并为一张卡片，实体名只出现一次，原因逐条列出。 |
| G-09 | 排序：A 类 → B 类 → C 类；同类内按 \|缺口量\| 降序；缺口量相等或不可比时按编号升序。 |
| G-10 | 默认展开前 3 条，其余折叠；折叠标题必须写「另有 N 条（A a / B b / C c）」，禁止只写「更多」。 |
| G-11 | 原因随参数编辑重算，重算节流 200 ms；重算期间保留上次结果并标注"重算中"，禁止闪烁清空。 |
| G-12 | 原因文案模板全部来自内容层的文案表（可本地化），不在 GDScript 里拼字符串；文案表每条带 `reason_id` 与槽位声明。 |

### 5.4 原因类别全表

### 6.3 间距栅格

- **基本单位 4 lu**。间距刻度：`4 / 8 / 12 / 16 / 24 / 32 / 48 / 64`。不允许出现刻度外的值。
- **列栅格**：12 列，槽距 24 lu，页边距 宽档 32 lu / 中窄档 24 lu。
- **基线栅格 26 lu**（= 正文行高）。区块高度取 26 的整数倍，误差对齐到 4 lu。
- **表格**：行高 40 lu（H-tall）/ 34 lu（H-short）；单元格左右内边距 12 lu；
  表头下线 `paper.rule.struct` 1lu；行间细线 `paper.rule.hair` 1lu；合计行上线 `paper.rule.struct` 2lu。
- **卡片**：内边距 16 lu；卡间距 12 lu；圆角 2 lu（档案感，不用大圆角）；无阴影，用 1lu 边框。
- **最小命中区**：任何可点击元素的命中矩形 ≥ 32 × 32 lu，即使视觉尺寸更小。
- **验收**：`test_spacing_grid.gd` 遍历全部 Control，断言其 `position`/`size` 的
  非自适应显式偏移量 ∈ 刻度集合；命中区断言 ≥ 32×32。

### 6.4 布局断点

尺寸单位 **lu**（逻辑单位）。`ui_scale ∈ {1.00, 1.25, 1.50}`，由 `DisplayServer.screen_get_scale()`
初始化并可在设置中覆盖。**1 lu 渲染为 `ui_scale` 个物理像素**；窗口的 lu 宽度 = 物理宽度 ÷ `ui_scale`。
**绝不使用整屏等比拉伸**（`stretch/mode = disabled`）——等比拉伸会在 1366×768 上把 17 lu 正文
压到约 12 物理像素，直接违反 §11 的 16 像素底线。

| 档 | lu 宽度 | 布局 |
|---|---|---|
| `W-wide` | ≥ 1600 | 三栏：左目录 200 lu ｜ 主区弹性 ｜ 右证据栏 380 lu |
| `W-mid` | 1280 – 1599 | 两栏：左目录折叠为 56 lu 图标条 ｜ 主区弹性 ｜ 证据栏改为覆盖抽屉（`E` 唤出） |
| `W-narrow` | < 1280 | 单栏：目录改顶部下拉 ｜ 证据栏为全屏抽屉 |

| 档 | lu 高度 | 布局 |
|---|---|---|
| `H-tall` | ≥ 900 | 顶部条 48 + 页签 40 + 路径 32；底部固定区 96；表行 40 |
| `H-short` | < 900 | 顶部条与页签合并为 48；路径 28；底部固定区 72；表行 34 |

**目标配置核算**

| 配置 | lu 尺寸 | 档 | 内容区高度 (lu) | 正文物理像素 |
|---|---|---|---|---|
| 1920×1080 @100% | 1920 × 1080 | W-wide / H-tall | 1080−48−40−32−96 = **864** | 17 |
| 1366×768 @100% | 1366 × 768 | W-mid / H-short | 768−48−28−72 = **620** | 17 |
| 1920×1080 @125% | 1536 × 864 | W-mid / H-short | 864−48−28−72 = **716** | 21.25 |
| 1920×1080 @150% | 1280 × 720 | W-mid / H-short | 720−48−28−72 = **572** | 25.5 |

最苛刻配置是 **1920×1080 @150%**（1280×720 lu，内容区 572 lu）。
五个主页面的"首屏必须有"清单**以此配置为设计约束**：572 lu 内必须装下。
按 §3 各页的首屏清单核算：总览需 3 张风险卡（各 76 lu，共 228）+ 三栏关键数（120）
+ 地区图与诊断（200）+ 区块间距（24）= 572 lu，恰好占满，因此总览页的风险卡
在 `H-short` 档默认**证据链折叠为 1 行**（规格已如此写）。

## 7. 可读性规格与验收测量方法

每条规格 = 要求 + **怎么量** + **量到什么算通过**。
测量在 **REF-01 参考机**（见 `docs/ENGINE.md`）上进行，四种目标配置各测一遍：
`C1 = 1920×1080@100%`、`C2 = 1366×768@100%`、`C3 = 1920×1080@125%`、`C4 = 1920×1080@150%`。

| # | 规格 | 怎么量 | 通过线 |
|---|---|---|---|
| **1** | 正文 ≥ 16 物理像素 | 以 `--ui-audit` 启动开关遍历全部 `Control`，导出 CSV：`节点路径, 字族, font_size(lu), ui_scale, 有效像素=font_size×ui_scale, 是否可见`。四配置各导一份。另做人工复核：对 C2 截图，用像素取色量「国」字外接框高度。 | CSV 中所有 `是否可见=true` 行的 `有效像素` **最小值 ≥ 16**，且豁免清单为空；人工复核「国」字外接框 ≥ 16 物理像素 |
| **2** | 文字对比度 ≥ 4.5:1，非文字 ≥ 3.0:1 | (a) 自动：`test_contrast.gd` 读取 Theme 的前景/背景令牌配对注册表（每个组件声明自己用哪一对），按 WCAG 相对亮度公式计算；(b) 截图取样：五个主页面 + 预算审查各截图，在预先登记的 12 个采样点取相邻像素对计算，与 (a) 结果比对 | (a) 全部文字对 ≥ 4.5，非文字结构对 ≥ 3.0，无未注册配对；(b) 与 (a) 的差值 ≤ 0.05 |
| **3** | 风险必须同时用文字、图标、颜色表达 | (a) 自动：遍历全部 `RiskBadge`/`ClassBadge`/状态徽章，断言 `text` 非空、`icon` 非 `null`、`icon.shape_id ∈ {4 种登记形状}`；(b) 人工：对五主页面各出三张图——原图、完全去色图（保留相对亮度）、色觉模拟图（protanopia / deuteranopia / tritanopia 各一），请 2 名未参与开发者在**去色图**上指出全部风险项与三类信息标记 | (a) 零违例；(b) 2 名评审在去色图上对风险项与三类标记的指认准确率 **100%**，用时不限 |
| **4** | 图表必须标注时间、单位、价格基期、分母 | (a) 自动：所有图表继承 `ChartBase` 并实现 `get_meta() -> {time_range, unit, price_base_year, denominator}`，测试断言四项均为非空字符串；(b) 渲染断言：四项对应的 `Label` 节点存在且其 `rect` 完全落在图表框内（不被裁切） | 全部图表（首版 ≥ 12 张）四项齐备且可见；缺一即失败 |
| **5** | 四配置下不截断、无横向滚动、命中区达标 | 脚本化 UI 测试：四配置 × （5 主页面 + 预算审查 + 17 张台账 + 结算进度层）逐个打开并截图，断言：(a) 无 `Label` 触发 `text_overrun_behavior` 的省略；(b) 根 `ScrollContainer` 的 `scroll_horizontal` 最大值 ≤ 0；(c) 全部可交互 `Control` 的命中矩形 ≥ 32×32 lu；(d) 无 `Control` 溢出其父容器 `rect` | 四配置全通过，零违例 |
| **6** | 首屏信息量 | 每页在规格中声明 `required_above_fold` 节点名清单。测试在 **C2 与 C4** 下打开该页，不滚动，断言清单中每个节点 `visible == true` 且 `get_global_rect()` 完全落在视口内 | C2 与 C4 下全部主页面的首屏清单 100% 可见 |
| **7** | 结算过程可见、不假死 | 推进季度时记录帧日志，测量 `StepProgress` 相邻两次文本更新的时间间隔 | 相邻更新间隔 ≤ 100 ms；总结算时长与 §17 性能门槛分开记录（门槛约束 SimCore，不约束绘制） |
| **8** | 三次点击可达证据 | 自动遍历五主页面首屏全部带 `citation` 的数字节点，用 UI 图搜索最短交互路径至其台账行高亮态 | 全部 ≤ 3 次点击 |

四地区用**清楚的行政轮廓**（多边形），**不用密集六边格**（§11 明文）。

## 11. 本提案已知的取舍

1. **克制图形的代价**：表格密度高，新玩家第一屏信息量偏大。缓解手段是"首屏只放 3 张风险卡"
   与"证据链默认折叠"，但这仍需 §17 的 5 人试玩验证（"至少 4 名可完成前 4 季"）。
2. **引用强制的代价**：每个数字都要带引用码，占用横向空间，并要求 SimCore 为每个值保留来源。
   这会增加 SimCore 的记录负担。取舍理由：§13 本来就要求"每条变化附带实体 ID、来源操作、
   金额／数量、时间和约束"，引用码只是把这项已有要求暴露到界面。
3. **深蓝框 + 暖灰纸的双底色**：需要维护两套文字色令牌（`ink.*` 与 `onchrome.*`），
   组件必须声明自己处于哪一面。代价是组件多一个 `surface` 参数；收益是"卷宗 + 纸页"的
   隐喻直接成立，且赭色在两面上都有合格对比度的变体。
4. **不做自由缩放地图**：失去"放大看细节"的操作，但 4 个地区的信息密度不需要缩放，
   且固定比例让截图测试（§7 #5）可稳定断言。
