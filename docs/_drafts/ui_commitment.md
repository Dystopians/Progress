## 0. 一句话立场

**界面是一张承诺与约束表，不是一块仪表盘。**

玩家在这个游戏里真正要管理的不是「当前数值」，而是**已经签下的、还没兑现的东西**：在建项目的剩余付款、债券批次的到期本金、建成设施的永续运行费、施工队列的占用、培训队列的结业时间、政治上已经许下的分配承诺。

因此本提案的组织主干是**时间轴、到期表、队列、预算占用**四件套，五个主页面都围绕同一条时间轴排布，每一页的右侧都常驻同一根**承诺栏**。指标（GDP、失业率、指数）是这些承诺的**结果读数**，放在次要位置；「后劲」和「不可逆成本」放在首屏。

这个立场要落到三条可检验的产品规则上：

| 规则 | 编号 | 可检验形式 |
|---|---|---|
| 任何屏幕上的货币数字，都必须能回答「这笔钱被占用到哪一季」 | `R-COMMIT-1` | 每个货币数字节点必须挂 `horizon_quarters: int`（0 = 仅本季存量）与 `ledger_id`；`--ui-audit` 遍历断言非空 |
| 任何一次「推进季度」之前，玩家必须已经看过四季现金预测与新增长期承诺 | `R-COMMIT-2` | `budget_review_seen_for_turn == current_turn` 才允许启用推进按钮；单元测试覆盖 |
| 任何不可逆支出在**发生之前**必须至少出现一次带「不可逆」徽章的显式提示 | `R-COMMIT-3` | 结算器输出的每笔 `irreversible = true` 的支出，必须在本回合的确认清单中有对应条目；回归测试比对集合相等 |

## 1. 全局外壳与信息分层

### 1.1 三层信息模型（全局约定）

| 层 | 名称 | 内容边界 | 进入方式 | 退出方式 |
|---|---|---|---|---|
| L1 | **首屏层** | 不需要滚动即可看到。只放：本季身份、三项优先风险、承诺栏摘要、本页主问题的直接答案 | 打开页面 | — |
| L2 | **展开层** | 同页内展开/滚动。放分解（按地区、按部门、按群组）、时间序列、预期 vs 实际 | 点击 L1 区块标题或「展开」 | Esc / 再次点击 |
| L3 | **台账层** | 右侧抽屉 `drawer.ledger`，宽 640（逻辑 px）。放逐行原始记录，可排序、可筛选、可导出 CSV | 点击任一数字或「查看台账」 | Esc / 抽屉外点击 |

**动线硬约束（可测）**：
- `R-NAV-1` 从任一 L1 数字到它的 L3 台账行，点击数 ≤ 2。
- `R-NAV-2` 从任一 L3 台账行返回它的 L1 数字，点击数 ≤ 1（抽屉头部常驻「返回 ←〈来源区块名〉」）。
- `R-NAV-3` 五个主页面之间互相跳转，点击数 = 1（顶栏页签常驻）。
- 验收：`tests/ui_navigation_depth.gd` 用页面图遍历所有 `ledger_id` 入口，断言最短路径长度满足上述三条。

## 2. 信息三分类：已经发生 / 规则推断 / 情景预测

计划书 §04「报告必须区分『已经发生』『规则推断』和『情景预测』」、§13「区分会计贡献、约束诊断与情景预测」。本节给出的编码是**全局的**，五个页面、所有图表、所有台账、所有原因文案一律适用。

### 2.1 三类定义（边界必须无歧义）

| 类 | 代号 | 定义（判定规则） | 典型内容 |
|---|---|---|---|
| 已经发生 | **F** | 该数字来自**已完成结算**的回合产物，且能在某条台账里找到一行或多行与之精确对账（求和残差 = 0） | 上季实际收入、已付项目款、库存期末余额、已签合同的到期本金 |
| 规则推断 | **R** | 该数字由**当前已知状态 + 已公开的固定规则**确定性推出，不含任何随机抽样与行为假设 | 未来四季到期本金与票息、在建项目按合同进度的应付款、已建成设施的运行费、「本季产量的最紧约束是电力」这类约束诊断 |
| 情景预测 | **S** | 该数字依赖**行为假设、价格响应速度或未来外生条件**，其中至少一项不是玩家可观测的当前规则 | 基线/不利两条路径的 GDP、就业、税收；政策生效后的容量利用率；集团反应强度 |

**判定边界的争议处理（写死，避免实现时反复）**：
- 若一个数字同时含 R 与 S 成分（如「未来四季现金」含确定的还本付息 R 与不确定的税收 S），**整体降级为 S**，但表格必须把 R 行与 S 行分行显示，并在行首各带各自的编码。禁止混在一行。
- F 类不得包含任何未来季度的数字。未来季度只能是 R 或 S。
- R 类不得出现区间，必须是单值；S 类不得出现单值，必须是区间或两条具名路径（基线 / 不利）。这条本身就是一个可测的不变式：`R-CLASS-1`。

### 2.2 视觉编码（四通道冗余，颜色只是第四通道）

| 通道 | F 已经发生 | R 规则推断 | S 情景预测 |
|---|---|---|---|
| **① 措辞前缀**（必需，中文，行首） | `实测 ·` | `按规则 ·` | `若 · ` |
| **② 左边条几何**（必需，3px 宽，贴块/行左缘） | **实线**，连续 | **短划线**：实 6px / 空 3px | **点线**：实 2px / 空 4px |
| **③ 图标填充度**（必需，14×14，前缀词左侧） | `●` 实心圆 | `◑` 半填充圆（左实右空） | `○` 空心圆（1.5px 描边） |
| **④ 颜色** | `--teal` `#5FB3AA` | `--lilac` `#A79CC4` | `--ochre` `#D99A4E` |
| **⑤ 底纹/外框**（块级时追加） | 无底纹，块背景 `--bg-panel` | 45° 斜细纹，线 1px `#1B2F3C`，间距 6px | 无底纹，块外框 1px 点线 `--ochre` |
| **⑥ 强制随附元数据** | `对账：〈ledger_id〉 · n 行` | `依据：〈规则名/公式〉`（可点开算式） | `假设：〈假设项列表〉` + `区间/两路径` |
| **⑦ 数值形态** | 单值，精度 = 口径精度 | 单值 | **禁止单值**：区间 `[a, b]` 或两行「基线 / 不利」 |

### 2.3 为什么不会互相混淆（设计论证 + 验收）

1. **通道正交**：三类在①②③上两两不同，且三个通道分别属于**语言、几何、形状**三种感知系统。任何单一感知缺陷（色觉、低分辨率、灰度打印）都不会同时抹掉三条。
2. **颜色可拆除**：`R-CLASS-2` 灰度回归测试 —— 把整屏渲染转灰度后，自动化断言三类块的①②③仍全部存在（前缀字符串匹配、边条 dash 模式属性、图标 glyph 码点）。通过条件：0 条缺失。
3. **形态互斥**：R 必单值、S 必区间/双路径（`R-CLASS-1`），所以即使编码全丢，**数值形态本身**还能区分 R 与 S。F 与 R 则靠「是否指向未来季度」区分（`R-CLASS-3`：F 类节点的 `horizon_quarters` 必须 = 0）。
4. **不允许无类**：`R-CLASS-4` 任何显示数字的 Control 必须携带 `info_class ∈ {F, R, S}`；`--ui-audit` 断言 0 条缺失，缺失即 P1 缺陷（计划书 §17 缺陷序）。

### 3.1 `ui.overview` 国家总览

**这一页回答**：「这一季我应该先看哪里？我已经欠下的东西撑不撑得住？」
（计划书 §11「国家总览解决『先看哪里』」）

**L1 首屏必须有（不滚动可见）**：
1. 季度身份条：`第 07 季度 (Y2Q3)`、任期目标、距下次预算审查/选举的季数。
2. **本季优先风险卡，最多 3 张**（计划书 §04「最多 3 项优先风险」）。每张卡 = 风险名 + 定量事实 + 信息类编码 + 「查原因 ▸」按钮。
3. **承诺时间轴 `ui.overview.timeline`**：横轴 Q07 → Q46（本季 + 未来 39 季，默认视窗显示 12 季），纵向四条泳道：债务到期、项目付款、运行费起点、队列结业/投运。这是本提案取代传统「三大指标卡」的首屏主体。
4. 三个结果读数（小号，第二优先级）：实际产出指数、失业率、债务存量。

**L2 展开层**：
- 承诺时间轴切换视窗（12 / 24 / 40 季）、切换「仅已签(F+R)」/「含本草案(+R)」/「叠加情景(S)」。
- 四地区一览条（人口、主导部门、本季最紧约束），点击跳 `ui.region`。
- 收支年度化摘要（收入/支出/利息/本金），仅作对账入口。

**区块表**：

| 区块 ID | 内容 | 数据来源（SimCore 结算产物） | 单位与口径标注要求 | 信息类 | 点入台账 |

| `ui.overview.header` | 季度身份、任期目标、审查/选举倒计时 | 回合计数、政治日程 | `第 n 季度 (YkQm)`；倒计时 `n 季` | F | — |

### 3.2 `ui.region` 地区

**这一页回答**：「同一项政策，为什么在四个地区结果不一样？这个地区现在被什么卡住？」
（计划书 §11「地区页面解释差异」）

**L1 首屏必须有**：
1. **行政轮廓地图**（§7），当前图层 + 图例（含分级断点、单位、时间、分母）。
2. 当前选中地区的**约束诊断条**：`Q_actual = min(Q_plan, Q_capacity, Q_labor, Q_energy, Q_materials)` 五项并排，标出哪一项是当期最小值，四个部门各一行。
3. 该地区的**承诺切片**：在建项目、未来四季该地区应付款、该地区设施运行费、队列占用。
4. 邻接与物流条：本地区与相邻地区的边、物流成本、本季跨区流量。

- 部门×约束矩阵（4 部门 × 5 约束）逐格展开算式。

### 3.3 `ui.policy` 政策工作台

**这一页回答**：「我能改什么？改了以后我在未来几季欠下什么？为什么这条现在做不了？」
（计划书 §11「政策工作台组织决策」、§04「政策页必须告诉玩家『为什么不能执行』」）

工作台采用**三栏 + 草案篮**结构，主干是「承诺占用」，不是政策图标墙。

**L1 首屏必须有**：
1. 左栏：12 项政策清单，每项显示 **状态徽章**（可提交 / 有缺口 / 被阻断 / 生效中 / 已退出）+ 最早反馈季数 + 是否含不可逆支出。
2. 中栏：选中政策的**参数编辑区** + 该政策的九字段说明（计划书 §09「目标问题、法定权限、一次性与持续成本、启动条件、生效时滞、作用对象、退出规则、政治反应、可验证的失败路径」）。
3. 中栏下部：**该政策的承诺足迹**（一次性成本曲线、持续运行费、占用哪条队列几季、不可逆部分）。
4. 右栏（在承诺栏左侧、宽 360）：**原因面板 `ui.policy.reasons`**，实时显示当前参数下的全部 HARD / GAP / NOTE 原因（§4.4 文案规则）。

**L2 展开层**：
- 「路线对比」：对同一政策给出基线/不利两条 S 路径（计划书 §10 路线 A/B 的通用化），并排两列，禁止预填赢家标签。
- 「退出预览」：若现在撤回，已发生沉没成本、违约赔偿、残值登记各是多少（`R-COMMIT-3` 的展示位）。
- 政治反应预览：三个集团 + 居民群组分布（不给合成支持率单值，给分布）。

### 3.4 `ui.society` 社会

**这一页回答**：「这一轮发展，谁得到了什么，谁付出了什么？我的留任条件靠什么撑着？」
（计划书 §11「社会页面展示受益受损」、§08「民众不是一个『满意度』」、§18「玩家只看一条综合分数」是风险信号）

**L1 首屏必须有**：
1. **受益/受损分布图 `ui.society.delta`**：36 个群组槽位排成 4×9 网格（行=地区，列=年龄层×技能档），着色为「本季实际可支配收入变化」，同时用图标标出住房负担与服务可及性是否恶化。**禁止合成为一个满意度数字。**
2. **三支柱条 `ui.society.pillars`**：当期生活 / 未来预期 / 程序信任，三条独立，各自给分布（分位数 3 点：P25/P50/P75），不得相加。
3. **留任承诺表 `ui.society.mandate`**：距离下次选举季数、当前席位转换规则下的留任判定输入项、三个利益集团的组织强度与立场（每个集团单列，禁止合并）。
4. **政治承诺台账入口**：已对群组/集团作出的可追溯承诺（如失业保障替代率、公共住房分配规则），及其未来四季财政占用。

### 3.5 `ui.report` 季度报告

**这一页回答**：「上季我预期了什么、实际发生了什么、差在哪、下一步该继续还是撤回？」
（计划书 §11「季度报告串起结果」、§04 环节 06、§13「区分会计贡献、约束诊断与情景预测」）

季度报告是本提案里**唯一允许长滚动**的页面，采用「报告文本 + 可追溯表格」交替的书籍式排版（正文列宽 ≤ 72 中文字符）。

**L1 首屏必须有**：
1. 报告页眉：第 n 季度、报告版本、生成时间、**「本报告使用规则模板生成，无生成式 AI 参与结算」** 常驻声明（计划书 §12 AI 边界）。

## 4. 底部固定区：政策草案 → 预算审查 → 推进季度

这是本提案的**决策闸门**，也是「承诺表」立场最集中的地方。计划书 §11 原文：「确认前显示四季现金预测与新增长期承诺；对会导致资金缺口的方案给出具体原因，不只显示『不可用』。」

### 4.1 状态机

| 状态 | 条件 | 草案篮 | 预算审查按钮 | 推进季度按钮 |
|---|---|---|---|---|
| `S0` 空草案 | 本季未加入任何政策命令 | 空 | 可用 | **禁用**，提示「先打开预算审查」 |
| `S1` 有草案未审查 | 草案 ≥ 1，本季未打开过审查 | n 项 | 可用（高亮） | **禁用**，提示「先打开预算审查」 |
| `S2` 已审查·无阻断·无缺口 | `budget_review_seen_for_turn == current_turn` 且 HARD=0 且 GAP=0 | n 项 | 可用 | **可用** |
| `S3` 已审查·存在 HARD | HARD ≥ 1 | n 项 | 可用 | **禁用**，列出全部 HARD 原因与出口 |
| `S4` 已审查·存在 GAP·未选路径 | GAP ≥ 1 且缺口处理路径未选定 | n 项 | 可用 | **禁用**，打开缺口处理器 |
| `S5` 已审查·存在 GAP·已选路径 | GAP ≥ 1 且每个 GAP 都已绑定一条处理路径 | n 项 | 可用 | **可用**（按钮文案改为「承担缺口并推进 ▸」） |
| `S6` 结算中 | 回合结算进行中 | 锁定 | 禁用 | 禁用，显示 8 环节进度（§5） |
| `S7` 结算完成待复盘 | 结算产出已生成 | 清空 | 可用 | 禁用，按钮变为「查看季度报告 ▸」 |

**关键设计判断**：资金缺口**不是**硬阻断。计划书 §07 要求「无法融资时进入支出排序、延期与重组选择，不允许无提示的负国库余额」—— 所以缺口的正确产品形态是**强制做出一次显式选择**（S4 → S5），而不是把按钮变灰。硬阻断只保留给「规则上不可能」的情形（权限、前置、队列、额度、参数越界）。

`R-COMMIT-2` 的实现：`S0` 也必须先看审查。理由是即使玩家什么都不做，**已签承诺本身**也可能在四季内造成缺口；让玩家在「什么都不做」时也看到这一点，正是本提案的核心。

**四季现金预测表的硬性规格**：
- `R-DOCK-1` 必须恰好 4 列：本季 + 未来 3 季（共四季，与计划书「未来四季」口径一致；口径本身在表头写明「本季 Q07 起算，含本季」）。
- `R-DOCK-2` 行必须分三段：现行承诺 / 本草案新增 / 季末现金，段间用 1px `--stroke-strong` 分隔，段标题必须出现。
- `R-DOCK-3` 每行必须标 F/R/S 分类；含任一 S 行时「季末现金」行整体标 S 并同时提供不利路径（`R-CLASS-1`）。
- `R-DOCK-4` 任一季末现金 < 0 时，该单元格必须同时出现：⚠ 图标 + 「缺口」文字 + 赭色（三通道，§9.3）。
- `R-DOCK-5` 表内每个数字都可点入台账（现行承诺行）或展开算式（本草案行、合计行）。

**新增长期承诺表的硬性规格**：
- `R-DOCK-6` 必须区分「有明确结束季」与「永续」，永续行的「累计名义」列显示 `— (永续)` 而非一个有限数（避免暗示承诺有限）。
- `R-DOCK-7` 必须有「取消代价」列，不可撤的写「不可撤」。
- `R-DOCK-8` 底部三项合计必须同时给出：四季内合计占用、稳态新增（永续部分）、不可逆部分。缺一不渲染。

### 4.3 缺口处理器 `ui.dock.gap_resolver`

当 GAP ≥ 1，推进按钮被禁用并指向缺口处理器。处理器把计划书 §07「支出排序、延期与重组」做成四类可选路径：

| 路径类 | ID | 玩家选择的内容 | 必须显示的代价 |
|---|---|---|---|
| 融资 | `gap.finance` | 发行债券（额度、期限、票息由规则给出，非玩家自定） | 未来各季利息、到期本金季、对 `rail.principal` 的增量 |
| 延期 | `gap.defer` | 把哪些合同付款延后几季 | 投运/结业推迟季数、违约金（按合同条款）、是否触发队列重排 |
| 削减 | `gap.cut` | 把哪些政策规模按比例下调 | 效果量的下降、最早反馈季的推迟、已发生沉没成本不退 |
| 重组 | `gap.restructure` | 触发债务重组（仅在满足触发条件时可选） | 债权人减记额、程序信任下降、后续融资价格上升 |

**规格**：
- `R-GAP-1` 每个 GAP 原因必须**至少**绑定一条路径才能推进；多个 GAP 可共用一条路径（如一次发债解决 G01 与 G02），但绑定关系必须显式显示。
- `R-GAP-2` 处理器必须在选定后**重算并重绘**四季现金预测表，且新表必须显示为「已应用路径」标记；未重绘完成前推进按钮保持禁用。
- `R-GAP-3` 若四类路径在当前状态下全部不可行，处理器必须显示「本季无出口，最早可行季：Qn」及其计算依据，并允许玩家仍然推进（进入欠付/延期状态，由结算器按规则处理，计划书 §13「结算失败应产生欠付、延期或取消状态，而非静默改账」）。此时按钮文案为「在无出口下推进 ▸」，并要求二次确认对话。

### 4.4 原因文案：类别全表与生成规则

#### 4.4.1 生成规则（实现层契约）

1. **模板唯一**：每个原因码恰有 1 条中文模板，存于 `content/reasons_zh_cn.tres`，槽位用**命名占位** `{slot_name}`，禁止位置占位 `{0}`。
2. **槽位只填不算**：所有定量槽位的值由资格检查器/现金预测器**随原因对象一起返回**，UI 层禁止自行计算。静态检查：`ui/` 目录下原因渲染器不得出现算术运算符作用于原因槽位。
3. **五项必填**：每条原因渲染结果必须含 (a) 原因码 (b) 触发实体名 (c) 至少 1 个带单位的数字 (d) 至少 1 个季度标记 `Qn` (e) 至少 1 条出口，或明确的「本季无出口，最早可行季：Qn」。
4. **出口带代价**：每条出口必须形如 `〈动作〉（代价：〈定量或定性后果〉）`。出口数量 1—4 条；> 4 条时按影响幅度取前 4 并显示「其余 n 条 ▸」。
5. **禁用词表**：渲染结果不得包含 `不可用`、`条件不满足`、`无法执行`、`错误`、`请稍后`、`未知原因` 等无槽位词作为**完整句子**。测试断言正则不匹配。
6. **长度上限**：主句 ≤ 60 个汉字；每条出口 ≤ 40 个汉字。超长在模板层就要改写，不在运行时截断。
7. **排序**：`HARD` > `GAP` > `NOTE`；同级按 (最早触发季 asc, |缺口绝对值| desc, 原因码字典序 asc)。
8. **折叠规则**：HARD 与 GAP **永不折叠**，全部展开；NOTE 超过 3 条时折叠余下并显示「其余 n 条提示 ▸」。
9. **证据链**：每条原因携带 `reason_id` + `evidence_ledger` + `evidence_row_ids: PackedInt64Array`；点击「证据」直接打开对应台账并高亮这些行。`evidence_row_ids` 为空的原因禁止渲染（`push_error`）。
10. **本地化**：模板与槽位分离，数字格式化（U 保留 2 位、百分比保留 1 位、人数千分位）由统一格式化器负责，模板内不得出现硬编码单位字符串以外的格式。

## 5. 每回合六环节在界面上的落位与动线

计划书 §04 的六环节，逐一落到具体页面与控件。

| 环节 | 主场 | 玩家看到的控件 | 玩家做的动作 | 到下一环节的操作数 |
|---|---|---|---|---|
| **01 读局势** | `ui.overview` L1 | `ui.overview.risk[0..2]`（≤3 张）+ `ui.overview.timeline` + 承诺栏 `rail.headroom` | 扫读三张卡与时间轴，判断是需求问题、供给瓶颈还是实施受阻 | 点卡上「查原因 ▸」= 1 次 |
| **02 查原因** | 原因链抽屉 `drawer.cause` → 必要时跳 `ui.region` / `ui.society` | 抽屉三级：指标 → 约束诊断（min() 五项）→ 台账行。抽屉底部常驻「相关政策 ▸」 | 沿指标进入机制，读约束诊断与台账，不在菜单中试错 | 点「相关政策 ▸」直达 `ui.policy` 并预选该政策 = 1 次 |
| **03 定方案** | `ui.policy` | 参数编辑区 + `ui.policy.footprint` + `ui.policy.reasons` | 调整参数、选地区与资金来源，加入草案篮；边调边看原因面板实时刷新 | 点底部「预算审查」= 1 次 |
| **04 看预期** | `ui.dock.review` 抽屉 | 四季现金预测 + 新增长期承诺 + 原因面板（含 NOTE）；每条 S 数据给基线/不利 | 辨认不可逆成本与未来运行负担；必要时进缺口处理器选路径 | 点「推进季度 ▸」/「承担缺口并推进 ▸」= 1 次 |
| **05 推进季度** | 确认对话 `ui.dock.confirm` → 结算进度 `ui.dock.progress` | 确认对话列出**本季将发生的全部不可逆动作**（`R-COMMIT-3`）；结算进度显示 §13 八环节，中断时就地展开原因 | 确认；结算中只能观察 | 结算完成自动跳 `ui.report` = 0 次 |
| **06 复盘修正** | `ui.report` | `ui.report.variance` 偏差表 + `ui.report.todo` 四动作（继续/暂停/改期/撤回，撤回旁常驻沉没成本） | 选择继续/暂停/改期/撤回，承担已发生成本 | 点顶栏「总览」回到环节 01 = 1 次 |

**动线总计**：一个完整回合的**最小必要点击数 = 6**（3 张风险卡只看不点时为 4）。这是一个可测指标。

- `AC-LOOP-1` 脚本化走一遍六环节，断言最小点击数 ≤ 6，且每一步的目标控件在当前分辨率下均位于首屏内（A1—A4 四组合）。
- `AC-LOOP-2` 结算中断（欠付/延期/取消/配给）发生时，`ui.dock.progress` 必须就地展开对应原因文案（不得等到报告页才说明）；夹具注入中断，断言进度面板出现原因块。
- `AC-LOOP-3` 「新手前四季」（计划书 §04）逐季脚本：Q01 找到供电瓶颈并提交一项可融资项目；Q02 看到支出先于收益；Q03 查看分配后果；Q04 完成首次年度审查。每季断言所需控件可达且原因文案完整。这是计划书 §17「可理解性」门槛的自动化前置检查。

**「低风险维护可预先设定」的落位**（计划书 §04）：`ui.policy` 左栏底部设「常设指令」区，允许把维护类操作（设施维护拨款、库存补货比例）设为持续指令，每季自动进入草案篮并在预算审查中以独立段落显示（标 `常设` 徽章）。常设指令**不跳过**预算审查，只跳过重复录入。

## 6. 信息设计底线

计划书 §04：「可以隐藏未来冲击，不隐藏当前规则。」

### 6.1 可以隐藏的

| 可隐藏 | 边界 |
|---|---|
| 未来外生冲击的**发生与强度** | 冲击一旦发生，必须在当季报告中完整披露：类型、强度、持续时间、抽样所用随机流（计划书 §07「每次抽样写入日志」）。冲击**类型的存在**（出口需求 / 进口价格 / 外部融资）不可隐藏，开局即在帮助中列明。 |
| 未来季度的事件触发 | 事件模板的**触发条件**属于「当前规则」，必须可查（见 6.2）。 |
| 情景预测的精确未来值 | 因为它本来就不存在精确值；必须以区间/双路径呈现。 |

### 6.2 不可隐藏的「当前规则」（清单化，便于验收）

以下内容必须在游戏内可查，且入口 ≤ 2 次点击：

1. 12 项政策的九字段全文（含失败路径）。
2. `Q_actual = min(...)` 五项约束的定义与各部门的投入系数。
3. 财政两条恒等式（现金与债务，计划书 §07）及其逐项口径。
4. 债券批次规则：期限、票息、到期本金的计算方式。
5. 配给规则：公开优先级或比例配给的具体排序。
6. 队列规则：四条队列的容量、占用与释放条件。
7. 政治规则：预算审查周期（每 4 季）、选举季（Q16/Q32）、席位转换规则全文。
8. 人口规则：出生/死亡/成年/退休/技能转变/迁移的触发与去向。
9. 12 个事件模板的**触发条件**（不披露是否会触发，只披露若触发需满足什么）。
10. 3 类外生冲击的**机制**（不披露本局的抽样结果）。
11. 本局的 `seed` 与 `content_hash`（用于重放与申诉）。
12. 全部原因码表（§4.4.2）与其触发条件。

### 7.1 拓扑（提案，待剧本确认 —— 见 §11 待决问题）

四地区采用**中州为枢纽**的星形 + 一条北原—西岭旁路：

**渲染规格**：
- `R-MAP-1` 用**多边形行政轮廓**（每地区 1 个闭合多边形，顶点数 8—20），2px 描边 `--stroke-strong`，填充由当前图层决定。禁止六边格、禁止瓦片网格、禁止装饰性等高线。

| `A5` | 1366×768 | 125% | 1093×614 | **低于最低支持逻辑分辨率**；显示不支持横幅 + 允许纵向滚动，不崩溃 |

- **Godot 配置**：`display/window/stretch/mode = canvas_items`，`aspect = expand`，基准 1920×1080；系统缩放通过 `DisplayServer.screen_get_scale()` 读取并换算为逻辑分辨率。
- `R-RES-1` 最低支持逻辑分辨率 **1280×720**。A4 必须全绿；A5 允许降级但不得崩溃或丢失控件。
- **验收测量方法**：`tests/ui_layout_matrix.gd` 在 headless 下依次设置五组窗口尺寸，遍历全部 Control：
  1. 断言 `size >= get_combined_minimum_size()`（无挤压）；
  2. 断言 `Label.text_overrun_behavior == TEXT_OVERRUN_NO_TRIMMING`，若某节点必须裁剪，则断言其 `tooltip_text` 包含完整文本；
  3. 断言所有标记为 `first_screen = true` 的节点的全局矩形完全落在视口内（A1—A4）；
  4. 逐页截图落盘，进入人工抽检包。
  通过条件：A1—A4 四组各 0 条违规；A5 仅允许「首屏外」一类违规。

### 9.2 字号与对比度

- **字号**（见 `R-FONT-3`）：`--ui-audit` 全树遍历 → CSV（节点路径, font_size, style_level, 有效缩放后像素）→ 断言 `style_level != M1 → font_size >= 16`。通过 = 0 违规。
- **对比度**：`--ui-audit` 同时导出每个文本节点的 (前景 token, 背景 token) 对 → `tools/contrast_check.py` 计算 WCAG 2.1 对比度 → 断言：文本 ≥ **4.5:1**；`--stroke-strong`、图表轴线、图表标记、焦点环等非文本图形 ≥ **3.0:1**。通过 = 0 违规。**本文件 §8.1 所列数值即为该脚本的输出，必须与脚本结果逐位一致**（CI 比对）。
- 有效值抽检：随机抽 10 张实机截图，用离线取色器取实际渲染像素重算对比度，与 token 计算值偏差 ≤ 0.1（防止半透明叠加导致的隐性失败）。**因此禁止在文本层使用不透明度 < 1.0 的任何值** —— `R-TEXT-1`，静态检查 `modulate.a == 1.0`。

### 9.3 风险的三通道表达

计划书 §11：「风险同时用文字、图标与颜色表达。」

| 通道 | 规格 |
|---|---|
| 文字 | 风险名 + 至少 1 个定量事实（带单位），字号 ≥ 16 |
| 图标 | 14×14 单色图标，来自固定图标集；**每个风险等级的图标 glyph 唯一** |
| 颜色 | 仅 `--ochre`（注意）或 `--rust`（缺口/阻断）；正常态不着色 |

- `R-RISK-1` `cmp.badge_risk` 构造时三个通道任一为空即 `push_error` 并渲染红色占位。
- **验收测量方法**：
  1. 结构断言：遍历所有 `cmp.badge_risk`，断言 `text != ""` 且 `icon != null` 且 `color_token ∈ {--ochre, --rust}`。通过 = 0 违规。
  2. 灰度可判读断言：把渲染结果转灰度后，断言同屏出现的所有风险徽章的 (图标 glyph 码点) 两两不同 —— 即颜色被剥离后仍可区分。通过 = 无重复 glyph。
  3. 人工抽检：使用色觉模拟（protanopia / deuteranopia / tritanopia）处理 10 张截图，5 名评审中至少 4 名能正确说出每个徽章的含义。这一条与计划书 §17「可理解性」门槛合并执行。

### 9.4 图表四标注

计划书 §11：「图表注明时间、单位、价格基期和分母。」

- `R-CHART-1` `cmp.chart` 构造函数强制接收 `ChartMeta { time_range: String, unit: String, price_base: String, denominator: String }`。四项均为必填 `String`；若某项在语义上不适用，必须显式写 `"不适用"`，**不允许空字符串**。
- `R-CHART-2` 四项必须渲染在图表可视区域内（不是仅在悬停提示中），字号 ≥ 16（刻度数字可用 `M1`=13，但四标注本身必须 ≥16）。
- **验收测量方法**：`tests/ui_chart_meta.gd` 实例化项目中全部 `cmp.chart` 子类，断言：(a) 四字段非空；(b) 渲染后四字段文本在图表矩形内；(c) 传入空字符串时 `push_error` 被触发且出现红色占位块。通过 = 全部子类 0 违规。

### 9.5 数字三件套

- `R-NUM-1` 每个 `cmp.value` 必须有：**值 + 单位 + 口径角标**。口径角标可折叠为上标数字（`M1`），悬停/聚焦展开完整口径句（≥16px）。
- 口径句的必备成分：期间（`/季` `/年` `存量@Qn`）、价格基准（`名义` 或 `实际, 基年价`）、分母（比率时）、指数基期（指数时）。
- **验收测量方法**：`--ui-audit` 断言每个 `cmp.value` 的 `unit != ""` 且 `basis_note != ""`；对比率类断言 `basis_note` 含「分母=」；对指数类断言含「基期=」；对货币类断言含「名义」或「实际」。通过 = 0 违规。缺任一项记为 **P1 缺陷**（计划书 §17 缺陷序）。

### 9.6 键盘与焦点

- `R-KEY-1` 五个主页面可用 `1`—`5` 直达；`Tab` 焦点顺序与视觉顺序一致；`Esc` 逐层关闭抽屉；`Enter` 触发主操作但**推进季度按钮不响应 Enter**（防误触不可逆动作）。
- `R-KEY-2` 焦点环 `--focus` 2px 实线 + 2px 外扩，对比度 ≥ 3:1（实测 8.48—10.81，见 §8.1）。
- **验收测量**：`tests/ui_focus_order.gd` 走一遍每页的 Tab 序列，断言焦点矩形的 (y, x) 序列单调；断言推进按钮的 `shortcut` 不含 `Enter`。

## 11. 待决问题（open questions）

1. 地区拓扑（§7.1 的 4 条边与两对非邻接）是 UI 侧提案，**必须由剧本配置确认**；若剧本改为全连通或不同枢纽，地图组件与「物流层」图例断点需同步改。
2. 「未来四季」的口径：本文取「含本季，共 4 列」。计划书 §07 原文为「未来四季到期本金」，可解释为「不含本季的后 4 季」。二义需在数据协议中定死，UI 表头随之改写。
3. 「预算审查每 4 季」与选举 Q16/Q32 的具体季号映射（是 Q04/Q08/… 还是 Q01/Q05/…）会改变 `reason.H01` 的模板与倒计时显示。
4. `rail.headroom` 的告警阈值：本文取「< 0」。是否需要一个 > 0 的预警带（如 < 0.5 U 即黄色注意），需试玩数据决定。
5. `reason.G03`（到期本金集中）、`G07`（稳态运行费失衡）、`N04`（效果集中单一地区）的阈值均为待校准参数，需登记进参数登记表。
6. 「常设指令」（§5 末）是否属于首版范围：它降低重复点击（计划书 §04「低风险维护可以预先设定」），但增加一条命令来源，需与命令/重放协议对齐。
7. 台账 CSV 导出是否进入首版：计划书 §18 要求「保留调试日志导出」，但玩家可见的 CSV 导出可能属于后续功能。
8. 字体授权：Noto Sans SC / Noto Serif SC 的发行包内嵌授权需在 G0 阶段核查（计划书 §14 末段）。
9. 信息类 S 的「基线 / 不利」两路径，其「不利」的定义（第几分位？固定的不利参数集？）会直接决定偏差表的「落点」判定，需与结算合同对齐。
10. `ledger.*` 的 13 个台账 ID 是本文自定的 UI 侧入口名；若数据协议给出不同的台账切分，本文的「点入台账」列需整体重映射。
