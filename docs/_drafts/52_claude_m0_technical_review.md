## 0 结论摘要

1. **方向与时间方案同意**：固定季度内核、年度规划、可中断的批量推进、M0→M4 分段与放行条件都可以落地。
   不变步长我也同意，理由见提案 §2.2。
2. **与提案不同的三处建议**：
   - **建筑用「堆」而不是逐栋实例**。一行代表「地区 × 建筑类型 × 所有者 × 生产方式」，记录等级与产能，作为产能的唯一来源；
     逐栋实例只存在于施工中的项目。这和提案 §5.4「默认合并显示等级」一致，也和《维多利亚3》的建筑等级同构，但省掉数千实例的存储与哈希成本（见 §6 替代方案 B）。
   - **M1 必须先解决价格水平锚**，这是长局的最大技术风险，比数组容量更根本。现行价格上下限是基年价的 0.4—2.5 倍，而无冲击基线 40 季里能源价已到 1.46 倍，400 年必然撞顶截断。
   - **贸易伙伴在 M2 用外部账户下的分账**实现，不新增主体。唯一的外部现金账户保持守恒，伙伴余额是必须对平的备查子账；是否扩主体表留到 M3 战争前再定。

**不需要改的**：
- 八步结算与随机流按季开季。
- 账本日志每季在 S01 清空（`turn_runner.gd:400` 起），内存里只有当季细账，所以「400 年细账撑爆内存」在现行架构下不存在。追溯靠确定性重放加年度检查点：某季细账需要时，从最近的检查点重放出来。
- 存档用「状态 + 命令流」模式，长局可用。

**时间成本（实测外推）**：
- 单季中位数 71 ms：推进一年约 0.3 秒，五年约 1.5 秒，1600 季纯结算约 2 分钟。
- 从第 0 季全程权威重放也约 2 分钟，所以权威重放要改为按年度检查点分段核对（`checkpoints.jsonl` 格式已有）。
- 新增建筑堆与研究块后需要重新测量。

**逐季与批量等价**：
- 批量推进 = 应用层循环调用同一个 `advance_quarter`，每季仍各有一条推进标记（docs/11 命令码 99 的规则不变），所以哈希等价按构造成立。
- 暂停条件：S08 写本季的「需要关注」位掩码（流量，不进存档）。科技完成、需选择的事件、重大建设完工、首次缺口、制度转换、阶段里程碑各占一位。
- 应用层读这个掩码，停在季末边界。
- 最小接口：`JWGame.advance_quarters(n: int, pause_mask: int) -> Dictionary`，返回 `{done, stopped_reason, q}`。
- 验收：同一命令流，逐季推进与批量推进的逐季哈希一致；中途暂停后再存读档、继续，结果也一致。

**价格水平锚（R-PRICE-LONG-01 草案）**：
- 推荐方案 A：
  - 工资调整从「只锚失业率」改为「失业率 + 物价指数目标」双锚，使无冲击长局的名义价格平稳。
  - 价格上下限改成相对滚动价格指数的带宽（例如 ±60%），允许相对价格随技术长期变化。
  - 基年绝对界只保留为溢出护栏，放宽到 0.01—100 倍。
- 方案 B（允许长期通胀，定期改币换算单位）：牵动存档、界面和历史对照，不推荐。
- 验收：无冲击 1600 季，价格指数停留在基年的 0.5—2 倍内，任何价格都不撞护栏，金额不溢出。
- 这一项要反复标定，是 M1 里风险最高的一块。

### Q2 研究、建筑、生产方式怎么映射到四部门与项目队列，如何避免双计

**现状**：
- 生产单元产能（`capital.cell_capacity_active`，16 格）的唯一增量写入点是 S01 的 `commit_pending`（INV-054）。
- 增量来源两个：
  - 企业投资：`add_purchased_capital` 写待投运产能；
  - 项目投运：目前只能写电网、港口、公共服务等产能，**不能写工业产能**。`asset_commissioning.gd:291` 因项目没有部门字段而显式失败。
- 减量：S06 折旧。

**建议：建筑堆作为唯一来源（裁定草案 R-BUILDING-01）**：
- 新状态块 `state.building.*`（SoA，容量 `BUILDING_CAP`，稳定 ID）。
- 每行一个「地区 × 建筑类型 × 所有者 × 生产方式」组合，字段：产能、状况（维护）、首建季、最近改造季。施工中的实例留在项目队列（项目加 `building_type` 与 `target_stack` 字段）。
- 生产单元产能改为派生量：S01 由建筑堆汇总，`cell_capacity[cell] = Σ 属于该 cell 的堆产能`（建筑类型映射到部门）。
- 企业投资与项目投运都改写「堆」的待投运量，不再直接写生产单元。折旧作用于堆。INV-054 的唯一增量写入点随之迁到堆表，生产单元数组退化为汇总视图。
- 这样每一单位产能只在一个堆里出现一次，改造时新旧不会同时计入。

**旧资本映射**：
- 加载期把剧本的生产单元初始产能转成每格一个「既有设施」堆，建筑类型为该部门的传统类型，生产方式为「既有」。
- 逐位守恒：Σ 堆 == 原产能。
- 这个迁移函数新旧剧本共用，并加断言测试。

**生产方式**：
- 现行投入系数按部门给出（`io_table` 的劳动 / 能源 / 材料系数）。
- 方式改变的是「每单位产出的投入」：生产单元的有效系数 = 按堆产能加权的方式系数平均（整数加权、最大余数分配）。生产函数结构不变。
- **改造**是一个项目：
  - 施工期冻结旧堆的相应产能，不产出，也就不双计；
  - 完工后把这部分产能从旧方式堆转到新方式堆，总量守恒；
  - 停工损失与费用在改造预览里列出。

**科技（裁定草案 R-RESEARCH-01）**：
- 新状态块 `state.research.*`：每项科技的状态（未知 / 进行中 / 已掌握）、整数研究进度、当前课题。
- 研究点 = 教育公共服务的实际交付量 × 转化参数 + 研究设施产出，登记为非货币流量 `flow.research.points`。钱仍走工资与采购。
- 科技只解锁资格：建筑类型、生产方式、制度选项的资格位。效果一律经建筑与方式落地。新不变量：研究块不得写任何经济数组。
- 切换课题：各课题进度保留、不清零；切换成本 = 当季研究点损失一定比例（参数）。反复切换不能复制进度。

### Q3 政府项目与企业投资：出资、资产归属、收入

**现有机制**：
- 政府项目：合同分期付款（项目合同支付档）→ 在建工程 → 投运转政府资本。
- 企业投资：企业现金购买制造业资本品 → 产能。
- 政府补助企业投资：P09，支付类型 SUBSIDY。

**M2 可以同时给出三条产业路线**：

| 路线 | 出资 | 资产与收益 | 复用 | 新增 |
|---|---|---|---|---|
| 国有试点工场 | 政府项目合同（分期、延期、取消全部复用） | 投运写入所有者为政府的堆；生产在所在生产单元发生（用该地工人与市场）；营业盈余按堆的产能占比拆分，政府份额每季以财产收入（kind 18，已有）转入国库 | 项目队列、合同支付档、财产收入 | 项目加建筑类型字段；S06 收入分配处增加「盈余按所有者拆分」一条过账规则（裁定草案 R-OWNER-01） |
| 扶持私人投资（共同出资） | 企业自有现金 + 政府资本补助 | 资产与收益归私人堆；政府收益 = 税 | P09 补助档、SUBSIDY | 补助指向具体建筑类型或生产方式 |
| 企业自主投资 | 企业现金 | 私人 | `compute_invest_intent` | 投向从「加总产能」改为按利润率挑选已解锁的建筑类型或方式；界面可视化 |

**不需要新账户类型**：政府资本账户、在建工程、生产单元现金、财产收入、补助、资本品购买都已存在。要新增的只是「所有者」字段和一条过账规则。

**三个家族的切片可行**：
- 灌溉：公共设施，走现有 P07 项目路径。
- 工场：产业设施，国有试点与扶持私人两条路线都能演示。
- 学校：公共服务，同时是研究点来源。

这满足提案 §5.3「M2 至少一种可主动投资并改造的产业设施」。

### Q4 国家延续与政府更替：继承什么，如何防刷，旧模式如何保留

**拆分（裁定草案 R-REGIME-01）**：
- 政治块分成两部分：「政府」（执政方、授权位、任期计数、任期目标）与「国家」（其余全部状态）。
- 战役模式下，选举失利或失去信任触发「政府更替」，不终局：
  - 任期计数加 1；
  - 新执政联盟按集团组织力与支持度的规则确定，不由玩家挑选；
  - 授权位按制度重算。
- 过渡成本：一季内不能通过新政策（新增阻断原因「过渡期」）；行政执行能力一次性下降（参数）。

**继承**：
- 原样保留：债务批次、项目合同、欠付、在建工程、研究进度、政策生效状态与冷却、开关计数、信任与预期。
- 这些本来就不在「政府」字段里，拆分后自然继承，不需要搬运。

**防刷**：
- 更替只由规则结果触发，玩家没有「下台」命令。
- 不重置任何冷却、计数或违约记录。
- 过渡成本非零。
- 预算审查连败计数跨更替保留，按参数逐步衰减，不能靠换届清零。

**旧模式作回归基准**：
- 旧剧本声明 `single_term`，走原来的直接终局路径；新战役声明 `campaign`。两种模式是同一模块里的分支，不复制代码。
- 现有 540 项测试钉在旧剧本上作回归基准；战役测试另立文件。
- 旧剧本内容指纹与样例存档不变。

### Q5 四部门够不够支撑首次技术转型

**首次转型（1600—1800：农业 → 工场 → 机械化）四部门可以诚实表达**：
- 粮食 = 农业品：有库存、有市场、有短缺。
- 机械 = 制造业品：作为资本品或中间投入，资本品购买已有。
- 运输、商贸、教育 = 服务。
- 燃料与动力 = 能源部门产出。

**注意：现行能源产出是按「电力」经电网分给各生产单元的**：有用电系数的部门都受电力分配约束。前工业时代必须：
1. 电力约束按生产方式启用：只有用电系数大于 0 的方式受电网约束，未通电的农庄不会因没有电网停产。
2. 前工业方式把用电系数置 0，动力改走「燃料中间投入」（经市场交易的能源部门产品），或不需外购动力（人力、水力）。

这两点都靠生产方式数据加一处约束开关就能表达，不需要新部门。不会出现「只挂煤图标却无条件增产」：燃料是真的有库存、要购买、要运输、会短缺的能源部门产品。

**什么时候必须加品类**：当玩法需要同一部门内的替代与短缺时，例如煤与木材、机械与工具，大约是 1800 年后的工业化与电气化。

- 最小扩展是把部门从 4 个加到 5—6 个，例如能源拆成燃料与电力，或新增矿产。
- 部门数这个维度贯穿所有按部门的数组、市场、投入产出表和剧本。改动是机械性的，但面很广：估 3—5 工作日，另加重标定。
- 建议 M3 开工前评估，不进 M2。

### Q7 贸易、主动产业投资、有限战争的复用边界，以及危机状态机

**最小贸易（M2，裁定草案 R-TRADE-01）**：
- 在外部账户之下新增 `state.partner.*`，3 个伙伴，字段：出口需求份额、进口供给份额、价格系数、关系值、条约位、信贷额度份额。
- 现金仍只在唯一的外部账户里，伙伴余额是备查子账。新不变量：Σ 伙伴子账变动 == 外部账户现金变动，逐季对平。
- 贸易安排是命令：选伙伴、品类、额度。它改变该伙伴在外部世界模块里的交付容量与需求份额，扩大通道不会凭空创造外国库存或购买力。
- 外交选择：一次贸易协定，降成本或提额度，效果落在上述数值上。
- 这样不复制外部资金，也不动主体表。主体表是 60 个固定编号，要扩的话牵动账户、账本与哈希布局，留到 M3 战争真有必要时再定。

**主动产业投资（M2）**：见 Q3 的三条路线。

**有限战争（M3 边界，裁定草案 R-WAR-01）**：
- 复用：
  - 劳动力群组：动员 = 从劳动年龄群组划出服役人数，作为一类公共雇主，军饷走公职工资支付档。同一人不能同时生产和服役。
  - 政府采购：军需 = 向制造业采购，进库存。
  - 债券：战争融资。
  - 危机状态机：外交危机 → 动员警告 → 战役。
- 新增：
  - 战区状态：每个方向记录前线值、补给储备、兵力、装备。
  - 季度战役结算：确定性公式加专用随机流，重载不能重抽。
  - 伤亡：人口流出，登记死亡原因；另有复员。
  - 赔款：转移支付，记到伙伴子账，双边入账。
  - 设施损坏：堆的状况下降。
- 守恒：服役人数从在业与失业人口里扣出；军需真实采购、真实库存；赔款双边入账；和平不清旧债。
- 边界：M3 不改领土（地区归属不变）。失败后果是赔款、贸易限制或权益损失；「丧失独立」是战争线唯一的终局路径，门槛公开。

**危机状态机（裁定草案 R-CRISIS-01，M1 先做两轨）**：
- 政治块新增：
  - `crisis_stage[4]`：财政 / 供给 / 合法性 / 战争四轨，各自取值 0 无、1 预警、2 危机、3 最后补救窗口；
  - `crisis_since_q[4]`：进入当前级别的季度。
- S08 用既有指标判级：
  - 财政：欠付、预算审查连败、违约；
  - 供给：基本品未满足需求、生活指数；
  - 合法性：支持度、信任、集团立场。
- 每轨独立显示触发事实与仍可采取的行动，不合成一个失败分数。
- 结果：
  - 财政轨道取代现在「重组失败直接终局」，进入窗口后可强制重组或紧缩；
  - 合法性轨道在战役模式下触发政府更替，不终局；
  - 只有「最后窗口届满且条件仍成立」的国家级结果（解体、失去独立）才终局。
- 阈值与窗口长度是参数，按长局基准实测后再标定。
- 旧模式不变。
