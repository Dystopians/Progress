# 界面与信息架构提案 · 诊断台派

> 提案编号：UI-B（三份互不通气的独立提案之一）
> 对应计划书：§04 玩家体验、§07 财政页面必须展示、§11 界面与美术方向、§12 层次禁止事项、§13 结算合同、§17 质量门槛
> 状态：提案。本文件不依赖 `docs/10—14`（变量字典、数据协议、结算合同、待决问题、参数登记）的存在；凡涉及字段名与参数值处，均标注为「本提案建议值」，需与那几份文档对账。
> 语言：界面全部简体中文；代码标识符英文 snake_case。

## 0. 一句话立场

**界面是一台诊断仪，不是一块仪表盘。**

仪表盘只回答「现在是多少」；诊断仪回答「哪里不对 → 凭什么这么说 → 机制上卡在哪一环 → 我能拧哪几颗螺丝」。
本提案把全部五个页面、全部组件、全部文案，统一编排成一条固定排查动线：

```
症状 (Symptom)  →  证据 (Evidence)  →  机制 (Mechanism)  →  干预 (Intervention)
  红色数字          可追溯台账行          约束定位与规则卡        可提交的政策命令
```

这条动线是**硬性结构要求**，不是修辞：凡是能变红、能报警、能被列为「优先风险」的元素，
其详情视图必须依次包含这四段，缺一段即视为缺陷（验收方法见 §8.9）。

计划书 §02「能理解」要求「报告把问题定位到就业、供电、住房或融资，而不是只显示红色数字」——
本提案把这句话实现为：**任何红色数字都不允许是终点，它必须是一条四段动线的入口。**

### 1.3 导航深度约定

界面只有三层深度，超过三层的信息一律用「打开台账」而不是继续嵌套：

- **L1 页面**：五个主页面。
- **L2 区块内展开**（原地展开，不遮挡，不新开窗口）：区块右上角 `▾ 展开` 或按 `Space`。
- **L3 台账抽屉 LedgerDrawer**：从右侧滑入，宽 720 px，可与 L1 并存（左侧页面仍可见）。台账是表格 + 筛选 + 导出，不再往下嵌套。

按 `Esc` 逐层收起；`Ctrl+[` / `Ctrl+]` 在台账抽屉的历史堆栈中前后移动。

## 2. 三类信息的视觉编码（信息设计底线）

计划书 §04：**可以隐藏未来冲击，不隐藏当前规则；报告必须区分「已经发生」「规则推断」「情景预测」。**
本提案把它实现为一套**强制三类制**：界面上任何承载数值的元素，必须且只能属于以下三类之一，并同时携带四个独立编码通道。

### 2.1 三类定义

| 类 | 代码 | 定义（可判定） | 数据来源 |
|---|---|---|---|
| 已经发生 | `actual` | 已完成结算的季度中真实记入台账的值。可在 `ledger.*` 中定位到具体行。 | 结算后状态快照 |
| 规则推断 | `inferred` | 由**当前已生效规则 + 当前状态**确定性外推得到，不含任何随机抽样、不含未提交命令。 | 规则引擎 dry-run |
| 情景预测 | `projected` | 在明确列出的假设集合下的推演，含参数扫动或备选情景。**必带区间与情景名。** | 情景引擎 |

判定边界（避免争议）：
- 只要结果依赖**未来随机抽样**（事件触发、冲击抽样），一律是 `projected`，不得标 `inferred`。
- 只要结果依赖**尚未提交的草案命令**，一律是 `projected`。
- 已结算季度的数据被重新聚合（例如四季合计）仍是 `actual`。
- 「按当前规则、无新命令、无外生冲击」的未来现金预测是 `inferred`（唯一允许的确定性未来）。

### 2.2 四通道视觉编码

| 通道 | `actual` 已经发生 | `inferred` 规则推断 | `projected` 情景预测 |
|---|---|---|---|
| ① 措辞前缀（必须是该行最左的 2–3 个字符） | `实记` | `按规则` | `情景` |
| ② 图标（14×14，实心度递减） | ▰ 实心方块 | ◈ 半填菱形 | ◇ 空心菱形 |
| ③ 左边框（3 px，宽度相同、笔形不同） | 实线 `teal.core` | 虚线 dash 6/4 `line.strong` | 点线 dot 2/4 `warm.text` + 4 px 45° 斜纹底 `rgba(warm.text,0.06)` |
| ④ 数字排版 | 等宽 tabular，字重 600，**永不带 ± 区间** | 等宽 tabular，字重 400，**必带机制角标** `[M-042]` | 等宽 tabular，字重 400，**必带区间 `x.xx–y.yy` + 情景名 + 到第 N 季** |

补充第五道保险（文本层）：
- `inferred` 行末尾必须有一句**可点击的假设摘要**：`假设：无新命令 · 无外生冲击 · 价格按 R-PRICE-01 外推`。
- `projected` 行必须有**情景选择器**并显示当前情景名（首版两个：`基线` / `不利条件`，计划书 §04 环节 04）。

### 2.3 为什么不会互相混淆

| 失效场景 | 仍然可区分的原因 |
|---|---|
| 用户是色盲 / 显示器色彩偏差 | 通道 ①②③④ 全部与色相无关：前缀是汉字、图标是实心度、边框是笔形、排版是字重与 ± 区间 |
| 界面被灰度打印或截图转灰 | 边框笔形（实/虚/点）与图标实心度在灰度下差异 ≥ 3 级；斜纹底提供第三重纹理 |
| 小字号 / 150% 缩放下图标糊 | 汉字前缀 `实记 / 按规则 / 情景` 在任何布局档都不缩小、不省略、不折行（§8.2） |
| 用户只扫数字不读前缀 | `actual` 永远没有 ± 区间，`projected` 永远有 ± 区间——数字本身的**形状**就不同 |
| 同一表格里三类混排 | 禁止：同一张表格不得混排三类。混排时必须拆成三张带标题的分表，或增加一列「类别」并按类别分组排序（验收 §8.9） |
| 开发新增了第四种含糊状态 | 组件层强制：`NumberCell.info_class` 是必填枚举，无默认值；未赋值在 debug 构建下直接抛错 |

### 2.4 「不隐藏当前规则」的实现

- 任何数字获得焦点后按 `R`，从右侧滑出**规则卡 RuleCard**：公式原文 + 当前参数值 + 单位 + 参数来源类型 + 该数字代入公式后的逐项展开。
- 三类外生冲击（出口需求、进口能源/设备价格、外部融资收紧）在 `ledger.rules` 中**列出类别、可能影响的科目、强度与持续期的取值范围**；
  但本局的**是否发生 / 何时发生 / 抽样值**显示为固定文案：`本局未披露`。
  这是「隐藏未来冲击」与「不隐藏当前规则」的分界线，界面必须同时显示两者，不允许把整张冲击规则卡藏起来。

## 3. 数字标注规范（全局）

计划书 §11 要求「图表注明时间、单位、价格基期和分母」。本提案把它提升为**每个数字**的要求。

### 3.1 五元组角标

每个数字元素 `NumberCell` 必须携带元数据五元组，缺任一项在 debug 构建下抛错：

| 字段 | 取值 | 界面呈现 |
|---|---|---|
| `unit` | `U` / `μU` / `人` / `万人` / `%` / `指数` / `单位电力` / `季` | 紧随数字的小号后缀，如 `2.41 U` |
| `measure` | `stock 存量` / `flow 流量` / `index 指数` / `ratio 比率` | 角标色块首字：`存` `流` `指` `比` |
| `period` | `本季` / `年化` / `四季合计` / `累计至今` / `第 N 季` | 角标第二段 |
| `price_base` | `名义` / `基年价(Y1)` / `不适用` | 仅金额与产出类必填；`基年价` 显示为上标 `ᵇ` |
| `denominator` | 比率类必填，如 `劳动力` / `总人口` / `名义GDP` | 角标第三段，比率类不填则抛错 |

**紧凑呈现**：`8.0 %ᵇ` 这类会误导，因此比率的分母**不允许只放在悬浮提示**，必须在同一视觉块内以不小于 14 px 显示，例如：

```
失业率        8.0 %
              比 · 本季 · 分母=劳动力(1,180 万人)
```

### 3.2 数字格式

| 类型 | 格式 | 例 |
|---|---|---|
| 金额 | 2 位小数，千分位半角逗号，右对齐 tabular | `1,204.35 U` |
| 内部记账 | 仅在台账与调试导出中出现 | `1204350000 μU` |
| 人口 | 整数，万人为单位时保留 1 位小数 | `900.0 万人` |
| 比率 | 1 位小数 + 分母说明 | `8.0 %（分母=劳动力）` |
| 指数 | 整数 + 基期说明 | `100（基期=第 1 季）` |
| 差额 | 始终带符号 + 方向字 + 箭头 | `改善 ▲ +0.42 U` / `恶化 ▼ −1.10 U` |
| 区间（仅 `projected`） | `下界–上界` + 情景名 | `1.80–2.60 U（不利条件，到第 11 季）` |

**方向色**：`改善` 用 `teal.core`，`恶化` 用 `ochre.core`，`持平` 用 `text.muted`。
色只是第三通道，方向字与箭头是前两通道（§8.6 验收）。

#### 4.1.5 诊断卡的生成与排序规则（必须可实现）

1. **候选生成**：对下列检测器各跑一遍，每个命中产出一条候选：
   `DET-PROD` 部门产出环比下降超阈值；`DET-BIND` 某部门×地区连续 2 季同一紧约束；
   `DET-CASH` 未来四季现金最低点低于底线；`DET-DEBT` 某季到期本金+票息超该季可用现金；
   `DET-UNEMP` 某地区失业率超阈值或环比上升超阈值；`DET-HOUSE` 某地区住房占用率超阈值；
   `DET-SERV` 某服务实际可用率低于名义容量超阈值；`DET-QUEUE` 项目队列阻滞超 N 季；
   `DET-TRUST` 程序信任环比下降超阈值；`DET-EXT` 外部信用额度余量低于阈值。
   全部阈值登记在 `ledger.rules` 的 `R-DIAG-*`，界面必须可查。
2. **排序键**：`(紧迫度季数 升序, 可干预性 降序, 影响人口权重 降序)`。
   紧迫度季数 = 距离该问题产生不可逆后果的季数（无法计算时记 99）。
   可干预性 = 命中的候选政策数（0 个候选政策的风险仍会显示，但「干预」段改为写明「首版无对应政策工具」，不得留空）。
3. **取前 3 条**。第 4 条起折叠为一行 `另有 N 项低于优先阈值 ▸ 全部诊断`。
4. **无风险时不得留空**：显示阈值说明与规则卡入口（见线框图）。

#### 4.1.6 「不用单一分数」的落实

总览页**不存在**「国力」「综合评分」「满意度」这类合成数字。三支柱是三个**不可互相换算**的量纲（指数 / 比率 / 金额），
并且每个支柱展开后必须显示分布或分项（产出→4 部门；就业→4 地区；财政→4 季路径）。
验收见 §8.8。

#### 4.2.4 约束阶梯 ConstraintLadder（本页最重要的控件）

把 `Q_actual = min(Q_plan, Q_capacity, Q_labor, Q_energy, Q_materials)`（计划书 §06）画成五根**同量纲**横条：

- 五项**必须已换算为同一种产品的可产出数量**，条上标注换算单位；未换算完成的项显示 `不适用（投入系数为 0）` 并置灰，不参与 min（对应计划书「某项投入系数为零时跳过该约束」）。
- 最小的那根加 `◀紧` 标记与 `ochre.core` 描边 + 文字「紧约束」（三通道，§8.6）。
- 下方固定两行：
  - `◈按规则`：**解除当前紧约束后的次紧约束与新产量**，附假设「其余四项不变」。这是「机制定位」的可操作输出。
  - `◇情景`：不利条件情景下的同一推演，带区间。
- 禁止把五项合成一个「瓶颈指数」。

- 低风险维护（如已定的运行费拨付、已批项目的续拨）默认进入**常设项 StandingItems** 折叠区，不占草案篮，但在预算审查中完整列出。

#### 4.5.4 报告的三类信息分区（硬规则）

**小节即分区**：一/二小节的「本季实记」列是 `actual`；三小节整体是 `inferred`；四小节整体是 `projected`。
第二小节是唯一允许把 `actual` 与 `projected` 放在同一行的地方（本质是对账），因此该表**必须有独立的类别列头**：
`上季情景(◇)` 与 `本季实记(▰)` 分列，列头带图标，并且情景列的每个值都是区间、实记列的每个值都不是区间。

| 一 恒等式核对 | `read.fiscal.identity_check(q)`，失败时必须显示为醒目差额而不是隐藏 | actual |

#### 4.5.6 措辞禁令

- 必须使用「**模型中的限制因素**」，禁止使用「原因是」「导致」「因为 X 所以 Y」等因果断言（计划书 §13）。

- 禁止在报告中出现「本季评分」「治理得分」「国力等级」。

### 5.4 原因对象与文案生成规则

#### 5.4.1 原因对象结构

```
Reason {
  code:        枚举（见 5.4.3/5.4.4）
  severity:    BLOCK | WARN | INFO
  quarter:     发生季（整数 1..40+）
  subject_id:  被阻塞的对象（草案 ID / 政策 ID / 项目 ID）
  need:        需求量（带 unit）        # 允许为空的仅 BLK_WINDOW / BLK_AUTHORITY
  avail:       可用量（带 unit）
  gap:         need − avail（带 unit）
  drivers:     占用来源列表（实体 ID + 金额/数量），最多显示 3 条
  exits:       可操作出口列表（≥1 条，每条含一句动作 + 该动作后的 gap 预估）
  links:       相关台账定位 ≥1
}
```

#### 5.4.2 文案模板（四段式，固定顺序）

```
行1（标题）： {severity图标} {code} · 第 {quarter} 季 · {类别中文名}
行2（定量）： {约束对象}{比较语}，需要 {need}{unit}，可用 {avail}{unit}，缺口 {gap}{unit}。
行3（占用）： 主要占用：{drivers[0].name} {drivers[0].amount}{unit}、{drivers[1]...}。
行4（出口）： 出口：① {exit[0].action}（缺口降至 {exit[0].residual_gap}{unit}）
                    ② … ③ …
行5（链接）： ▸{links...}
```

**硬性生成规则**（任一违反即为缺陷）：

| R# | 规则 |
|---|---|
| RG-1 | 禁止输出仅含「不可用」「不满足条件」「资金不足」而无数值的文案。行2 必须含 `need / avail / gap` 三个数字（`BLK_WINDOW`、`BLK_AUTHORITY`、`BLK_DUPLICATE` 三类用「时点/权限/已存在对象」替代三数字，见 5.4.4） |
| RG-2 | 必须含**发生季**。无法确定季时不得生成该 Reason，改由检测器降级为 `INFO` 并说明「时点不可确定的原因：…」 |
| RG-3 | `exits` 至少 1 条。若规则上确实无出口（如权限需等到第 8 季审查），出口写为「等待：第 8 季预算审查窗口」——**等待也是一条出口，但必须写明等到第几季** |
| RG-4 | 每条 exit 必须附 `residual_gap`（执行该出口后的剩余缺口）。无法计算时写「需重新计算 ▸ 试算」并提供一键试算按钮 |
| RG-5 | `drivers` 按金额降序，最多 3 条，其余折叠为「另有 N 项合计 X U」 |
| RG-6 | 多条 Reason 排序键 `(quarter 升序, severity BLOCK>WARN>INFO, gap 降序)`；同类合并时保留最早季那条并在标题追加「（另 N 季同类）」 |
| RG-7 | 同一 Reason 对象在政策工作台目录、政策卡、预算审查三处必须渲染同一文案（同一渲染函数），禁止各写各的 |
| RG-8 | 文案中所有金额沿用 §3.2 格式；所有实体必须可点击定位 |

## 6. 六环节在界面上的落位

计划书 §04 的六个环节，与五个页面的映射关系如下。**动线是单向推荐、非强制**：玩家随时可跳页，但底部固定区按顺序点亮。

| 环节 | 主落位 | 具体区块 | 玩家动作 | 完成判据（界面可检测） | 键盘 |
|---|---|---|---|---|---|
| 01 读局势 | 国家总览 | 三支柱 + 诊断卡 1–3 条 | 阅读，判断是需求问题、供给瓶颈还是实施受阻 | 至少展开 1 张诊断卡的「机制」段 | `1`，`Space` 展开 |
| 02 查原因 | 地区 / 社会 / 台账抽屉 | 约束阶梯、群组矩阵、`ledger.production` `ledger.labor` `ledger.cash` | 沿指标进入机制，而不是在菜单里试错 | 打开过 ≥1 个台账并回到页面 | `2`/`4`，`Enter` 进台账，`Esc` 返回 |
| 03 定方案 | 政策工作台 | 政策目录 + 政策卡编辑器 + 草案篮 | 调整政策：顺序、规模、地区、资金来源 | 草案篮 ≥1 条，或显式声明「本季不提交」 | `3` |
| 04 看预期 | 政策工作台影响预览 + 预算审查 A/B 表 | 「◈按规则」确定性后果 + 「◇情景」基线/不利条件 | 辨认不可逆成本与未来运行负担 | 两个情景都被查看过（切换器被点过），且预算审查被展开过 | `Ctrl+Enter` |
| 05 推进季度 | 底部固定区 ③ | 原因清单 → 确认框 | 处理 BLOCK / 确认 WARN → 结算 | 结算完成，顶栏状态变「已结算(第 N 季)」 | `Ctrl+Shift+Enter` + 二次确认 |
| 06 复盘修正 | 季度报告 | 小节二「偏差」+ 小节五「待办」 | 继续 / 暂停 / 改期 / 撤回，承担已发生成本 | 待办清单被处理或显式跳过 | `5` |

### 6.1 动线引导（不是强制流程）

- 底部固定区左侧有一条 6 段**进度脉络 FlowTrace**，已完成的环节点亮，未完成的保持 `text.muted`：
  `读局势 › 查原因 › 定方案 › 看预期 › 推进 › 复盘`
- 点击任一段直接跳到该环节的主落位。
- **跳过不被阻止**：直接点「推进季度」永远可行（只受 BLOCK 约束），但若「看预期」未点亮，确认框会额外加一行
  `⚠ 你尚未查看本季预算审查。四季现金最低点 0.31 U（第 10 季）。` ——提示而非阻断。
- 新手前四季（计划书 §04）由 FlowTrace 上的一次性气泡引导，第 5 季起自动关闭，可在设置中重开。

### 6.2 结算中的界面行为

结算期间（计划书 §13 的八步）：
- 全界面只读，底部固定区变为八步进度条，每步完成打勾并显示该步「必须记录或检查」的一句摘要。
- **重要中断**（融资失败、欠付、项目取消、冲击触发）出现时，进度条就地展开一张中断卡，说明原因并给出「本季已发生的不可逆成本」，玩家确认后继续（不可回退——计划书 §04「承担已经发生的成本」）。
- 结算结束自动跳转到季度报告页。
- 性能门槛（计划书 §17：中位数 < 0.5 s / P95 < 1 s，参考机 REF-01）若被突破，进度条不隐藏耗时，直接显示实测毫秒数并写入调试日志。

- 组件内边距：卡片 `s5`，表格单元 `s3` 横 / `s2` 纵，区块间 `s5`。
- 行高：表格行 ≥ 32 px（L/M 档 36 px），可点击行 ≥ 36 px。

## 8. 可读性规格与验收测量方法

### 8.1 分辨率与缩放矩阵

| # | 物理分辨率 | 系统缩放 | 逻辑视口 | 布局档 | 允许纵向滚动 | 必测 |
|---|---|---|---|---|---|---|
| V1 | 1920×1080 | 100% | 1920×1080 | L | 否（首屏不滚动） | ✔ 基准 |
| V2 | 1920×1080 | 125% | 1536×864 | M | 否 | ✔ |
| V3 | 1920×1080 | 150% | 1280×720 | S | 部分页面允许 | ✔ |
| V4 | 1366×768 | 100% | 1366×768 | M | 否 | ✔ |
| V5 | 1366×768 | 125% | 1093×614 | S | 允许 | ✔ |
| V6 | 1366×768 | 150% | 911×512 | XS | 允许；底部固定区压缩为单行 | ✔ |

**降级规则（硬性）**：视口变小时，**只允许**减少列数、折叠第二层、启用纵向滚动、把并排改为堆叠。
**禁止**缩小字号、禁止隐藏单位口径角标、禁止隐藏三类信息前缀、禁止隐藏原因清单。

XS 档（V6）的特殊约定：
- 底部固定区压缩为 56 px 单行：`草案3 · 审查⛔1 · [推进季度]`，点击任一段展开全高浮层。
- 国家总览的地区图缩小到 480×280 并允许折叠；诊断卡改为纵向滚动列表。
- 季度报告纸面栏宽降为 720，正文仍为 16 px。

Godot 侧实现约定：`display/window/stretch/mode = canvas_items`，`aspect = expand`，
并用 `ThemeDB` 的 `default_font_size` 随布局档**保持不变**（只改布局，不改字号）。

### 8.2 正文尺寸 ≥ 16 屏幕像素

**要求**：任何布局档下，正文（`body` 与 `body.dense`）的实际屏幕渲染字号 ≥ 16 px。

**验收测量方法（两种都做，都必须通过）**：

1. **导出断言法（每次构建自动跑）**
   在 `--headless` 下运行 `tools/ui_metrics.gd`，遍历全部 Theme 与已注册控件，导出
   `build/ui_metrics.json`：`{node_path, role, font_size_logical, content_scale_factor, font_size_screen}`。
   断言：对 `role ∈ {body, body.dense, number.table, number.kpi, number.hero, title.*}` 的全部条目，
   `font_size_screen = font_size_logical × content_scale_factor ≥ 16`。
   `role == caption` 允许 ≥14，但同时断言该节点存在 `redundant_of` 指向一个 ≥16 px 的节点（即 §7.2 的「不得承载唯一信息」）。
   **通过标准**：0 条违规。

2. **像素测量法（每档手测一次，记录入表）**
   在 V1–V6 六档各截一张 `page.overview` 与 `page.report` 的原始分辨率 PNG（不缩放保存）。
   用 `tools/measure_text.py`（PIL）对预置探针文本（总览页「查看增加值与瓶颈」、报告页「模型中的限制因素」）
   做二值化后求文字包围盒高度，取汉字「查/模」的字面高度。
   **通过标准**：汉字字面高度 ≥ 13 px（对应 16 px 字号的典型汉字字面率 ≈ 0.82–0.88），且 6 档全部通过。
   测量结果记入 `docs/_drafts/ui_readability_log.md`（六档 × 两页 = 12 个数值，含截图文件名）。

### 8.3 首屏不滚动

**要求**：V1、V2、V4 三档下，五个页面的「首屏必须有」内容全部可见，无纵向滚动条。

**验收方法**：`tools/ui_metrics.gd` 导出每页根容器的 `content_height` 与 `viewport_height`。
断言 `content_height ≤ viewport_height`。同时导出「首屏必须有」清单中每个节点的
`global_rect`，断言其完全落在 `Rect2(0, top, w, body_h)` 内。
**通过标准**：3 档 × 5 页 = 15 个组合全部 `content_height ≤ viewport_height` 且 0 个必备节点越界。

### 8.4 对比度 ≥ 4.5:1

**要求**：全部文字前景 × 其允许出现的背景组合 ≥ 4.5:1；非文字 UI 图形（边框、图标、图表线）≥ 3:1。

**验收方法**：
1. 色板定义唯一来源是 `content/theme/palette.json`，含每个 token 的 hex 与 `allowed_on: [bg tokens]`。
2. `tools/check_contrast.py` 读取该 json，按 WCAG 2.1 相对亮度公式计算**全部** `(token × allowed_on)` 组合，
   输出表格并对 `kind == text` 断言 ≥ 4.5、对 `kind == graphic` 断言 ≥ 3.0、对 `kind == decorative` 仅登记不断言。
3. 静态检查：`kind == decorative` 的 token（目前只有 `line.hair`）在 `ui/` 下的每一处使用，
   必须同时存在斑马底或 ≥32 px 行高（人工复核清单 + 用法计数上限）。
4. 截图复核：对 V1 档每页截图，用 `tools/sample_contrast.py` 在 20 个随机文字像素点取前景/背景实际渲染色，
   计算对比度。**通过标准**：断言 0 违规；截图抽样 100 个点中 ≥ 4.5 的比例为 100%（抗锯齿边缘像素排除，取字心像素）。

本文件 §7.1 表中的粗体数值即该脚本的当前输出，色板变更后必须重跑并更新本表。

### 8.5 赭色克制

**要求**：赭色只用于需要注意的状态。

**验收方法**：对每页在「无任何 WARN/BLOCK」的构造状态下截图（用测试存档构造），
`tools/count_ochre.py` 统计像素颜色落在 `ochre.core`/`ochre.hot` 的 ΔE < 5 邻域内的像素数。
**通过标准**：该数 ÷ 总像素 ≤ 0.1%（容许图例中 `series.4` 的色块，其面积应 < 0.1%）。
有警告状态下无上限，但需人工确认赭色出现位置全部对应 `RiskBadge` 或 `ReasonList`。

### 8.6 风险三通道（文字 + 图标 + 颜色）

**要求**：风险不得只靠颜色表达。

**验收方法**：
1. **自动**：遍历场景树全部 `RiskBadge` 与所有带 `severity` 属性的节点，断言
   `text != "" && icon_id != "" && color_token != ""`，且 `text` 中含明确等级词
   （`提示` / `需要注意` / `需立即处理`）。**通过标准**：0 违规。
2. **灰度法**：对含三级风险的构造截图，用 `tools/to_grayscale.py` 转灰度后由 2 名评审独立判读三级风险的等级，
   **通过标准**：2 人判读结果与真值全部一致。
3. **色觉模拟**：用 `tools/simulate_cvd.py`（红绿色盲 protanopia/deuteranopia、蓝黄 tritanopia 三种）转换同一批截图，
   **通过标准**：三种模拟下 `ochre.core` 与 `teal.core` 的灰度亮度差 ≥ 20/255，且图标形状可区分。

### 8.7 图表四标注

**要求**：图表必须标注时间、单位、价格基期和分母。

**验收方法**：
1. `ChartFrame` 的 `chart_meta` 四字段为必填；debug 构建下缺项 `push_error` 并在图表位置渲染红底占位「图表元数据缺失：{字段}」。
2. `tools/ui_metrics.gd` 导出全部 `ChartFrame` 实例的 `chart_meta`，断言四字段非空
   （`price_base` 与 `denominator` 允许取值 `不适用`，但必须显式写「不适用」而非空串）。
3. 视觉断言：截图中每个图表下方存在四行标注文本（OCR 或固定坐标取样）。
**通过标准**：全部图表 0 违规，且 V1 档截图中四行标注可见（未被裁切）。

分类系列还须满足 §7.1.7 的 C-1/C-2/C-3：
- C-1/C-2 由 `tools/check_contrast.py` 的 `--series` 模式断言（对画布 ≥3.0；两两亮度比 ≥1.45）。
- C-3 断言每个系列的 `stroke_dash` **与** `fill_pattern` 均两两不同，且图例项同时渲染色块、笔形样段与图案样块三者。
- 灰度复核：图表截图转灰度后，4 条系列线仍可按深浅排序（2 名评审独立判读，排序与真值一致）。

### 8.8 「不用单一综合分数」

**验收方法**：
1. 静态检查：仓库中不得存在 `ScoreGauge`、不得存在名为 `*_score`、`*_rating`、`overall_*` 的读模型字段
   （白名单：`support_score` 之类若确需存在，必须同时提供 `*_distribution` 字段，否则报错）。
2. 结构检查：遍历界面中每一个被标为 `is_summary = true` 的 `NumberCell`，
   断言其父容器内存在 `DistributionBar` 或 `GroupMatrix` 或分项表格节点。
**通过标准**：0 违规。

### 8.9 诊断动线与信息类完整性

| 检查 | 方法 | 通过标准 |
|---|---|---|
| 四段动线 | 遍历全部 `DiagnosticCard`，断言 症状/证据/机制/干预 四段 children 非空 | 0 违规 |
| 红数字非终点 | 遍历全部 `severity != INFO` 的 `NumberCell`，断言 `ledger_link != null` 或存在关联 `DiagnosticCard` | 0 违规 |
| 三类不混排 | 遍历全部表格，若同表含 ≥2 种 `info_class`，断言存在「类别」列或分组标题 | 0 违规 |
| 预测必带区间 | 遍历 `info_class == projected` 的 `NumberCell`，断言 `range != null && scenario_name != "" && horizon_quarter != null` | 0 违规 |
| 实记不带区间 | 遍历 `info_class == actual`，断言 `range == null` | 0 违规 |
| 推断必带机制 | 遍历 `info_class == inferred`，断言 `mechanism_id != ""` 且 `assumption_text != ""` | 0 违规 |
| 原因不空洞 | 对 22 个原因类别各构造 1 个触发用例，断言生成文案含 ≥2 个数字 + 1 个季度 + ≥1 条出口，且不含子串「不可用」作为唯一说明 | 22/22 通过 |
| 规则可达 | 随机抽取每页 10 个数字，按 `R` 后断言 `RuleCard` 打开且五段非空 | 50/50 通过 |

### 8.10 可理解性（对应计划书 §17）

5 名首次体验者中至少 4 名完成前 4 季并能解释一项政策未按预期生效的原因。
界面侧的记录字段：首次有效决策耗时、打开过的台账数、被忽视的 `WARN`、无法理解的指标（逐条记名）、重复点击次数。
界面必须提供 `--ui-telemetry-local` 开关把上述计数写入本地日志（无网络、无默认遥测，符合计划书 §18）。

## 9. 地区图

### 9.1 形式

- **清楚的行政轮廓**：4 个手绘感行政多边形（每区 12–24 个顶点），描边 2 px `line.strong`，区间留 6 px 缝隙。
- **禁止密集六边格**（计划书 §11）；禁止瓦片网格；禁止 3D 倾斜。
- 每区固定标签：区名 + 人口 + 当前图层值 + 单位。
- 选中区 3 px `teal.core` 描边 + 内侧 1 px `bg.abyss` 分隔（保证在任何图层填色下都可见）。
- 图幅在 L 档为 960×520（总览页）/ 620×420（地区页）；XS 档 480×280。

### 9.2 四地区拓扑（本提案建议值，需与剧本配置对账）

| 边 | 两端 | 建议物流成本系数 | 说明 |
|---|---|---|---|
| e1 | 北原 ↔ 中州 | 1.0（基准） | 主干通道，粮食进城 |
| e2 | 北原 ↔ 西岭 | 1.4 | 山地通道 |
| e3 | 中州 ↔ 西岭 | 1.2 | 能源进中州 |

这构成一条可被玩家发现的结构性约束（能源运输受中州通道约束），也让「中州枢纽拥堵」成为可能的机制故事。

> 界面侧的硬要求是：(a) 邻接关系必须在图上以边的形式**可见**；(b) 每条边必须显示成本系数与其基准定义；
> (c) 成本系数是无量纲相对值，图例必须写明「基准 e4/e1 = 1.0」的选择。

## 10. 禁止事项（界面侧）

| # | 禁止 | 依据 | 实现约束 | 验收 |

## 12. 本提案的自我限制

- 本文件规定**界面与信息架构**，不规定模拟规则、数值与参数。凡出现的具体数字（如 `2.41 U`、物流系数 `0.8`）
  均为**线框图占位与格式示例**，不是参数提案。
- 读模型字段名（`read.*`）与台账 ID（`ledger.*`）为本提案建议命名，需与数据协议文档统一后才可编码。
- 本文件不引用、不假设 `docs/10—14` 的内容；如与那几份文件冲突，以那几份为准，并回改本文件。
