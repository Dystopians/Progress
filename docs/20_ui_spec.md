## 0. 本文件的地位与边界

### 0.1 本文件规定什么

1. 五个主页面、四个覆盖层、底部固定区的**结构、区块、首屏清单、状态机**。
2. **三类信息**（已经发生 / 规则推断 / 情景预测）的编码与判定规则。
3. **原因对象**（为什么不能执行 / 为什么会有缺口）的结构、文案生成规则与覆盖契约。
4. **组件清单、Control 树、实现约束、交付分级与工时**。
5. **验收清单**：每条可读性与信息设计要求 → 怎么测量 → 通过标准。

### 0.2 本文件不规定什么

- 不定义变量字典、数据协议、结算合同、待决问题登记、参数登记（`docs/10`—`docs/14`，另有作者并行撰写）。
- 不定义任何模拟规则、参数值、剧本数值。文中出现的一切数字（`2.41 U`、`8.4 %`、物流系数等）**是排版夹具**，不是参数提案。
- 不定义地区拓扑与物流成本系数。界面从剧本配置读取，见 §7.2.5。

### 0.3 命名的归属方向（重要）

本文件使用的 `ldg.*`（台账）、`reason.*`（原因码）、`read.*`（读模型）三个命名空间，**一律是占位别名**。

- 界面**不**约束 SimCore 的命名。真实 ID 由数据协议与结算合同决定。
- 包含方向是：**界面必须为 SimCore 能返回的每一个 `reject_code` 提供一张原因卡**（§9.5 覆盖契约），而不是反过来要求 SimCore 的码集合是本文表格的子集。
- 别名到真实 ID 的映射集中在**唯一一个文件** `content/ui/alias_map.json`。docs/10—14 落地后，只改这一个文件，不改任何场景、脚本或本文件的示例。
- 验收 AC-31 断言：`res://ui/` 下不得出现任何 `ldg.` / `reason.` / `read.` 字面量，一律经 `JwAlias.resolve()` 解析。

> 特别注意：并行撰写的骨干文档草案中，`L-xxx` 形式已被用于**失败路径码**（如 `L-FUEL`、`L-DELIVERY`）。
> 因此本文件的台账别名使用 `ldg.` 前缀，不使用 `L-`，避免反向占用。

## 3. 三类信息编码（信息设计底线）

> 计划书 §04：**可以隐藏未来冲击，不隐藏当前规则；报告必须区分「已经发生」「规则推断」和「情景预测」。**
> 计划书 §13 第 08 步：**区分会计贡献、约束诊断与情景预测。**

### 3.1 枚举与判定

```gdscript
enum JwInfoClass { ACTUAL, DERIVED, PROJECTED }   # 无默认值，必填
```

| 类 | 枚举 | 定义（可判定） | 数据来源 |
|---|---|---|---|
| 已经发生 | `ACTUAL` | 已完成结算的季度中真实记入台账的值，能定位到具体行，且同类行求和残差为 0 | 结算后状态快照 |
| 规则推断 | `DERIVED` | 由**已结算状态**按**公开规则**确定性算出，不依赖任何未来经济结果、未提交草案或随机抽样 | 规则引擎 dry-run |
| 情景预测 | `PROJECTED` | 依赖未来经济结果、未提交草案、行为假设或随机抽样 | 情景引擎，必带区间与情景名 |

### 3.2 判定瀑布（逐单元格，不逐表）

按顺序求值，命中即停：

1. 该值已由某个**已结算季度**的台账行记录，且可对账 → `ACTUAL`。
2. 否则，该值由已结算状态按公开规则算出，**且不依赖任何未来经济结果、未提交草案与随机抽样** → `DERIVED`。
3. 否则 → `PROJECTED`，**必须给区间与情景名**。

**显式映射表**（消除争议，实现者按此表判，不再讨论）：

| 内容 | 类 |
|---|---|
| 会计贡献分解（增加值、支出构成、双边交易） | `ACTUAL` |
| 约束诊断（`Q_actual = min(...)` 的五项与紧约束判定） | `DERIVED` |
| 未来到期本金、逐批次票息、已签合同按进度的应付款、已建成设施运行费 | `DERIVED` |
| 解除紧约束后的次紧约束与新产量（假设其余项不变） | `DERIVED` |
| 未来税收、出口收入、价格、就业、GDP、留任前景 | `PROJECTED` |
| 任何含**本季未提交草案**的推演（含预算审查 A 表的「含草案」列组） | `PROJECTED` |
| 任何含外生冲击抽样的推演 | `PROJECTED` |

**单元格规则（硬）**：同一行、同一张表可以含多类；**但单个单元格的 `info_class` 必须是单值**，禁止「实/预」这类复合取值。

### 3.3 四通道编码

| 通道 | `ACTUAL` | `DERIVED` | `PROJECTED` |
|---|---|---|---|
| ① 徽章字（表格、单元格、角标位） | `实` | `算` | `预` |
| ① 词前缀（散文行、块级行首，该行最左） | `实记 ·` | `推算 ·` | `预测 ·` |
| ② 图标（14×14，项目自带图标集，实心度递减） | `icon.class_actual` 实心方 | `icon.class_derived` 半填菱 | `icon.class_projected` 空心菱 |
| ③ 左标尺（3 lu 宽，`StyleBoxTexture` 垂直平铺三张纹理之一） | 实线 | 短划 6/3 | 点线 2/4 |
| ④ 数字形态 | **永不带区间**；等宽，字重 600 | **货币与数量必单值**；等宽，字重 400；必带机制角标 `[M-xxx]`。**时滞与季数允许规则给定的区间**（如「最早反馈 4–8 季」），此时必须紧跟来源标注 `（区间来源：政策定义）` | **必带 `〔下界–上界〕` + 情景名 + 「到第 N 季」**；禁止单点数。分布型输出以 ≥3 分位点表示，视为满足「非单值」 |

**通道④ 的正则（可 lint）**：

- `PROJECTED` 的主数值文本必须匹配 `^〔-?[\d,]+(\.\d+)?\s*–\s*-?[\d,]+(\.\d+)?〕$`。
- `ACTUAL` 的主数值文本必须**不**匹配 `[〔〕–±]`。
- `DERIVED` 的货币/数量主数值文本必须不匹配 `[〔〕]`。

**通道③ 的实现**：三张 3×12 px 的 9-patch 纹理随发行包分发，用 `StyleBoxTexture` 垂直平铺。
Godot 的 `draw_dashed_line()` 只接受单一 dash 长度、实段与空段等长，做不出 6/3 与 2/4；`StyleBoxFlat` 不支持虚线边框。
纹理方案是唯一可实现路径，成本为三张图片。**若实机发现平铺接缝问题，降级形态为统一 3 lu 实线，区分交给通道①②④**（记为 T1 风险，§14）。

### 3.4 为什么不会互相混淆

| 失效场景 | 仍然可区分的原因 |
|---|---|
| 色盲 / 显示器偏色 | ①②③④ 全部与色相无关：前缀是汉字、图标是实心度、标尺是笔形、形态是区间的有无 |
| 灰度打印或截图转灰 | 标尺笔形与图标实心度在灰度下差异 ≥3 级 |
| 150% 缩放 | 汉字前缀与徽章字在任何布局档都不缩小、不省略、不折行（§15 B-11） |
| 玩家只扫数字不读前缀 | `ACTUAL` 永远没有区间，`PROJECTED` 永远有 `〔 〕`——**数字的形状本身**就不同 |
| 同表混排 | 允许混排，但必须有「类」列或按类分组并加分组标题（AC-07） |
| 实现者漏标 | `JwNumberCell.info_class` 是**无默认值的必填枚举**；debug 构建下未赋值直接 `push_error` 并渲染红底占位 |
| 玩家不知道实/算/预是什么 | 顶栏常驻 `%ClassLegendButton`（§7.0），首次出现时弹一次性定义卡（§10.4） |

### 3.5 引用码与规则号（三条硬规则）

1. **裸引用码只出现在 `ACTUAL`**。看到不带前缀的 `ldg.xxx#Qnn.row`，一定是既成事实。
2. **`DERIVED` 的引用码必须整体位于 `输入：` 前缀之后**，并且同一行必须出现字面插入符规则号 `^R-xxx`。
   例：`推算 · 海岬制造本季紧约束为电力  ^R-PROD-03  输入：ldg.constraint#Q07.014、ldg.service#Q07.031`
3. **`PROJECTED` 不得出现任何台账引用码**。只允许 `情景：SC-base` 与 `假设 N 条 ▾`。

> 规则号写作**字面插入符 + 规则 ID**（`^R-PROD-03`），**不使用排版上标**——Godot 的 `RichTextLabel` 没有上标标签。

### 3.6 「不隐藏当前规则」的实现

- 任何 `JwNumberCell` 在获得**焦点或悬停**时，在数字右上角渲染 12×12 lu 的规则角标 `icon.rule`；
  **点击角标 = 打开规则卡**；**点击数字本体 = 打开台账**。键盘等价：`Alt+R` 打开规则卡，`Enter` 打开台账。
  （不得只提供键盘路径——鼠标玩家同样必须能达到规则，AC-22 分键盘/鼠标两组断言。）
- 规则卡 `JwRuleCard` 五段：公式原文 / 当前参数值与单位 / 参数来源类型 / 该数字代入公式的逐项展开 / 生效范围。
- 三类外生冲击：在 `ldg.rule` 中**必须列出**类别、可能影响的科目、强度与持续期的取值范围；
  本局的「是否发生 / 何时发生 / 抽样值」显示固定文案 `本局未披露`。
  这是「隐藏未来冲击」与「不隐藏当前规则」的分界线：**规则卡整张不得隐藏，只隐藏抽样值**。

| `value_uU: int` | 内部整数（1 U = 1_000_000 μU） | 金额类必填 |
| `unit: StringName` | `U` / `μU` / `人` / `万人` / `%` / `指数` / `单位电力` / `季` / 部门产出单位 | 必填 |
| `measure` | `存` 存量 / `流` 流量 / `指` 指数 / `比` 比率 | 必填 |
| `period` | `本季` / `年化` / `四季合计` / `累计至今` / `第 N 季` / `期末` / `期初` | 必填 |
| `price_base` | `名义` / `基年价(Y1)` / `不适用` | 金额与产出类必填 |
| `denominator` | 比率类必填，如 `劳动力(1,180 万人)` | `measure == 比` 时必填 |
| `index_base` | 指数类必填，如 `基期=第 1 季` | `measure == 指` 时必填 |
| `info_class` | §3 枚举 | 必填，无默认值 |
| `citation` | 引用码；`ACTUAL` 必填 | 见 §3.5 |
| `rule_id` | `DERIVED` 必填 | 见 §3.5 |
| `scenario` / `range_lo` / `range_hi` / `horizon_q` | `PROJECTED` 必填 | 见 §3.3 |
| `evidence_path: Array[StringName]` | 到台账行的交互路径，长度 ≤3，元素为目标控件唯一名 | `citation` 非空时必填 |

### 4.2 口径的承载位置规则

五元组不必逐格重复。**承载位置按上下文判定**：

| 上下文 | 口径由谁承载 | 单元格内保留 |
|---|---|---|
| 独立展示的数字（支柱、诊断卡、风险卡、承诺摘要、KPI） | 数字自身的角标行，紧贴其下，字号 ≥14 lu 且带 `redundant_of` | 全部五元组 |
| 表格单元格 | **列头 + 表脚**；单元格设 `meta_source` 指向列头节点 | 数值 + 徽章字 |
| 图表 | `JwChartFrame` 的四行标注（§4.4） | 数值标签 |

`JwNumberCell.meta_source` 为空且不在表格上下文中时，debug 构建 `push_error`。
AC-13 断言：**每个数字的五元组可从单元格本身或其 `meta_source` 解析到**。

比率的分母**不允许只放在悬浮提示**，必须在同一视觉块内（列头或角标行）以 ≥14 lu 呈现，并且同屏给出分母的绝对数。

### 4.3 数字的两种呈现形态

Godot 的 `RichTextLabel` 内联 span **不是 Control**，挂不了元数据，`--ui-audit` 遍历看不见。因此：

| 形态 | 用于 | 元数据挂在 | 受审计 |
|---|---|---|---|
| **形态 A**：`JwNumberCell`（独立 Control） | 表格单元格、卡片单值、KPI、承诺摘要 | Control 自身 | 是（AC-13、AC-14） |
| **形态 B**：句内嵌数字（`RichTextLabel` 内联） | 原因文案、报告正文、说明句 | 所属**数据对象**的 `slots: Array[JwValueSlot]`，每槽含 value/unit/info_class/citation/horizon_q | 是，但审计对象是**数据对象**，不是 Control |

**硬规则**：形态 B 的数字**不得是该数字通往台账的唯一入口**。同一个数字必须在同屏的某张表或某个卡片里有一个形态 A 的入口。
（`RichTextLabel` 的 `[hint]` 支持 span 级悬停提示，但不支持 span 级键盘焦点。）
AC-15 断言：每个 `JwValueSlot` 都能在同屏找到 `citation` 相同的形态 A 节点。

### 4.4 图表四标注

```gdscript
class_name JwChartMeta extends Resource
@export var time_range: String = ""     # 例 "第 04–07 季"
@export var unit: String = ""           # 例 "U/季"
@export var price_base: String = ""     # 例 "基年价(Y1)" 或 "不适用"
@export var denominator: String = ""    # 例 "分母=劳动力" 或 "不适用"
```

- `JwChartFrame` 用 `@export var meta: JwChartMeta`（**不是构造函数参数**——`PackedScene.instantiate()` 不传参）。
- `_ready()` 断言四项非空，缺项 `push_error` 并渲染红底占位「图表元数据缺失：{字段}」。
- `@tool` 下实现 `_get_configuration_warnings()`，使违规在**编辑器里**就报错。
- 「不适用」必须显式写出，空串即违规。
- 方法名为 `get_chart_meta() -> JwChartMeta`。**不得命名为 `get_meta()`**——那是 `Object` 的原生方法，签名不同，声明即编译错误。

### 4.5 数字格式

| 类型 | 格式 | 例 |
|---|---|---|
| 金额 | 2 位小数，千分位半角逗号，右对齐等宽 | `1,204.35 U` |
| 内部记账 | 仅在台账、调试导出与 `ACTUAL` 单元格的聚焦提示中出现 | `1204350000 μU` |
| 人口 | 整数；以万人为单位时保留 1 位小数 | `900.0 万人` |
| 比率 | 1 位小数 + 分母 | `8.0 %（分母=劳动力）` |
| 指数 | 整数 + 基期 | `100（基期=第 1 季）` |
| 差额 | 符号 + 方向字 + 箭头（三通道） | `改善 ▲ +0.42 U` / `恶化 ▼ −1.10 U` |
| 区间（仅 `PROJECTED`） | `〔下界–上界〕` + 情景名 + 到第 N 季 | `〔1.80–2.60〕U（不利条件，到第 11 季）` |

方向色只是第三通道；方向字与箭头是前两通道。负数用前置 `−` 并同时用次级文字色，不靠颜色单独表达。

## 5. 全局外壳、缩放与断点

### 5.1 窗口与外壳

- **默认窗口模式：无边框全屏**（`DisplayServer.WINDOW_MODE_FULLSCREEN`），设置项可切窗口模式。
  理由：窗口模式下 1920×1080 显示器的客户区约 1920×1008（标题栏 + 任务栏），任何按 1080 计算的首屏保证都会假失败。
- 首屏高度**不得写成常量**，一律实测：
  ```gdscript
  var logical := Vector2(get_window().size) / get_window().content_scale_factor
  var body_h  := logical.y - TOPBAR_H - TABS_H - dock_height_for(logical.y)
  ```
- 窗口最小尺寸：`min_size = Vector2i(1280, 720) * ui_scale`。低于最低逻辑尺寸时（只可能出现在 1366×768 叠加 125%/150% 的降级档），
  显示**不可关闭**的提示条「当前显示设置低于最低支持尺寸 1280×720 逻辑单位；界面允许纵向滚动」，并允许主区纵向滚动。

| 外壳元素 | 高度 (lu) | 规则 |
|---|---|---|
| `%TopBar` | 56 | 国名 + 季度定位 + 国库现金 + 债务 + 三类信息图例入口 + 规则手册入口 + 存档指示 + 结算状态 |
| `%PageTabs` | 40 | 五页固定顺序，任何时候可切换（不阻断） |
| `%Body` | 实测 | 页面工作区，「首屏」= 此矩形 |
| `%ActionDock` | 逻辑高 ≥900 → 104；<900 → 80 | 五页共用同一实例，永不隐藏 |

顶栏固定规则：

| 元素 | 规则 |
|---|---|
| 季度计数 | `第 NN 季（第 k 年 第 m 季）`，**显示季号 NN = 内部 `q` + 1**，NN ∈ [1,40]（内部 `q ∈ [0,39]`）。界面**永不显示内部 `q`**，只在台账、调试导出与 `content_hash` 旁显示。选举季与预算审查季加徽标（§19） |
| 国库现金 / 债务 | `JwNumberCell`，单位 U，2 位小数，点击进 `ldg.cash` / `ldg.debt` |
| 债务旁 | **不得出现债务/GDP 单一比率作为唯一偿付能力指示**（§07）。该比率只在年度审查中出现一次，且必须紧跟免责句（§10.1） |
| `%ClassLegendButton` | **常驻**。点击弹出三类信息图例（三行：徽章字 + 图标 + 标尺 + 一句定义 + 一个本局实例）。W-mid 档仍常驻，不得只藏在抽屉里 |
| 结算状态 | 三态 `未结算 / 结算中 / 已结算（第 N 季）`；结算中全界面只读 |

### 5.2 缩放的落地机制（唯一入口）

```
项目设置：
  display/window/stretch/mode   = disabled
  display/window/stretch/aspect = ignore
运行时：
  get_window().content_scale_factor = ui_scale
```

- **1 lu 渲染为 `ui_scale` 个物理像素。** Theme 内的全部字号、StyleBox 边距、容器 separation 一律按 lu 字面值编写，不做二次换算。
- `ui_scale` 的确定顺序（前者优先）：
  1. 命令行 `--ui-scale=1.00|1.25|1.50`（测试与验收一律走这条，不依赖系统探测）；
  2. 设置项中的显式覆盖；
  3. `snap({1.00, 1.25, 1.50}, DisplayServer.screen_get_dpi(DisplayServer.window_get_current_screen()) / 96.0)`，并 `clamp` 到 [1.00, 1.50]。
- **禁止使用 `DisplayServer.screen_get_scale()`**：它在 Windows 上恒返回 1.0（本项目主开发环境为 Windows 11）。
  静态检查 AC-30 断言该方法在 `res://` 下 0 次调用。
- 启动时把实测 DPI、推导值、最终 `ui_scale` 写入调试日志；T04 工程骨架任务须在 REF-01 上实测三档 DPI 的返回值并记入 `docs/ENGINE.md`。

**目标配置（四配置必测）**

| 配置 | 物理 | `ui_scale` | 逻辑视口 | 宽档 | 底部固定区 | 主区高 (lu) | 正文物理像素 |
|---|---|---|---|---|---|---|---|
| C1 | 1920×1080 | 1.00 | 1920×1080 | W-wide | 104 | 880 | 16 |
| C2 | 1366×768 | 1.00 | 1366×768 | W-mid | 80 | 592 | 16 |
| C3 | 1920×1080 | 1.25 | 1536×864 | W-mid | 80 | 688 | 20 |
| C4 | 1920×1080 | 1.50 | 1280×720 | W-mid | 80 | 544 | 24 |

**降级档（不必测首屏，必须测动线）**：C5 = 1366×768 @125%（1093×614）、C6 = 1366×768 @150%（911×512）。
要求：显示不支持提示条、允许纵向滚动、不崩溃、正文仍 ≥16 物理像素、六环节动线仍可完成（AC-03b）。

### 5.3 断点与降级

| 宽档 | 逻辑宽 | 布局 |
|---|---|---|
| `W-wide` | ≥ 1600 | 主区可两栏；台账抽屉（640 lu）与页面并存 |
| `W-mid` | 1280–1599 | 主区单栏或窄两栏；**台账抽屉转全屏模态**（`Esc` 返回并恢复原滚动位置） |
| 不支持 | < 1280 | 提示条 + 纵向滚动 |

| 高档 | 主区高 | 首屏清单 |
|---|---|---|
| `H-tall` | ≥ 800 | 完整清单（附录 B 列 L） |
| `H-mid` | 640–799 | 中清单（列 M） |
| `H-short` | < 640 | 短清单（列 S） |

**降级规则（硬）**：视口变小时**只允许**：减少并排列数、把并排改为堆叠、折叠第二层、缩小地图/图表的绘图面积、启用纵向滚动。
**禁止**：缩小正文字号、隐藏单位口径角标、隐藏三类信息前缀或徽章字、隐藏原因清单、隐藏底部固定区、隐藏承诺摘要的告警态。

### 5.4 导航深度

只有三层。超过三层的信息一律用「打开台账」，不再嵌套。

- **L1 页面**：五个主页面，页签常驻，切换 1 次点击。
- **L2 区块内展开**：原地展开，不遮挡，不新开窗口。触发：区块标题右侧的 `▾` 按钮（显式控件，可 `Tab` 到达），或 `Alt+Space`。
- **L3 台账抽屉 `JwLedgerDrawer`**：宽 640 lu，右侧滑入（W-wide）或全屏模态（W-mid）。表格 + 筛选 + 排序 + 定位高亮，不再往下嵌套。

覆盖层（预算审查、确认框、年度审查、终局档案、存档、规则手册、结算回放）挂在 `%ModalLayer`，与 L1–L3 正交，`Esc` 逐层收起。

### 5.5 线程与节流契约（对 Application 层的硬要求）

| # | 要求 |
|---|---|
| TH-1 | **季度结算在独立 `Thread` 上一次跑完**，完成后通过 `call_deferred` 把 `{step_results: Array[Dictionary](8), interrupts: Array[JwInterrupt]}` 交回主线程。SimCore 不得触碰场景树、不得 `await`、不得发 UI 信号。 |
| TH-2 | 界面在结算完成后**回放**八步进度并逐张展示中断卡；回放速率由界面控制，不由 SimCore 控制。回放不可回退（§04「承担已经发生的成本」）。 |
| TH-3 | **dry-run 异步**，带 `request_id`；界面丢弃过期结果。参数编辑触发的重算节流 200 ms；重算期间**保留上次结果并标注「重算中」**，禁止闪烁清空。 |
| TH-4 | 结算期间主线程帧间隔 ≤ 100 ms，窗口不进入无响应（AC-26）。步与步之间的耗时属于 SimCore，由 §17 性能门槛约束，不由界面规格约束。 |
| TH-5 | 结算后**只刷新读模型发生变化的节点**，禁止整页 `queue_free` 重建。 |

### 5.6 输入优先级与快捷键

优先级链：**模态 > 抽屉 > 页面 > 全局**。每一级处理后必须调用 `set_input_as_handled()`。

- 页面级与全局快捷键一律走 `_shortcut_input`，并在 `LineEdit` / `SpinBox` / `TextEdit` 持有焦点时**整体禁用**。
- 不得直接占用 `Space` 与 `Enter`（二者都是 `ui_accept`，任何获焦按钮会先吃掉）。

| 键 | 作用 |
|---|---|
| `1`–`5` | 切五页（仅 `_shortcut_input`，文本控件获焦时禁用） |
| `Alt+Space` | 展开/收起当前焦点所在区块 |
| `Enter` | 打开当前焦点数字的台账（`ui_accept` 语义，由 `JwNumberCell` 自身处理） |
| `Alt+R` | 打开当前焦点数字的规则卡 |
| `Alt+L` | 循环切换地图图层 |
| `Esc` | 逐层收起：模态 → 抽屉 → 区块展开 |
| `Ctrl+[` / `Ctrl+]` | 台账抽屉历史堆栈前后移动 |
| `Ctrl+Enter` | 打开预算审查 |
| `Ctrl+Shift+Enter` | 打开推进季度确认框（**不响应裸 `Enter`**，防误触不可逆动作） |
| `/` | 全局检索（§10.5） |

## 6. 状态机

### 6.1 通用界面状态 `JwUiState`

```gdscript
enum JwUiState { LOADING, NORMAL, WARNING, BLOCKED, SETTLING, READONLY }
```

每个页面、覆盖层与承载状态的组件都实现 `set_ui_state(s: JwUiState)`，行为契约如下。**不得用「置灰」作为状态的唯一表达。**

| 状态 | 何时进入 | 视觉（三通道：文字 + 图标 + 颜色） | 交互 | 禁止 |
|---|---|---|---|---|
| `LOADING` | 读模型请求中、dry-run 重算中、存档读取中 | 区块内显示骨架块 + 文字「重算中…」+ `icon.loading`；**保留上次结果**，只在其上叠加轻量标记 | 只读；已有内容仍可点击进台账 | 闪烁清空、遮罩整页 |
| `NORMAL` | 无 `WARN`、无 `BLOCK` | 常规样式 | 全部可用 | — |
| `WARNING` | 存在 `GAP` 或 `NOTE` | 文字「N 项提示」+ `icon.warn` + 赭色描边（不填充） | 全部可用；点击定位到第一条原因 | 只用颜色 |
| `BLOCKED` | 存在 `BLOCK` | 文字「N 项阻断：{首条类别名}」+ `icon.block` + 赭色深档描边 | **控件仍可点击**；点击 = 展开并滚动定位到第一条阻断原因 | 无原因的置灰；只写「不可用」 |
| `SETTLING` | 结算线程运行中或进度回放中 | 底部固定区变八步进度条；页面标题右侧显示 `icon.settling` + 「结算中」 | 全界面只读；页签仍可切换（只读浏览） | 接受任何命令 |
| `READONLY` | 读取旧存档且 schema 不匹配、或观战结算 | 顶栏显示「只读：{原因}」 | 只读 | 静默吞掉玩家操作 |

### 6.2 底部固定区状态机 `JwDockState`

```gdscript
enum JwDockState { IDLE, DRAFT, WARN, GAP_UNBOUND, GAP_BOUND, GAP_NOEXIT, BLOCKED, SETTLING, SETTLED }
```

| 状态 | 条件 | 推进按钮文案 | 点击行为 |
|---|---|---|---|
| `IDLE` | 草案篮空，无 `BLOCK`/`GAP` | `推进季度 ▸` | 打开确认框 |
| `DRAFT` | 草案 ≥1，无 `BLOCK`/`GAP` | `推进季度 ▸` | 打开确认框 |
| `WARN` | 有 `NOTE`，无 `BLOCK`/`GAP` | `推进季度（N 项提示）▸` | 打开确认框；框内逐条列出提示，需勾选「我已阅读全部 N 项提示」 |
| `GAP_UNBOUND` | 有 `GAP` 未绑定出口 | `处理缺口并推进 ▸` | 打开预算审查并定位到第一条 `GAP`，展开缺口处理器 |
| `GAP_BOUND` | 每条 `GAP` 都已绑定一条出口 | `承担缺口并推进 ▸` | 打开确认框；框内显示已绑定的出口与其代价 |
| `GAP_NOEXIT` | 四类出口全不可行 | `在无出口下推进 ▸` | 打开确认框 + **二次确认**；结算器按 §13 产生欠付/延期/取消 |
| `BLOCKED` | 有 ≥1 `BLOCK` | `不可推进：N 项阻断 · {首条类别名}` | **不置灰**：展开预算审查并滚动定位到第一条阻断原因 |
| `SETTLING` | 结算中 | `结算中…（第 k/8 步）` | 无 |
| `SETTLED` | 结算产出已生成 | `查看季度报告 ▸` | 跳季度报告 |

**硬规则**：
- 推进按钮**在任何状态下都不使用无原因的置灰**。`BLOCKED` 态按钮可点、可 `Tab` 到达，点击产生定位行为。
- **空草案可直接推进**（`IDLE` → 确认框 → 结算）。不得因为「未打开预算审查」而阻止推进。
  显示义务由确认框本体承担（§8.4），不由「是否打开过抽屉」承担。
- 未启用文案禁止出现纯流程理由（如「未查看预算审查」）。允许的理由只有两类：`N 项阻断（{码} …）` 与 `N 项缺口未绑定出口（{码} …）`。

### 6.3 状态转移

```
LOADING ──读模型就绪──▶ NORMAL
NORMAL  ──dry-run 返回 NOTE──▶ WARNING
NORMAL/WARNING ──dry-run 返回 BLOCK──▶ BLOCKED
BLOCKED ──玩家执行出口动作，BLOCK 归零──▶ NORMAL/WARNING
任意 ──确认推进──▶ SETTLING ──回放完成──▶ NORMAL（新季）
读档 schema 不匹配 ──▶ READONLY
```

`JwDockState` 由 Application 层每次 dry-run 返回后重算，界面不自行判定（§15 B-02）。

#### 7.1.5 诊断卡的生成、排序与终局措辞禁令

1. **候选生成**：十个检测器各跑一遍，命中即产出一条候选：
   `det.output_drop`（部门产出环比下降超阈值）、`det.binding`（某部门×地区连续 2 季同一紧约束）、
   `det.cash_path`（四季最窄余量低于底线）、`det.maturity`（某季到期本金+票息超该季可用现金）、
   `det.unemployment`、`det.housing`、`det.service_avail`、`det.queue_stall`、`det.trust_drop`、`det.ext_credit`。
   全部阈值登记在 `ldg.rule` 的 `R-DIAG-*`，界面必须可查。
2. **排序键**：`(紧迫度季数 升序, 可干预性 降序, 影响人口权重 降序)`。紧迫度无法计算时记 99。
   可干预性 = 命中的候选政策数；为 0 的风险**仍然显示**，干预段改写为「首版无对应政策工具」。
3. **取前 3 条**，第 4 条起折叠为一行「另有 N 项低于优先阈值 ▸ 全部诊断」。
   **不足 3 项时显示实际条数，禁止用次要项凑满**——「没有优先风险」必须是一个可被读出的信号。
4. **无风险时不得留空**：`JwEmptyState` 显示阈值说明与规则卡入口。
5. **终局措辞禁令（§04「经济下滑本身不是立即失败」）**：
   - 产出、增长、指数类下降**只能进入 `NOTE` 级**，不得标为阻断或终局风险。
   - 风险卡文案禁用词：`失败`、`淘汰`、`倒计时`、`game over`（进 §9.4 禁用词表）。
   - **只有留任资格与财政重组两项判据允许在界面上标注为终局风险**，且必须同时写出触发规则 ID 与判据表达式。
   - AC-29 断言：构造「连续 4 季产出下滑」夹具，页面上不出现任何终局措辞，且该风险的 `severity == NOTE`。

#### 7.1.6 不用单一分数

三支柱是三个**不可互相换算**的量纲（指数 / 比率 / 金额）。每个支柱展开后必须显示分布或分项：
产出 → 4 部门增加值；就业 → 4 地区失业率；财政 → 4 季现金路径。AC-21 验收。

#### 7.2.2 约束阶梯 `JwConstraintLadder`（本页最重要的控件）

把 `Q_actual = min(Q_plan, Q_capacity, Q_labor, Q_energy, Q_materials)`（§06）画成五根横条：

| 规则 | 内容 |
|---|---|
| CL-1 | 行标一律中文：**计划产量 / 产能 / 劳动 / 电力 / 材料**。英文符号（`Q_plan` 等）作为 14 lu 副标注，且必须在 ≥16 lu 处有冗余承载（列头或悬停面板） |
| CL-2 | 五项**必须已换算为同一种产品的可产出数量**，条上标注换算单位，且与部门用电/用料系数同单位（§10「单位必须与部门用电系数一致」）。量纲不一致时组件 `push_error` |
| CL-3 | 投入系数为 0 的项显示 `不适用（投入系数为 0）`、置灰、**不参与 min**（§06「某项投入系数为零时跳过该约束，不做除零运算」）。断言不出现 `inf` / `nan` 文本 |
| CL-4 | 最小项加 `◀紧` 标记 + 描边 + 「紧约束」文字（三通道） |
| CL-5 | 条下**固定两行**：`算 · 若解除当前紧约束，下一紧约束为 X，实际将升至 Y（+Z）。假设：其余四项不变` 与 `预 · 不利条件下同一推演〔下界–上界〕` |
| CL-6 | **禁止把五项合成「瓶颈指数」**（§15 B-04） |

#### 7.2.3 四象限与家庭负担

象限 ③「服务与住房」首屏必须包含**家庭负担率**：

```
家庭负担率 =（住房支出 + 基本服务支出）÷ 可支配收入
```
口径：`比 · 本季 · 分母=该组可支配收入`，同屏显示人数与金额绝对值。
这是 §04 环节 02「玩家看到什么：地区差异、**家庭负担**、项目与资金台账」三项之一，不得只出现在社会页的第二层。
指标定义为界面侧提出，需变量字典确认（§18 待决 10）。

#### 7.2.4 对比模式

勾选「并排四区」后，四象限变为 4 行 × 4 列矩阵（行=象限主指标，列=四地区），每格仍带徽章字与口径。
**并排模式禁止对地区排名打分**；排序只能按玩家选定的单一指标，列头必须写明排序依据。

#### 7.2.5 地区图与拓扑

- **界面不定义拓扑**。`JwRegionMap` 从剧本配置读取多边形顶点、邻接表与物流成本系数（`content/scenarios/chengwan/`）。
  UI 层不得硬编码任何邻接关系或系数值。
- 界面硬要求三条：
  (a) 剧本声明的**每条邻接边必须在图上以边的形式可见**；
  (b) 每条边必须显示成本系数与其基准定义；
  (c) 成本系数是无量纲相对值，图例必须写明基准的选择。
  AC-20 断言：修改剧本邻接表后，地图连线与「经 X 中转」文案随之改变，无需改 UI 代码。

- 选中态：3 lu 描边 + 内侧 1 lu 分隔 + 区名加粗，**不用颜色变化表示选中**（颜色留给图层数据）。
- 禁止密集六边格、瓦片网格、3D 倾斜、真实地理投影、现实国家轮廓。
- C4 档降级：地图退化为**四格横条**（区名 / 主题短语 / 面层值），不绘多边形。

#### 7.3.2 首屏必须有

12 项政策全部可见，按状态分三组（可提交 / 有缺口 / 阻断），**每一项在目录折叠状态下就直接带一句原因**——

#### 7.3.3 九字段（§09 原文）

目标问题 / 法定权限 / 一次性与持续成本 / 启动条件 / 生效时滞 / 作用对象 / 退出规则 / 政治反应 / 可验证的失败路径。
全部九项在第二层完整展开，第一层给摘要。AC-17 断言九字段节点存在且非空。

#### 7.3.4 影响预览（环节 04 的一半）

两栏：

| 左栏 `算 确定性后果` | 右栏 `预 情景（基线 / 不利条件）` |
|---|---|

| 假设行：`无新命令 · 无外生冲击` | 假设行 + 提示「本预览不含未来冲击（已隐藏）」 |

**右栏必须包含「受益 / 受损前 3 群组」三行**（`PROJECTED`，带区间与情景名），并附固定句
`多个瓶颈的影响通常不能简单相加`。
这是 §04 新手第 3 季「面对住房或培训需求，学会查看分配后果」的**事前**落点——不能只在结算后才看得到。
AC-17b 断言：任何含分配规则参数的政策（P03/P06/P10）草案，其影响预览必须存在群组分解节点。

#### 7.3.5 草案篮与决策密度

- 草案篮**不设条数上限**。真正的限制来自资金、队列、窗口、权限，由原因对象表达（§04「不设置凭空出现的限制」）。
- **常设指令**折叠区见 §8.6。

### 7.4 页面四 · 社会 `page.society`

> **「这条政策，谁受益、谁受损、谁会反对？他们的不满是哪一种不满？」**

#### 7.4.1 首屏必须有

36 格群组矩阵（4 地区 × 3 年龄层 × 3 技能/教育档）；选定指标的分布条（P10/中位数/均值/P90 同时显示）；
三类民意三个**独立**数字；三个利益集团各自的支持方向与关切；受益受损清单。

#### 7.4.2 群组矩阵 `JwGroupMatrix`

| 规则 | 内容 |
|---|---|
| GM-1 | 必须渲染 **36 格**，断言格子数 == 36 |
| GM-2 | **两种符号必须区分**：`·` = 该槽位人口为 0（空组）；`—` = 该槽位对当前着色字段不适用。未成年群组在「收入 Δ%」字段下显示 `—`，**不是 `·`** |
| GM-3 | 着色字段切换器至少含四项：`实际可支配收入 Δ%` / `家庭负担率` / `服务可及性` / `教育准备程度`。未成年行在后两项下必须有值（§08「儿童档位代表教育准备程度，不代表劳动技能」） |
| GM-4 | 格内三个数字（人数 / 就业率 / 收入变化）的五元组由**列头与表脚**承载，格内只保留数值与徽章字（§4.2） |
| GM-5 | 就业率的分母是该组劳动年龄人口；未成年/老年组该项显示「不适用」 |
| GM-6 | **禁止**出现任何代表「社会整体」的单一数值控件 |

#### 7.4.3 三类民意与集团

当期生活 / 未来预期 / 程序信任 三项**分列，禁止相加、禁止平均、禁止合成**（§08「民众不是一个满意度」）。
三个利益集团各自单列：成员规模（人）、组织资源、当期立场、关切。成员规模与影响力分列，不合并为一个数。

#### 7.4.4 受益受损清单

- 触发源下拉必须接受三种来源：`本季结算` / `指定政策` / **`当前草案`**。选「当前草案」时整个视图标 `预` 并带区间。
- **受益与受损并列显示**，禁止只显示净额或平均。
- 归因行必须写明 `多个瓶颈的影响通常不能简单相加`（§13）。

#### 7.4.5 分配精度禁令

**不得出现**基尼系数、不平等指数或任何单一分配评分（§14「不从平均群组收入输出精确基尼系数」）。
允许且必须显示：组间差距（最高组 ÷ 最低组）、收入分位近似（P10/P50/P90），并附常驻不可关闭的说明条
`本版只报告组间差距与收入分位近似，未模拟组内全部差异`。

### 7.5 页面五 · 季度报告 `page.report`

> **「上一季我的判断成立了吗？哪里判断错了，错在证据还是错在机制？」**
> 这是唯一使用纸面底色的页面（`bg.paper`）——它是档案，不是控制台（§11「像一份正在变化的国家档案」）。
> 也是唯一允许长滚动的页面。

#### 7.5.1 小节顺序（固定）

| 小节 | 内容 | 类 |
|---|---|---|
| 一 · 与上季预期的偏差 | `JwVarianceTable`，**永远排在第一位** | 混合（分列） |
| 二 · 已经发生 | 结算 8 步逐项回执（步序按 §13 不可重排）+ 收支恒等式核对行 | `ACTUAL` |
| 三 · 在建项目与时滞 | `JwQueueTimeline`（见 §7.5.2） | 混合 |
| 四 · 模型中的限制因素 | 限制因素排序 + 不可加总声明 | `DERIVED` |
| 五 · 下季情景 | 基线 / 不利两栏并列，带区间与假设 | `PROJECTED` |
| 六 · 下季待办 | 由偏差表与未决原因生成，可勾选带入草案篮 | `DERIVED` |

**小节即分区**。第一小节是唯一允许把 `ACTUAL` 与 `PROJECTED` 放在同一行的地方（本质是对账），
因此该表**必须有独立的类别列头**：`上季情景（预）` 与 `本季实记（实）` 分列，列头带图标，
且情景列每个值都是区间、实记列每个值都不是区间。

#### 7.5.2 区块三「在建项目与时滞」（§04 第 2 季教学的落点）

计划书 §04 第 2 季目标是「看到支出先发生、收益尚未出现，理解建设时滞」。本区块是它在界面上的唯一落点，**进入首屏清单**。

`JwQueueTimeline` 逐项目一行，列定义固定：

| 列 | 说明 |
|---|---|
| 项目 | 项目 ID + 政策 + 地区 |
| 累计已付 (U) | `ACTUAL` |
| 交付进度 % | `ACTUAL` |
| 施工进度 % | `ACTUAL` |
| **本季新增能力** | **必须显示 `0`，不得留空**——这是这一课的全部内容 |
| 最早投运季 | `DERIVED`，带规则号 |
| 提前撤回成本 | `DERIVED`：已付不可收回 + 未完工残值 + 合同赔偿，三项分列 |
| 出处 | `ldg.project` / `ldg.commit` |

行下固定一句：`算 · 按规则本季无产能贡献（机制 [M-xxx]）。完工资产下一季才提供新增能力。`
AC-18b 断言：第 2 季报告必须至少渲染一行「累计已付 > 0 且本季新增能力 = 0」的项目行。

#### 7.5.3 偏差表 `JwVarianceTable`（环节 06 的操作落点）

三条约束：

| # | 约束 |
|---|---|
| VT-1 | 上季预测区间作为**只读字段存入存档**，不可被本季数据事后覆写。测试：篡改当前参数后重开报告，历史区间不变 |
| VT-2 | 偏差**只与区间比较**；落在区间内不算偏差，显示「区间内 —」 |
| VT-3 | 逐行给出四个承担动作 `[继续] [暂停] [改期] [撤回]` |

四动作的行为（§04 环节 06「继续、暂停、改期或撤回，承担已经发生的成本」）：

- 点击 `[暂停]` / `[改期]` / `[撤回]` **必须先渲染一张成本卡**，四项分列：
  已支付不可回收额 / 未完工工程残值 / 合同赔偿 / 取消后剩余承诺。
- 成本卡复用 `reason.gap.cancel_cost` 与 `reason.note.exit_lock` 的渲染函数。
- **未渲染成本卡不得提交撤回命令**。AC-18c 断言。

#### 7.5.4 措辞禁令

- 必须使用「**模型中的限制因素**」；禁止真实世界因果断言（§13「解释器不冒充因果识别」）。扫描域与白名单见 §9.4。
- 反事实对比必须紧跟假设说明，显式列出 ≥1 条假设。
- 禁止出现「本季评分」「治理得分」「国力等级」。

| A2 基线 / 不利两情景的三行对照 | 否 |
| B 本草案新增长期承诺全量 + 三项合计 | 否 |
| 将提交的命令清单（含常设指令产生的条目） | 否 |
| **本季将发生的全部不可逆动作**（结算器标记 `irreversible` 的支出逐条） | 否 |
| 全部 `BLOCK` / `GAP` / `NOTE` 原因（同一渲染函数） | `NOTE` 可折叠 |

- H-short 档确认框内部允许滚动，但上表「否」的六块属**不可折叠区**（AC-12）。
- `WARN` 态需勾选「我已阅读全部 N 项提示」后方可确认。
- `GAP_NOEXIT` 态需二次确认，文案写明「将由结算器按规则产生欠付 / 延期 / 取消状态」。
- 确认框**不响应裸 `Enter`**。

### 8.5 缺口处理器 `JwGapResolver`

计划书 §07：「无法融资时进入支出排序、延期与重组选择，不允许无提示的负国库余额。」

| 路径类 | 别名 | 玩家选择 | 必须显示的代价 |
|---|---|---|---|
| 融资 | `gap.finance` | 发行债券（额度、期限、票息由规则给出，非玩家自定） | 未来各季利息、到期本金季、对承诺摘要的增量 |
| 延期 | `gap.defer` | 把哪些合同付款延后几季 | 投运/结业推迟季数、违约金（按合同条款）、是否触发队列重排 |
| 削减 | `gap.cut` | 把哪些政策规模按比例下调 | 效果量下降、最早反馈季推迟、已发生沉没成本不退 |
| 重组 | `gap.restructure` | 触发债务重组（仅满足触发条件时可选） | 债权人减记额、程序信任下降、后续融资价格上升 |

| # | 规格 |
|---|---|
| GR-1 | 每条 `GAP` **必须至少绑定一条路径**才进入 `GAP_BOUND`。多条 `GAP` 可共用一条路径，但绑定关系必须显式显示 |
| GR-2 | 选定后**重算并重绘** A1/A2 表，新表标「已应用路径」；重绘完成前推进按钮保持 `GAP_UNBOUND` |
| GR-3 | 四类路径全不可行时，显示「本季无出口，最早可行季：第 N 季」及其计算依据，**仍允许推进**（`GAP_NOEXIT`），由结算器按 §13 产生欠付 / 延期 / 取消 |
| GR-4 | 每条路径必须给出执行后的**剩余缺口** `residual_gap` |

### 8.6 常设指令 `JwStandingOrders`（§04「低风险维护可以预先设定，减少重复操作」）

折叠区位于草案篮下方。每条常设指令的规格为四要素，缺一不可创建：

| 要素 | 说明 |
|---|---|
| 作用对象 | 资产 / 服务 / 品目 / 群组 |
| 每季金额上限 | 带单位；超过上限的部分不自动拨付，转为原因卡 |
| 自动终止条件 | 季号、达成条件或「无（永续）」；永续必须在 B 表中以永续行呈现 |
| 可随时撤销 | 撤销入口与撤销代价（复用 §7.5.3 成本卡） |

覆盖范围：运行费自动拨付、库存补库、失业保障等**规则性支出的续期**。

- 常设指令**不跳过预算审查**，只跳过重复录入：它们每季自动进入草案，在 A1 表与确认框中以独立的
  「常设」段落显示（带 `常设` 徽章）。
- 底部固定区 ① 增加一行「本季由常设指令处理 N 项 ▸ 查看」。
- 常设指令属于一条新的命令来源，需与命令/重放协议对齐（§18 待决 11）。

## 9. 原因对象与文案（「为什么不能执行」）

> 计划书 §04：**政策页必须告诉玩家「为什么不能执行」。**
> 计划书 §11：**对会导致资金缺口的方案给出具体原因，不只显示「不可用」。**

### 9.1 原因对象结构

**由 Application / SimCore 构造，界面只渲染。** 界面不判定可行性、不计算数值（§15 B-02）。

```gdscript
class_name JwReason extends RefCounted

var code: StringName            # 占位别名，映射到 SimCore 的 reject_code
var severity: int               # JwSeverity.BLOCK | GAP | NOTE
var quarter: int                # 发生季 1..40+，不可为空（RC-05）
var subject_id: StringName      # 被阻塞的对象：草案 / 政策 / 项目 / 合同
var need: JwQty                 # {value_uU:int, unit:StringName}
var avail: JwQty
var gap: JwQty                  # need − avail，由构造方计算
var drivers: Array[JwDriver]    # {entity_id, label, amount} 金额降序，最多 3 条
var exits: Array[JwExit]        # {command, label, cost_phrase, residual_gap} ≥1 条
var links: Array[JwEvidence]    # {ledger_alias, row_ids: PackedInt64Array} ≥1 条
var slots: Dictionary           # 命名占位 → 已格式化的字符串；UI 只填不算
```

`need` / `avail` / `gap` 允许为空的**只有**三类：`blk.window`、`blk.authority`、`blk.duplicate`
（它们用时点 / 权限名 / 已存在对象替代三个数字，见 §9.6 行 2 替代模板）。

### 9.2 文案模板（五行，顺序固定）

```
行1 标题：{严重度图标} {类别中文名} · 第 {quarter} 季
行2 定量：{约束对象}{比较语}，需要 {need}{unit}，可用 {avail}{unit}，缺口 {gap}{unit}。
行3 占用：主要占用：{drivers[0].label} {金额}、{drivers[1]...}。（另有 N 项合计 X U）
行4 出口：出口：① {exit[0].label}（代价：{cost_phrase}；缺口降至 {residual_gap}）
                 ② … ③ … ④ …
行5 链接：▸{links...}
```

**行 1 显示中文类别名，不显示原因码。** 原因码只出现在台账、导出与 debug 构建中。

### 9.3 生成规则（任一违反即为缺陷）

| # | 规则 |
|---|---|
| RC-01 | **模板唯一**：每个原因码恰有 1 条中文模板，存于 `content/ui/reasons_zh_cn.tres`。槽位用**命名占位** `{slot_name}`，禁止位置占位 `{0}`。**禁止在 GDScript 里拼字符串** |
| RC-02 | **槽位只填不算**：全部定量槽位的值由资格检查器 / 现金预测器随原因对象一起返回。`res://ui/` 下的原因渲染器出现作用于原因槽位的算术运算符即为缺陷（静态可查） |
| RC-03 | **五项必填**：(a) 类别中文名 (b) 触发实体名 (c) ≥1 个带单位的数字 (d) ≥1 个季度标记 (e) ≥1 条出口 |
| RC-04 | 行 2 必须含 `need / avail / gap` 三个数字；三类例外用替代模板（§9.6） |
| RC-05 | 必须含**发生季**。无法确定季时不得生成该 Reason，改由检测器降级为 `NOTE` 并说明「时点不可确定的原因：…」 |
| RC-06 | `exits` ≥1 条。**等待也是一条出口，但必须写明等到第几季**（如「等待：第 8 季预算审查窗口（还有 2 季）」） |
| RC-07 | 每条 exit 必须附执行后的 `residual_gap`。无法计算时写「需重新计算 ▸ 试算」并提供一键试算按钮 |
| RC-08 | 每条 exit 必须形如 `〈动作〉（代价：〈定量或定性后果〉）`，且**必须是一条可执行的 UI 命令**。**禁止纯文字建议**（如「请考虑削减支出」） |
| RC-09 | `exits` 数量 1–4 条；>4 条时按影响幅度取前 4 并写「其余 N 条 ▸」 |
| RC-10 | `drivers` 按金额降序，最多 3 条，其余折叠为「另有 N 项合计 X U」 |
| RC-11 | 排序：`severity` BLOCK > GAP > NOTE；同级按 `(最早触发季 升序, |缺口| 降序, 码字典序 升序)`。排序必须稳定（同输入两次输出顺序完全一致） |
| RC-12 | **`links` 为空或 `evidence_row_ids` 为空的原因禁止渲染**，`push_error` |
| RC-13 | **同一 Reason 在政策目录、政策卡、预算审查、确认框四处必须由同一渲染函数输出**，禁止各写各的 |
| RC-14 | 长度上限：主句 ≤60 汉字，每条出口 ≤40 汉字。超长在模板层改写，**不在运行时截断**（不出现省略号） |
| RC-15 | 金额沿用 §4.5 格式；所有实体必须可点击定位 |
| RC-16 | 重算随参数编辑节流 200 ms；重算期间保留上次结果并标注「重算中」，**禁止闪烁清空**（§5.5 TH-3） |

### 9.4 禁用词表与因果措辞

**禁用词（正则 lint，命中即失败）**：
`不可用`、`无效`、`错误`、`失败`、`不满足条件`、`无法执行`、`请稍后`、`未知原因`。
例外：这些词后**紧跟** `：{原因}` 且该原因含数字与季度时允许。

**因果措辞黑名单（扫描域受限）**：
- 扫描域**只限**三处解释性输出资源：季度报告小节四（限制因素）、诊断卡「机制」段、反事实对比文案。
- 黑名单只保留**断言式真实世界因果措辞**：`原因是`、`证明了`、`因为…所以…`、`导致了`（完成式断言）。
- **白名单**（不得命中）：模型内链路描述（「队列拥堵使进度停滞」）、UI 操作说明、引用计划书原文
  （§11 原句「对会导致资金缺口的方案给出具体原因」本身含「导致」，必须白名单）。
- 必须使用的固定措辞：「模型中的限制因素」「约束定位」「反事实对比（假设：…）」。

**终局措辞禁用词**：`失败`、`淘汰`、`倒计时`（见 §7.1.5）。

### 9.5 覆盖契约（包含方向）

```
对 SimCore / Application 能返回的每一个 reject_code c：
    alias_map.json 中存在 c → reason.* 的映射，且该 reason 有模板、有默认出口、有出处台账。
```

- 这是**界面对 SimCore 的义务**，不是 SimCore 对界面的义务。
- `tests/ui/test_reason_coverage.gd` 断言两件事：
  (a) `reject_code` 集合中的每个码都能解析到一张原因卡；
  (b) 本文件 §9.6 表中的每个码都有**至少一个构造用例能触发**（无法触发的码视为死码，必须删除或补夹具）。
- 新增任何拒绝路径时，必须同步登记：码 / 中文名 / 触发判据 / 行 2 模板 / 默认严重度 / ≥1 条默认出口 / 出处台账。
  **缺任一项不得上线**——否则界面会退回「只显示不可用」，而这正是 §04 底线禁止的。

## 10. 覆盖层

### 10.1 年度审查 `overlay.annual_review`（第 4 / 8 / … 季）

§04 新手第 4 季目标：**完成首次年度审查，辨认收入改善和公共服务负担并存的情况。**

首屏必须**并列**显示两块，**禁止折叠、禁止合成为单一数值**：

| 左块 · 本年收入 | 右块 · 本年公共服务负担 |
|---|---|
| `实` 四季收入合计及同比变化 | `实` 四季公共服务运行费合计 |
| 按税种 / 非税分解（≥4 行） | 已投运资产的每季运行费明细 |
| `算` 征收覆盖率变化（分母同屏） | `算` 下一年运行费（含在建项目投运后的增量） |
| 出处 `ldg.tax` | 出处 `ldg.opex`、`ldg.service` |

下方固定一行结论文案模板（三个槽位必填）：

```
本年收入改善 {X} U，同期新增公共服务运行费承诺 {Y} U每季，净覆盖缺口 {Z} U。
```

再下一行并列三个数：**债务（存量）· 名义 GDP（四季滚动）· 债务/GDP 比率**，
比率带角标 `比 · 四季滚动 · 分母=名义GDP`，并紧跟固定句：

```
该比率不替代偿付能力分析，见四季现金预测与到期表。
```

（§07 要求「单独展示债务/GDP，不能替代偿付能力分析」——这是一个肯定要求加一个限定，两者都必须落地。
顶栏旁仍然**禁止**把该比率作为唯一偿付能力指示。）

**与 `reason.blk.window` 的关系**：必须显式声明哪些政策类型不受审查窗口限制。
**项目立项类政策（如 P04）在第 01 季可提交**，否则 §04 第 1 季「提交一项可融资的项目」当场失败。AC-32 断言。

### 10.2 终局与提前结束档案 `overlay.final_archive`

§04：「第 40 季形成发展档案；失去留任资格或财政重组失败时，执政提前结束。
经济下滑本身不是立即失败。结算展示生活、分配、能力、韧性与政治结果，不以单一国力分数替代。」

| 项 | 规格 |
|---|---|
| 入口 | 两类：第 40 季正常结束；提前结束（失去留任资格 / 财政重组失败） |

### 13.4 表格的唯一实现路径

**Godot 4 没有数据网格控件。** `GridContainer` 没有「行」概念（做不了逐行左标尺与逐行底纹），
`Tree` 的单元格装不下任意子 Control。因此：

```
JwDataTable extends Control
├── %Header (JwTableHeader)   # 承载五元组（单位 / 口径 / 期间 / 价格基期 / 分母），见 §4.2
├── %Tree   (Tree, hide_root = true, columns = N)
│            # 每列 set_custom_draw_callback()：
│            #   3 lu 左标尺色条（按行的 info_class 取纹理）
│            #   徽章字（实 / 算 / 预）
│            #   右对齐等宽数值 + 小数点对齐
└── %Footer (JwTableFooter)   # 口径全文、合计行、残差核对
```

**表内的三类编码降级（明确写死，避免实现者去找不存在的能力）**：

| 通道 | 表格内 | 表格外（卡片、KPI、散文） |
|---|---|---|
| ① 徽章字 | 有（独立「类」列或数值前缀） | 有（词前缀） |
| ② 图标 | 有（自绘于单元格） | 有 |
| ③ 左标尺 | 有（`custom_draw` 画 3 lu 色条，按 `info_class` 取笔形纹理） | 有（`StyleBoxTexture`） |
| ④ 数字形态 | 有（区间的有无） | 有 |
| 底纹 | **无**（放弃） | 无（本规格未采用底纹通道） |
| 内联引用码 | **无**，降级为独立「出处」列的按钮 | 有（`JwCitationChip`） |

`Tree` 天然只绘制可视行，满足虚拟化要求。**禁止**用 `GridContainer` + 逐格 Control 实现任何超过 24 行的表。

### 13.5 实现约束（性能与可测性）

| # | 约束 | 理由 |
|---|---|---|
| IM-1 | `JwNumberCell` 必须是**单个自绘 Control**（`_draw()` + 缓存 `TextLine`），**不得**是 `HBox + 多个 Label + TextureRect` 的组合体 | 社会页 36 格 × 3 个数字 = 108 个单元；若每个 6 节点，仅矩阵就约 650 个 Control |
| IM-2 | 台账抽屉必须用 `Tree`（自带可视行裁剪）或手写虚拟化（只实例化可视行 ±2 行） | 200 行 × 8 列若不虚拟化约 1 万节点，实例化本身数百毫秒 |
| IM-3 | 结算后**只刷新读模型发生变化的节点**，禁止整页 `queue_free` 重建 | §17 性能门槛：玩家会把重建耗时计入结算时长 |
| IM-4 | 节点预算：**单页 ≤1500 个 Control，抽屉 ≤300**；`--ui-audit` 导出每页节点数（AC-25） | — |
| IM-5 | 图表、徽章等组件的必填项用 `@export` + `_ready()` 断言 + `@tool` 的 `_get_configuration_warnings()`，**不得用构造函数参数** | `PackedScene.instantiate()` 不传参；构造函数必填参数会逼所有组件放弃场景编辑 |
| IM-6 | 不得用 `modulate` 做抽屉 / 浮层的淡入 | 有效 alpha = 祖先链 `modulate.a` 连乘 × `self_modulate.a` × 主题 `font_color.a`；用 `modulate` 淡入会让文本有效 alpha < 1（§15 B-12） |
| IM-7 | 规则号用**字面插入符 + 规则 ID**（`^R-PROD-03`），不使用排版上标 | `RichTextLabel` 没有上标标签 |
| IM-8 | 左标尺笔形用 `StyleBoxTexture` + 三张平铺纹理 | `draw_dashed_line()` 的实段与空段等长，做不出 6/3 与 2/4；`StyleBoxFlat` 无虚线边框 |
| IM-9 | 地区图的命中测试自行实现：`Geometry2D.is_point_in_polygon`；凹多边形填充须 `Geometry2D.triangulate_polygon` | `Polygon2D` 是 `Node2D`，进不了 Control 布局 |
| IM-10 | 界面对 SimCore 的一切读取走 `JwDisplayValue{value_uU:int, unit:StringName, info_class:int, citation:String, ...}`；界面只格式化不运算 | 使「UI 不自己算账」成为可静态检查的边界（§15 B-02） |

### 16.3 夹具集（交付物，`res://tests/fixtures/ui/`）

「0 违规」的强度完全等于夹具覆盖率，因此夹具集是交付物，不是附属品。

**必须覆盖的状态清单**：

- `JwDockState` 九态各 1 个；
- 政策五种状态徽章各 1 个；
- **30 个原因码各 ≥1 个可触发组合**（12 政策 × 30 码的全矩阵**不做**，改为「每码 ≥1 夹具 + 每项政策 ≥1 个可达组合」= 30 + 12 = 42 个夹具）；
- C1–C4 各 1 个；
- Q01 冷启动、Q02 时滞、Q04 年度审查、第 40 季正常结束、两类提前结束；
- 边界值：空组、零值、负值、极大值、schema 不匹配的旧档。

夹具形式：**回合快照 + 命令序列**。每条验收条目标注它依赖的夹具 ID。
**在 SimCore 字段字典冻结前，本节验收只对夹具跑，不对真实结算跑**——这一点必须写在 CI 报告的抬头。
